## 3D

2D is Ollin's default, and most sketches stay 2D. A sketch opts into 3D by setting a **camera** — once a frame has one, the renderer adds a depth buffer and draws 3D geometry through the camera's view and projection. Set no camera and nothing changes: the 2D path is untouched and pays nothing.

Today the 3D geometry is **point clouds** — tens of thousands to millions of points, each drawn as a camera-facing disc, sized in world units so perspective shrinks the far ones and the depth test hides the ones behind — and **solid primitives** (box, sphere, cylinder, cone, torus, pyramid, helix, the regular polyhedra, a torus knot, and a plane), filled meshes drawn through the same camera and depth test, **lit** by a directional/point/spot light model. Loading meshes from file is ahead (see [What's here, what's ahead](#ahead)).

<a id="first"></a>
### A first 3D sketch

```swift
import Ollin

@main
final class Cloud: Sketch {
    override func draw() {
        background(.black)

        // Setting a camera makes the frame 3D. `orbiting` swings it around a target.
        camera(.orbiting(target: .zero, radius: 5, azimuth: time * 0.3, elevation: 0.5))

        // Build a cloud of world-space points and draw it.
        var cloud = PointCloud()
        for i in 0..<6000 {
            let a = Double(i) * 0.1, r = Double(i) / 6000 * 2
            cloud.add(Vector3(cos(a) * r, sin(Double(i) * 0.03), sin(a) * r),
                      color: Color(hue: r / 2, saturation: 0.8, brightness: 0.9),
                      size: 0.04)
        }
        drawPointCloud(cloud)
    }
}
```

The camera is **per-frame state**, like the geometry: it resets each frame, so you set it in `draw()` — which is exactly where you'd animate an orbit. A 2D sketch simply never calls `camera`.

<a id="camera"></a>
### The camera

A `Camera3D` is an eye looking at a target, plus how it flattens space onto the canvas (perspective or orthographic). The bare calls set one for the frame:

```swift
// Perspective: nearer is bigger. `fieldOfView` is the vertical angle in radians.
perspective(eye: Vector3(0, 2, 6), target: .zero, fieldOfView: .pi / 3)

// Orthographic: no foreshortening. `height` is the world units framed top-to-bottom.
ortho(eye: Vector3(0, 2, 6), target: .zero, height: 8)

// Or build a Camera3D and pass it — useful to keep and tweak.
camera(.orbiting(target: .zero, radius: 6, azimuth: a, elevation: 0.4))
```

`Camera3D` value-type factories:

- `Camera3D.perspective(eye:target:up:fieldOfView:near:far:)`
- `Camera3D.orthographic(eye:target:up:height:near:far:)`
- `Camera3D.orbiting(target:radius:azimuth:elevation:fieldOfView:near:far:)` — places the eye on a sphere around the target: `azimuth` turns around the up axis (0 looks down +z), `elevation` tilts above the horizontal, both in radians. The easy way to spin a camera around a scene.
- `Camera3D.fromIntrinsics(_:near:far:)` — a **metric** camera built from a depth frame's pinhole `CameraIntrinsics` (an off-axis frustum matching the lens), at the origin looking down −z. It puts a point cloud, a depth feed, and any placed object in one space measured in meters; see [depth compositing](./DepthCompositing.md#metric).

`near`/`far` are the clip distances (geometry outside them is cut away); `up` defaults to `.unitY`.

<a id="clouds"></a>
### Point clouds

A `PointCloud` is a list of points, each with a world-space position, a color, and a splat diameter in **world units** (so perspective shrinks distant points). Build one up front for a fixed scan, or rebuild it every frame for a live feed — a ~50k-point cloud rebuilt per frame is comfortable.

```swift
var cloud = PointCloud()
cloud.add(Vector3(x, y, z), color: .white, size: 0.05)   // one at a time
// …or in bulk:
let cloud2 = PointCloud(positions: pts, color: .cyan, size: 0.05)
let cloud3 = PointCloud(positions: pts, colors: cols, size: 0.05)   // per-point colors
drawPointCloud(cloud)
```

Splats composite in draw order and under the active [`blendMode`](./Drawing.md#blendMode) — `blendMode(.add)` sums them as light, the glowing-cloud look. Sub-pixel splats fade by area (the same coverage `drawCircle` uses), so a dense cloud of tiny points doesn't flicker.

<a id="primitives"></a>
### Solid primitives

The built-in shapes — the closed solids (box, rounded box, sphere, icosphere, cylinder, cone, capsule, torus, the Platonic solids, pyramid, helix, torus knot, plane) and the parametric/profile generators (supershape, superellipsoid, Möbius, Klein, extrude, lathe, tube) — are filled meshes, drawn through the same camera with depth testing. Each is centered at the model origin and sized in world units, so you place and orient it with the [3D transform stack](#transforms):

```swift
camera(.orbiting(target: .zero, radius: 8, azimuth: time * 0.2, elevation: 0.4))

withState {
    translate(-2, 0, 0)
    rotateY(time)
    drawBox(size: 1.5)              // a cube
}
drawSphere(radius: 1)              // at the origin
```

The closed solids, all on `Sketch`:

- `drawBox(size:)` / `drawBox(width:height:depth:)`, and `drawRoundedBox(size:radius:)` for filleted edges
- `drawSphere(radius:segments:rings:)` (a UV sphere) and `drawIcosphere(radius:subdivisions:)` (a geodesic sphere — evenly sized triangles, no pole pinching)
- `drawCylinder(radius:height:segments:caps:)`, `drawCone(radius:height:segments:)`, `drawCapsule(radius:height:)`
- `drawTorus(radius:tube:segments:sides:)` and `drawTorusKnot(p:q:radius:tube:…)`
- `drawPyramid(width:depth:height:)`, `drawHelix(radius:tube:turns:height:…)`, `drawPlane(width:depth:)`
- the Platonic solids: `drawTetrahedron(radius:)`, `drawOctahedron(radius:)`, `drawIcosahedron(radius:)`, `drawDodecahedron(radius:)`

And the parametric / profile generators (the [`3D/ShapeFactory`](../Examples/3D/ShapeFactory/) example):

- `drawSupershape(radius:m:n1:n2:n3:…)` — the Gielis superformula: a few numbers sweep an enormous range of organic, star, and flower forms (great driven by `time`)
- `drawSuperellipsoid(radius:e1:e2:…)` — a sphere that morphs toward a box (`e → 0`) or octahedron (`e → 2`)
- `drawMobius(radius:width:…)` and `drawKlein(scale:…)` — the one-sided surfaces
- `drawExtrude(_ outline: [Vector2], depth:)` / `drawExtrude(_ shape: Shape, depth:)` — push a flat 2D shape into 3D, paired with the `Profile` helpers (`Profile.rectangle`/`.ellipse`/`.triangle`/`.polygon`/`.star`)
- `drawLathe(_ silhouette: [Vector2], segments:)` — revolve a side profile into a vase/bowl
- `drawTube(_ path: [Vector3], radius:sides:closed:)` — sweep a solid tube down any 3D curve

**A solid takes the current `fill` as its surface color** and is shaded by the [light & material model](#lights) below — and because lighting has an auto-lit default, a solid looks 3D out of the box with no lights to set up. The `fill`'s **alpha** sets opacity (so `fill(Color(white: 1, alpha: 0.5))` makes a translucent solid). Gradient paint isn't supported on the 3D path — meshes take a solid color.

Under the hood each shape is a `Mesh` value type (positions, normals, a triangle-index list) built by a generator — `Mesh.box(…)`, `.sphere(…)`, `.supershape(…)`, `.extrude(…)`, etc. **Build a mesh once and draw it every frame** with `drawMesh(_:)` (the `draw*` calls build it each frame — fine for a cube, wasteful for a swept knot or a dense supershape):

```swift
let ball = Mesh.sphere(radius: 1, segments: 48, rings: 32)   // build once
// …each frame:
withState { fill(Color(hex: 0xF5A623)); translate(x, y, z); drawMesh(ball) }
```

You can also hand `drawMesh`/`Mesh(positions:normals:indices:)` your own arrays. Meshes need a camera (like point clouds) and ride the 3D transform stack, not the 2D affine.

<a id="load"></a>
### Meshes from file

Load a model from a file into a `Mesh` and draw it with `drawMesh`, the same depth-tested, lit path the built-in primitives use. Ollin reads three families:

- **`.obj`** (Wavefront): Ollin's own reader.
- **`.usdz` / `.usdc` / `.usda` / `.stl` / `.ply`**: through Apple's Model I/O.
- **`.gltf` / `.glb`**: Ollin's own reader. glTF 2.0 is what most 3D tools export, and the one common format Apple can't open, so Ollin reads it directly.

```swift
final class LoadedModel: Sketch {
    var model: Mesh?
    override func setup() {
        model = loadMesh("/path/to/duck.usdz")?.normalized(scale: 3)
    }
    override func draw() {
        camera(.orbiting(radius: 7, azimuth: time * 0.3))
        if let model {
            // Default white fill shows the model's own material; set a fill to tint
            // it (or to color a model that carries no material of its own).
            withState { rotateY(time); drawMesh(model) }
        }
    }
}
```

A loaded model arrives in its author's own coordinates, at whatever scale it was saved (a CAD export might span thousands of units; a game asset, fractions of one). **`normalized(scale:)`** recenters it on the origin and uniformly scales it so its longest dimension spans `scale` world units: a drop-in fit, the way the generators are already unit-sized. `bounds`, `center`, and `size` give you the raw extents if you'd rather place it yourself.

The loaders mirror the image and font ones: `loadMesh(path)` / `loadMesh(url)` on `Sketch`, or `Mesh(contentsOf:)`, `Mesh(path:)`, and `Mesh(resource:extension:in:)` for a bundled model (as ever, `in:` has no default, so pass `.module`). Each returns `nil` if the file can't be read.

**Its material, too.** A loaded model brings its own **base-color material**: a base color and an optional texture, mapped through the file's UVs (see [Textured meshes](#textures)). Keep the default white `fill` so it shows true (the `fill` still tints it). A **glTF** reads `baseColorFactor` + `baseColorTexture` + `TEXCOORD_0`; an **OBJ** reads its `.mtl` (`Kd` diffuse color + `map_Kd` texture) and `vt`; a **USD/STL/PLY** reads its Model I/O material and texture coordinates. A model with **no** material falls back to shading in your `fill`, so you pick the color. This is the **base color** only for now: a multi-material file wears its first material, and metallic/roughness and normal maps are the later PBR tier.

A model you make yourself is your own work, free to ship. A 3D design tool like Spline exports glTF or USDZ directly; downloaded sample models often carry non-permissive licenses, so check before bundling one. See the `3D/LoadedMesh` example (drop a `model.usdz`/`.glb`/`.gltf`/`.obj` beside it, or point `OLLIN_MESH` at one).

<a id="lights"></a>
### Lights & materials

A solid is shaded by a Blinn-Phong material whose surface color is the current `fill`. **With no lights set, Ollin applies a sensible default rig automatically** — so `fill(.red); drawSphere()` is a shaded red ball, not a flat circle, with zero setup. Add your own lights to take over the scene:

```swift
camera(.orbiting(target: .zero, radius: 8, elevation: 0.3))

ambientLight(Color(white: 0.15))                                   // flat fill so shadows aren't black
directionalLight(.white, direction: Vector3(-0.5, -0.8, -0.4))    // the sun (parallel rays)
pointLight(Color(hue: 0.5, saturation: 0.8, brightness: 1), at: Vector3(3, 2, 2))   // a bulb at a position
spotLight(Color(hue: 0.85, saturation: 0.7, brightness: 1),
          at: Vector3(0, 5, 0), direction: Vector3(0, -1, 0),
          angle: .pi / 5, penumbra: 0.5)                          // a cone aimed down

fill(.red)
specular(0.6)        // highlight strength (0 = matte, the default)
shininess(64)        // higher = tighter, sharper highlight
drawSphere(radius: 1)
```

The three light kinds:

- **`directionalLight(color, direction:)`** — parallel rays from a direction (the sun). `direction` is the way the light *travels*: `Vector3(0, -1, 0)` shines straight down.
- **`pointLight(color, at:)`** — an omnidirectional source at a world position.
- **`spotLight(color, at:direction:angle:penumbra:)`** — a point source narrowed to a cone aimed along `direction`, of full `angle`, with a `penumbra` soft edge (`0` hard … `1` very soft).

Each call takes an `intensity` too (default `1`). `ambientLight(_:)` is a flat term added to every surface — set it alongside the directional lights so faces turned away aren't pure black; an ambient *alone* gives a flat, unshaded fill of the surface color. `specular(_:)` and `shininess(_:)` set the highlight, and `material(_:)` sets a whole reusable finish at once (matte, glossy, iridescent, …) — see [Materials](#materials) below; all are drawing state saved by `withState`, so different solids can be matte or glossy in the same frame.

Each light also takes two optional refinements (passed to `directionalLight`/`pointLight`/`spotLight` or the `Light` factories). **`specular:`** tints a light's highlight separately from its diffuse color (default `nil` uses the light's color), so a light can throw a crisp white highlight over a warm key, or a bright rim. **`softness:`** (`0…1`) wraps the light a little past the terminator for a gentler shaded edge (a softbox versus a bare bulb); the default `0` is hard Lambert shading. The curated [lighting presets](#lights) lean on both.

The convenience calls:

- **`lights()`** — install the default rig explicitly (the same one used automatically). Handy to restore the default after using your own lights, or to make the intent visible.
- **`noLights()`** — turn lighting off for the frame: solids draw flat in their `fill` color (unlit). `ambientLight(.white)` is the other way to a flat, full-bright look.

#### Lighting presets

For a good-looking scene without hand-placing lights, hand `lightingPreset(_:)` a ready-made rig:

```swift
lightingPreset(.goldenHour)     // one call relights the whole scene
```

The curated set, each an ambient plus a few lights tuned with color temperatures (`Color(kelvin:)`):

- **`.standard`** — soft neutral ambient, a key, and a dimmer fill. The same rig solids get automatically; reach for it when you just want the scene to look 3D.
- **`.threePoint`** — the film key/fill/rim rig: a daylight key from the front-left, a cooler dimmer fill opening the shadows, and a rim light raking from behind for separation.
- **`.goldenHour`** — warm low sun with a cool sky bounce; long, warm shadows.
- **`.noir`** — a single hard, near-white key with the shadows crushed nearly to black. Pairs well with `castShadows()`.
- **`.studio`** — bright, soft, even daylight from several directions; low contrast, surfaces read clean.
- **`.moonlight`** — cool, dim, blue night light over a deep-blue ambient.

A preset is **per-frame** like the individual light calls (it replaces the auto-lit default), so call it in `draw()`. It's a plain value, so it's also how you extend the set — build your own or tweak a copy of a built-in:

```swift
var rig = LightingPreset.noir
rig.ambient = Color(white: 0.06)                       // lift the shadows a touch
rig.lights.append(.point(Color(kelvin: 8000), at: Vector3(2, 3, 1)))
lightingPreset(rig.intensified(by: 0.8))               // and dim the whole rig
```

`LightingPreset(ambient:lights:)` builds one from scratch; `intensified(by:)` returns a copy with every light's intensity scaled. There's no registry to register with; a preset is just a value you pass in.

Lighting is **per-frame**: one setup shades every mesh drawn this frame (like the camera), so place your lights once at the top of `draw()`. Per-mesh lighting state is a future refinement.

<a id="materials"></a>
### Materials

`material(_:)` gives a 3D shape its surface finish, the way it catches light. Pick one from the library and draw:

```swift
fill(.red)
material(.soapBubble)   // a rainbow sheen that shifts as the sphere turns
drawSphere(radius: 1)
```

The shape's **color** is its `fill`, set separately, so one material works in any color:

```swift
material(.clay)                       // a matte, earthy finish...
fill(.red);  drawSphere(radius: 1)    // ...on a red sphere
fill(.blue); drawSphere(radius: 1)    // ...and a blue one
```

#### The library

| Group | Materials |
|---|---|
| Matte to glossy | `.matte` · `.clay` · `.rubber` · `.plastic` · `.ceramic` · `.glossy` · `.polished` |
| Iridescent (view-angle rainbow) | `.iridescent` · `.soapBubble` · `.oilSlick` · `.beetle` |
| Glowing | `.velvet` (lit edges) · `.jade` · `.wax` (light through the surface) |
| Stylized | `.toon` (cel bands) · `.gooch` (warm-to-cool) |

`material(_:)` is drawing state saved by `withState`, so each shape can have its own material in the same frame.

#### Customizing

A `Material` is a plain value, so copy a built-in and change one thing, or build one from scratch:

```swift
var m = Material.glossy
m.iridescence = 0.4     // the glossy finish, plus a faint pearlescent sheen
material(m)

material(Material(shading: .toon, toonBands: 3, specular: 0.5, shininess: 64))
```

The pieces you can set:

- **shading** — `.standard` (smooth), `.toon` (cel bands), or `.gooch` (warm-to-cool).
- **specular** / **shininess** — the highlight's strength, and how tight it is.
- **rim** — a glow around the silhouette.
- **subsurface** — light glowing through thin parts.
- **iridescence** — a rainbow that shifts as the shape or camera moves.

To nudge just the highlight without rebuilding the material, call `specular(_:)` or `shininess(_:)` after `material(_:)`:

```swift
material(.glossy)
specular(0.4)           // the glossy finish, with a softer highlight
```

#### Notes

A material needs lights to show (the auto-lit default counts); under `noLights()` a surface draws flat in its `fill`. True *metal* (mirror-like, tinted reflections) and *glass* (see-through, refracting) need the physically-based / environment-lighting tier that's still ahead; `.polished` is as far as this model goes. See [`Examples/3D/Materials`](../Examples/3D/Materials).

<a id="matcap"></a>
### Matcap materials

A **matcap** ("material capture") is a different way to finish a surface: a sphere photographed or baked under fixed lighting, sampled by the **view-space normal**. Because the whole look (the lighting included) is painted into the image, a matcap needs *no* scene lights and costs one texture lookup. `matcap(_:)` wraps subsequent meshes in one:

```swift
matcap(.chrome)
drawSphere(radius: 200)
```

Reach for a built-in by name, bring your own matcap PNG, or generate one:

```swift
matcap(.clay)                                   // a bundled built-in
matcap(loadImage("my-matcap.png"))              // any matcap image
matcap(Matcap.shaded(baseColor: .teal,          // rolled-your-own, no asset
                     metallic: true))
noMatcap()                                      // back to the lit material model
```

A matcap is a **separate axis** from `material(_:)`: it bypasses the scene lights, `material(_:)`, and `castShadows()` entirely (the lighting is in the texture). The surface is tinted by the current `fill`, so `fill(.white)` shows the matcap as captured and other fills recolor it. Drawing state, saved by `withState`.

#### The built-in matcaps

The built-ins are real baked studio captures (CC0, derived from the Blender community's matcaps; see [`THIRD-PARTY-NOTICES.md`](../THIRD-PARTY-NOTICES.md)), grouped by family:

- **Metals**: `.chrome`, `.bronze`, `.carpaint`, `.hardSurfaceGrey`, `.hardSurfaceRed`
- **Clays / earths**: `.clay`, `.terracotta`, `.sage`, `.clayWarm`
- **Whites / ceramics**: `.pearl`, `.ceramic`, `.ceramicDark`
- **Translucent**: `.wax`, `.resin`
- **Neutral studio**: `.studio`, `.basicBright`, `.basicDark`, `.basicSide`
- **Toon / cel**: `.toon`, `.toonDark`
- **Diagnostic** (for inspecting geometry, not material looks): `.checkNormal`, `.checkGradient`, `.checkReflectionHorizontal`, `.checkReflectionVertical`, `.checkRimDark`, `.checkRimLight`

#### `Matcap.shaded(baseColor:metallic:roughness:)`

When you'd rather not bundle an asset, `Matcap.shaded(...)` renders an analytic shaded sphere on the CPU for a quick custom or recolored matcap. `metallic` tints the highlight by the base color (a metal) instead of leaving it white (a dielectric), and `roughness` (`0` mirror-sharp … `1` broad/matte) sets the highlight tightness. It's the same construct-or-reach-for-a-built-in shape as `Material` and `LightingPreset`.

```swift
matcap(Matcap.shaded(baseColor: Color(hex: 0x4488FF)))          // a blue plastic
matcap(Matcap.shaded(baseColor: .gold, metallic: true, roughness: 0.1))
```

Because the look is keyed to the *view*, a matcap shifts as a shape (or the camera) turns: orbit a matcap'd sphere and the highlights slide, as in [`Examples/3D/Matcap`](../Examples/3D/Matcap). Matcaps shade individual meshes only; the lit material model, cast shadows, and gradient paint don't apply to them.

<a id="shadows"></a>
### Shadows

Call **`castShadows()`** and solids ground in their setting, dropping shadows onto a floor and onto one another:

```swift
camera(.orbiting(target: .zero, radius: 12, elevation: 0.4))

directionalLight(.white, direction: Vector3(-0.5, -0.8, -0.4))   // the caster
castShadows()

drawPlane(width: 20, depth: 20)                  // the ground that catches them
withState { translate(0, 2, 0); drawSphere(radius: 1.5) }   // floats, casts a shadow below
```

Shadows are **opt-in** (a sketch that doesn't call `castShadows()` pays nothing) and **per-frame** like the lights and camera, so call it in `draw()`. It needs a camera and a caster: the scene's first **directional** light, or, when there's no directional, its first **spot** light, or, failing that, its first **point** light. (The auto-lit default's key is directional, so a default-lit scene just works.) With no camera or no caster it's a no-op. `noShadows()` (or `castShadows(false)`) turns it back off.

The shadow frustum **auto-fits** to the scene around the camera target, so there's nothing to size or aim. A directional caster uses an orthographic box, a spot caster a perspective frustum fit to its cone, and a point caster an omnidirectional cube (depth rendered into all six faces, sampled by direction) so its shadows fall every way at once. Under the hood it's shadow mapping: a depth pass renders the scene from the light's point of view, and each lit surface is darkened where that light can't reach it, with PCF for soft edges and bias tuned to keep self-shadowing artifacts off.

What participates:

- **Solid and textured meshes** cast and receive shadows. A **point** caster renders occluders' back faces into its cube map (to keep a surface from shadowing itself), so its casters should be solid, closed shapes; a thin or single-sided mesh casts cleanly from a directional or spot light, less so from a point light.
- **Wireframe meshes** don't (their faces are see-through), and **point clouds** and 2D drawing aren't shadow receivers.
- **Directional**, **spot**, and **point** casters. Softer (contact-hardening) shadows are a later step.

> Shadows render on the live window and through the headless image/snapshot export. The accumulation surface (`noClear`) and the texture/Syphon hand-off paths draw 3D without shadows for now, the same scope as their existing depth limitation.

The example `3D/Shadows` stands a few turning solids on a floor under a swinging directional key light; `3D/SpotShadow` casts from a sweeping spot light, and `3D/PointShadow` from a central point light whose shadows radiate outward.

<a id="textures"></a>
### Textured meshes

A mesh can wear an image on its surface, mapped through per-vertex texture coordinates (UVs) and lit like any solid.

#### `Mesh.textured(_:baseColor:)`

Returns a copy of the mesh wearing `image` as its surface, optionally tinted by `baseColor` (default white). It's a value transform, like `normalized(scale:)`:

```swift
let grid = loadImage("/path/to/texture.png")!
let globe = Mesh.sphere(radius: 200).textured(grid)
drawMesh(globe)
```

The texture maps through the mesh's **`uvs`** — the built-in `.sphere` and `.plane` generators emit them (the other generators fill in over time). A mesh with no UVs has nothing to map against, so it draws as a flat `baseColor × fill` surface instead; the texture is simply ignored until the mesh carries UVs.

The surface is the texture **tinted** by `baseColor × fill`: a white `fill` and white `baseColor` show the image as-is; either one colors it. The textured surface is shaded by the lights exactly like a solid one (the auto-lit default, or your own rig).

For full control, set the material directly — `MeshMaterial` is a value type (`baseColor` + an optional `texture`):

```swift
var floor = Mesh.plane(width: 800, depth: 800)
floor.material = MeshMaterial(baseColor: Color(white: 0.7), texture: grid)
```

A diagram of UV space (0,0 at the texture's top-left, matching image coordinates):

```
 (0,0) ───── u ─────▶ (1,0)
   │  ┌───────────────┐
   │  │   the image   │
   v  │   on the mesh │
   │  └───────────────┘
   ▼
 (0,1)               (1,1)
```

A textured `Image` can come from anywhere a normal one does: a loaded file, a frame you authored pixel by pixel, a live feed. The example `3D/TexturedMesh` builds a UV grid in code and wraps it around a sphere and a floor.

> A *loaded model's own* materials and textures are read by the loaders too (so a `.gltf`/`.usdz`/`.obj` arrives looking the way its author made it); see [Meshes from file](#load). `textured(_:)` is how you give *any* mesh an image yourself. Opaque base-color textures are the supported case; metallic/roughness and normal maps are the later PBR tier.

<a id="wireframe"></a>
### Wireframe

Draw a mesh as its triangle edges (the mesh "net") instead of filled surfaces.

#### `wireframe(_:)`

Drawing state, like `fill` and `stroke`: turn it on and every mesh drawn after it renders as edges, with the faces see-through. It works on any mesh, a built-in primitive or a loaded model.

```swift
wireframe()                      // edges from here on
strokeWeight(1.5)
stroke(Color(hex: 0x53D1FF))     // edge color
drawMesh(.icosphere(radius: 1.5, subdivisions: 2))
wireframe(false)                 // back to solid
```

The edges take the current **`stroke`** color (or the `fill` if there's no stroke) and **`strokeWeight`** for the line thickness. Because the faces are see-through, the back edges show through the front: the classic look for a structure study or a face/scan mesh. It's `withState`-scoped, so you can wireframe one shape and fill the next.

A wireframe doesn't light (there's no surface to shade), and it composes with the camera, depth, and transform stack like any mesh: a wireframe sphere occludes a solid one along its lines and vice versa.

<a id="transforms"></a>
### Transforms

In a 3D frame, `translate`, `rotateX/Y/Z`, and `scale` move geometry around *inside* the camera — the spatial siblings of the 2D transforms. They build a 4×4 **model matrix**, and `withState { }` saves and restores it, so you can place a body and come back:

```swift
camera(.orbiting(target: .zero, radius: 6, azimuth: time * 0.2, elevation: 0.4))

withState {
    translate(2, 0, 0)        // step along +x
    rotateY(time)             // spin about the world y-axis
    scale(Vector3(0.5, 0.5, 0.5))
    drawPointCloud(blob)      // drawn at (2,0,0), spun and half-size
}
// back to the original frame here — the withState restored it
```

The full set, all on `Sketch` (and the `Drawer`):

- `translate(_ offset: Vector3)` / `translate(_ x:_ y:_ z:)` — move in world units.
- `rotateX(_:)`, `rotateY(_:)`, `rotateZ(_:)` — rotate about a world axis (radians, right-handed: counter-clockwise looking from the positive axis toward the origin).
- `rotate(_ radians:axis:)` — rotate about an arbitrary axis.
- `scale(_ x:_ y:_ z:)` / `scale(_ factors: Vector3)` — scale per axis. Uniform scale is `scale(Vector3(s, s, s))`.

They **compose by post-multiplication** like the 2D stack, so `translate` then `rotateY` then draw places a point at `T · R · p`. Nesting `withState` is how an orbit rides another orbit — a moon inherits its planet's position and adds its own circle. The [`3D/Transforms`](../Examples/3D/Transforms/) example is exactly that: a sun, planets orbiting it, and a moon orbiting each planet, every body the same blob placed by a different stack of transforms.

Two things worth knowing:

- **Splat sizes are world units, so `scale` grows a body's dots too.** A body drawn at a small scale needs larger base `size` points to stay visible, since the transform shrinks the splats along with the body.
- **The 3D transforms don't touch 2D drawing.** Shapes, images, and text keep using the 2D transform (`translate(x, y)`, `rotate(angle)`, …), so both stacks stay live in a 3D frame — you can `withBillboard` a 2D label onto a 3D point in the same `draw()`. The 3D `translate(x, y, z)` (three arguments) and the 2D `translate(x, y)` (two) are distinct calls; the compiler picks by arity and by `Vector3` vs `Vector2`.

<a id="live"></a>
### A live depth cloud from a webcam

The Mac has no depth camera, but a neural depth model estimates one from a plain webcam — so a live 3D point cloud of whatever's in front of the camera is a `ModelTracker` plus this point-cloud path. The [`3D/DepthCloud`](../Examples/3D/DepthCloud/) example samples the depth map over a grid, lifts each cell into 3D by its depth, colors it from the camera image, and orbits the result. It's the Mac-side preview of the tethered-iPhone LiDAR cloud to come. (It needs the depth model — run `Scripts/fetch-models.sh` once.)

<a id="space"></a>
### World space

3D world space is **right-handed with y up**: x runs right, y up, and the camera looks down its local −z. Distances are in world units — whatever your geometry uses (meters for a depth cloud, say). This is a different convention from the 2D canvas (top-left origin, y *down*, points): 3D geometry lives in its own world space and reaches the screen through the camera. So a point cloud rides the camera and the **3D** transform stack ([Transforms](#transforms)) — never the *2D* affine (`translate(x, y)` / `rotate(angle)`), which keeps placing 2D shapes, images, and text.

`Vector3` carries 3D positions — `Vector2`'s arithmetic with a `z`, plus `cross` (returning a vector), `unitZ`, and `xy` to drop back to the canvas plane. See [Geometry](./Geometry.md).

<a id="ahead"></a>
### What's here, what's ahead

Here now: a perspective/orthographic camera, a depth buffer, the 4×4 transform stack ([Transforms](#transforms)), instanced point-cloud splats, the solid primitives ([Solid primitives](#primitives)) over a depth-tested mesh path, [meshes loaded from file](#load) (`.obj`, `.usdz`/`.stl`/`.ply`, `.gltf`/`.glb`) with their own base-color material and texture, the [light & material model](#lights) (directional/point/spot lights with a Blinn-Phong material, auto-lit by default), [lighting presets](#lights) (one-call rigs like `.goldenHour`/`.noir`), the [material library](#materials) (`material(_:)` with stylized finishes — iridescent, velvet, jade, toon, gooch — extensible like the presets), [matcap materials](#matcap) (`matcap(_:)` — a whole look in one view-normal-sampled sphere texture, 26 bundled CC0 looks plus a generator), [cast shadows](#shadows) (`castShadows()`, directional + spot + point), [textured meshes](#textures) (an image on a mesh's surface via UVs), and a [wireframe](#wireframe) mode. That's enough for point clouds (including a live webcam depth cloud) and lit, filled, textured, shadow-casting 3D shapes, and it's the foundation the rest of 3D builds on.

Ahead: softer, contact-hardening shadows, and physically-based shading with environment lighting (the later realism tier). 2D stays the default throughout.

<a id="notes"></a>
### Notes

- **2D is untouched.** With no camera, a frame allocates no depth buffer and renders exactly as before — the 3D path is entirely opt-in.
- **Depth testing** hides points behind nearer ones (less-equal, depth-writing). 2D overlays drawn in the same frame (a caption, a HUD) composite over the 3D scene in draw order without touching depth — *unless* they opt into a depth with [`depth(at:)`](./DepthCompositing.md), which lets a 2D mark sit inside the scene and be occluded by it.
- **Not yet in 3D:** the accumulation surface (`noClear`) and the live texture hand-off (Syphon, the virtual camera) render 3D without depth sorting for now — keep 3D sketches on the live window and the raster/PNG export paths, which are depth-correct.
