# Ollin — guidance for development

Ollin is a creative-coding framework for Swift + Metal (macOS). This file captures the design intent so work here stays coherent across sessions.

## Vision

**p5.js ergonomics on an OPENRNDR-grade core, with motion as the default.**

- The API people *type* should feel like p5: `setup()`/`draw()`, bare calls like `background(.white)`, `stroke(.black)`, `drawCircle(x, y, radius)`. That familiarity is the point — don't sacrifice it.
- The architecture they *grow into* should feel like OPENRNDR: typed value objects, an explicit `Drawer`, and composable geometry.
- `draw()` runs continuously at the display refresh rate. Animation is not opt-in — `radius: 120 + sin(time) * 40` just moves. `noLoop()` is the rare still-image escape hatch.

## Scope — a framework, not an editor (load-bearing)

Ollin is a *framework* — a library of creative-coding techniques you call from `draw()` — not an *application* you open instead of writing a sketch. The framing that keeps this honest: Ollin is a curated **collection of creative-coding recipes/techniques exposed as a coherent Swift API**, so depth is always welcome *as more recipes a sketch can call*, never as application surfaces that replace writing the sketch. The test for a feature: is it a *capability a sketch calls*, or an *application surface that owns the workflow*? The first grows without bound and Ollin stays a framework; the second is the drift to resist — a full 3D editor, a DAW, a video NLE, a node-graph studio.

**Richer experiences live in host apps built *on top of* the framework, not in the core.** `OllinLive` (dev hot-reload), `OllinExamples` (the gallery), and `OllinLiveCoding` (the live-coding / live-performance instrument) are apps that *consume* Ollin — the same tier, and the right home for performance- or editor-*shaped* features. **Live coding and live performance are first-class use cases** Ollin aims to serve, through that app layer. Three rules keep the apps from dragging the core out of lane: the framework stays fully usable on its own; the `.swift` **sketch is always the artifact and the source of truth**; and any tool is a *lens on that source* (round-trips to `.swift`), never a proprietary document only the GUI can open. A **code editor is the in-lane kind of editor** — `OllinLiveCoding` live-codes the Ollin **Swift sketch itself** (not just the shader part) and *shows* that code to the audience (the Hydra model, where the code is the performance), which keeps code canonical; a GUI document editor that makes the sketch incidental is the out-of-lane kind. (The live-coding loop builds on the shipped dylib hot-reload engine — `SketchLoader` / `SketchRunner.reload`, the `--keep-clock` phase-carry — driven from an in-app editor with evaluate-on-command, since Swift compiles rather than `eval`s.)

**Where Ollin meets the pro tools, it interoperates rather than replaces.** The integration tier — Syphon, OSC, MIDI, virtual camera, tempo sync (sync *to* Ableton, never *be* Ableton), USDZ export — is "play in someone's existing rig," not "be the rig." That interop posture is the framework lane expressed in code.

## Platform scope

Apple platforms only, by design. macOS is the focus today; iOS, tvOS, and visionOS are in scope as *future* targets (see the Swift Playgrounds / iOS follow-up and the 3D & visionOS follow-up). Linux and Windows are explicitly out of scope — not now, not later — so don't add cross-platform abstractions for them: lean on Metal, AppKit/UIKit, and SwiftUI freely. "No Linux/Windows" is not "macOS-only"; keep Apple-platform portability in mind (the `#if canImport(AppKit)`/`#if canImport(UIKit)` seams) so the iOS/visionOS work later isn't a retrofit.

**Web / WebAssembly was considered and declined, on purpose.** WASM (via SwiftWasm) is the one path to p5's "share a sketch by URL" web reach — the incumbents' biggest on-ramp advantage Ollin structurally lacks — so it's worth recording *why* it stays out rather than re-litigating it. The browser has no Metal: a web build needs a *second renderer* on WebGPU, exactly the cross-platform renderer abstraction this stance refuses, and the web version would be a reduced subset anyway (WebGPU has no hardware ray tracing or MetalFX, so the photorealism/RT tier wouldn't port, and the Apple-framework satellites — Vision, audio, MIDI, video, ARKit, the iPhone sensor link — have no browser equivalent). The Metal-native bet and a browser runtime are mutually exclusive, and the bet wins. Web *reach*, when wanted, is served by *exporting the artifact* (video / GIF / USDZ / SVG) and the OS-surface outputs, not a live web runtime; the only WASM use that wouldn't betray the bet is compiling the non-rendering geometry/SVG core for a web *tool* that emits vectors. The bar that would reopen it: WebGPU reaching feature parity (ray tracing included) *and* strong, specific demand for in-browser sketches — until both, it stays out.

## The architecture rule (load-bearing)

**The bare p5-style API is sugar over a public, typed core. Never make the facade the only path to a feature.**

- `Sketch`'s bare methods forward to an internal `Drawer` (see `Sources/Ollin/Core/Sketch.swift`). Keep that split. Anything `drawCircle(...)` can do, the `Drawer` should also do — with more control.
- The day a capability is reachable *only* through the bare API, the ceiling is capped. Build the feature on the core first, then add the sugar.

## Conventions

- **Typed value objects early.** Geometry and color are data you pass around, transform, and compose — not just immediate draw calls. Prefer adding `Vector2`, `Rectangle`, and a vector `Shape`/`Contour` type *before* the call sites multiply; retrofitting `x:y:` doubles into `Vector2` later is expensive.
- **Swift-idiomatic, not a literal p5 port.** Enums for modes (not `"CENTER"` strings), trailing-closure scoping (`withState { }`) over leaky global state, value types, overloads. Borrow p5's feel, not its warts.
- **Build on the extension seam.** OPENRNDR's `extend(...)` is shipped: register a `SketchExtension` (`Sketch.extend`) for `setup`/`beforeDraw`/`afterDraw` (in-frame, before the render — can draw into the canvas), `afterFrame` (post-render, with `FrameInfo` timing), and `frameRendered` (post-render, with the rendered `CGImage`) hooks. New cross-cutting features — overlays, guides, recorders, the FPS stats (already the seam's first customer) — bolt on as extensions instead of bloating the core. Extensions are per-instance, so the runner re-attaches built-ins like the stats observer across live-reload swaps. The **frame-grab** hook is the seam's latest customer: `frameRendered(_:_:)` hands an extension the rendered frame, *opt-in* via `wantsRenderedFrame` (read live each frame, so a recorder can arm/disarm) so only something recording pays the GPU→CPU readback; on the live path it's served by an off-screen re-render (pixel-identical to export, keeps it off the present path — an async drawable readback is a later optimization). The same capture without a window is the public headless `OllinApp.image(of:frame:)` (returns a `CGImage`; `OllinApp.export` is the PNG wrapper over it), which is what the render-correctness snapshot tests diff against committed references.
- Drawing methods live on `Sketch` (scoped to the instance), not true globals — keep it that way.
- **Draw verbs, not nouns.** Geometry-emitting calls are imperative verb phrases with a `draw` prefix — `drawCircle`, `drawRect`, `drawLine`, `drawPolygon`, `drawPolyline`, never bare nouns (`circle`). They read as the side-effecting immediate-mode commands they are (what the Swift API Design Guidelines want), and the prefix gives a clean rule: `draw*` emits geometry; state (`fill`/`stroke`/`background`) and transforms (`translate`/`rotate`/`scale`) keep their own names. "Feels like p5" is the *shape* of the API — bare top-level calls, terse positional args, motion by default — not p5's literal spelling, so the prefix keeps the feel and stays a good Swift citizen. New primitives take it too (`drawEllipse`, `drawTriangle`, …). (oF landed here too: `ofCircle` → `ofDrawCircle`.)
- **Consistent point arguments.** A primitive that takes a point offers a *positional* scalar form and a *role-labeled* `Vector2` form: `drawCircle(x, y, radius)` beside `drawCircle(center:radius:)`, `drawRect(x, y, width, height)` beside `drawRect(corner:…)`/`drawRect(center:…)`, `drawLine(x1, y1, x2, y2)` beside `drawLine(_:_:)`, `translate(x, y)` beside `translate(_ offset: Vector2)`. The rule: bare scalars go positional — everyone knows the `x, y, radius` order, and labels on them are pure stutter once call sites pass `x`/`y` variables (`drawCircle(x: x, y: y, …)`). The label is reserved for the value-object overload, where it names the *anchor* (`center:` vs `corner:`) and carries real information. New point-taking primitives (`drawEllipse`, `drawPoint`, `drawTriangle`, …) follow the same split. (Unlike Kotlin/OPENRNDR, Swift can't make one declaration callable both ways, so don't double the overloads to fake "both" — pick positional for the scalar form.)
- **State stack reads as Swift.** The drawing-state stack is `pushState()` / `popState()` — the combined transform+style snapshot, mirroring Core Graphics' `saveGState`/`restoreGState` — with `withState { }` as the scoped, exception-safe primary form (the `with…{ }` idiom of `withAnimation`/`withTaskGroup`). Reach for `withState { }`; the bare pair is the escape hatch. Combined (not split into transform vs style) by design; a split push/pop can come later as `Drawer`-level methods.
- **Deprecation path is a 1.0 gate.** Pre-1.0 the public API churns freely with no shims (the README disclaims stability) — no external sketches to protect yet, so renames like the noun→verb (`circle`→`drawCircle`) and `push`/`pop`/`isolated`→`pushState`/`popState`/`withState` ship unshimmed. *Before* 1.0, stand up the migration discipline that holds from 1.0 on: every public rename/removal ships an `@available(*, deprecated, renamed: "…")` shim that forwards to the new API, so Xcode offers a one-click fix-it. Gotchas: use the *full selector* in `renamed:` when labels or arity differ (`@available(*, deprecated, renamed: "drawCircle(_:_:_:)")`, not just `"drawCircle"`); keep deprecated members together (a `Deprecations.swift`) so they're easy to audit and drop after a grace cycle; have the shim *forward* to the new API, not duplicate it. A must-do gate, not a nice-to-have — the 1.0 stabilization pass is where the pre-1.0 renames get their shims.

## Sourcing & attribution (load-bearing — it's the public face)

This project is built with AI and says so openly (the README's "Built with AI" and "Influences & attribution" sections; the latter is a summary of the full credit record in the repo-root `ATTRIBUTION.md`). Getting attribution and license-compatibility right earns the creative-coding community's trust — treat it as first priority, not a side chore.

The framework is *inspired by* p5.js (LGPL-2.1), OPENRNDR (BSD-2-Clause), and openFrameworks (MIT): borrow their ideas and API vocabulary, write the implementation independently. **Never translate their source line-by-line** — a port of source is a derivative work that carries the original's license, and p5.js's LGPL is incompatible with Ollin shipping wholesale as MIT. "Inspired by" keeps Ollin MIT-clean; "ported from source" does not.

**One sanctioned exception: bundled third-party source (a distinct tier).** A library may be *vendored* — shipped as actual source — when it's a self-contained, permissively-licensed component wasteful to reimplement, wrapped behind Ollin's own API so it stays swappable and off the public surface. This is the opposite of inspired-by (it *is* their code), so it carries license obligations: keep the upstream LICENSE + per-file headers **intact** in the vendored dir (the one exception to "no framework names in code" — they're the library's own headers, and stripping them breaks the license); record provenance (upstream URL, commit, date); list it in the repo-root `THIRD-PARTY-NOTICES.md`; add a *Bundled third-party code* entry to `ATTRIBUTION.md` (the credits file the README links); keep the root `LICENSE` pure MIT so GitHub's root-only license detection holds the "MIT" badge. Vendor under `External/`, not `Sources/`. The first and only instance is **libtess2** (`External/CLibtess2`, SGI-B), the triangulator behind `Shape`/`Contour`. This tier is *not* a license to vendor copyleft (LGPL/AGPL/GPL) code, which stays inspired-by-only.

For ported *example sketches* (the iterate-by-porting workflow), provenance is per-sketch and must be honored:

- **Only port sketches whose license permits redistribution under MIT** — MIT, BSD, Apache-2.0, CC0/public domain, or CC-BY (with credit). For GPL/LGPL, CC-BY-NC, or CC-BY-SA sources, either get permission or rewrite the sketch as original work using the source only as inspiration (credit it as "inspired by").
- **Name the source in the file header** — the specific sketch, its author, a URL, and its license. Template lives in `Examples/README.md`.
- When unsure of a sketch's origin or license, **ask before committing it.** A trivial sketch (a plain dot grid) may fall below the copyright-originality bar, but crediting the inspiration is still the default.
- **Recreations** (`Examples/Recreations/`, organized by artist) credit the artist, framed as a homage *after* them (not a reproduction, not endorsed), plus the SFPC "Recreating the Past" class that inspired the section. Some are *ported* from a source sketch, so they also carry the code-lineage header (e.g. the Molnár ones, via the p5 repo); others are *original* Ollin interpretations built directly from the artwork, with no code lineage (e.g. the Riley one). Either way, name the artist and work and keep the homage framing. See `Examples/Recreations/README.md`.
- **Keep framework names — and product/lineage comparisons — out of code.** The influence story (p5.js / OPENRNDR / openFrameworks) lives in this file, the README, `ATTRIBUTION.md`, and commit messages — *not* in `.swift` comments. This is not limited to those three: it covers any *external product* reference (e.g. **Record3D** the capture app, SinkCam, Hydra) **and** *lineage/marketing comparison framing*. Don't write `// p5 default`, `/// like oF's ofNoise`, `// the own-app successor to borrowing Record3D's feed`, `// Ollin's own-app answer to X`, `// the way X does, but ours` — keep the information, drop the name *and* the comparison. (Ollin's *own* type/example names — `Record3DDevice`, `Camera`, `PhoneBodyPose` — are fine as plain internal cross-references, and Apple-framework API names actually in use — ARKit, Vision, usbmuxd — are fine; the prohibition is *external* product/framework names and *comparison framing*, not internal documentation.) Apply this *at authoring time*, not as a later cleanup, and when sweeping a file check *pre-existing* comments too — these have slipped into committed code before. The one *exception* is the per-example attribution header, which credits the actual source lineage. Source littered with running comparisons reads like a port and undercuts the "independent implementation, inspired-by not copied" stance.

There's a second tier of influence worth distinguishing from the conceptual one. Where p5.js / OPENRNDR / openFrameworks shaped the *API and ideas*, two peer Swift+Metal frameworks were read for *engineering approach* on the same platform: **swifty-creatives** (Apache-2.0, Processing-style immediate-mode) and **AsyncGraphics** (MIT, GPU image/video compositing). They were studied, not ported — specific lessons are noted inline through this file (shader build, pipeline cache, SDF circle, iOS seam, easing, snapshot testing). Same rules apply: credit them in `ATTRIBUTION.md` and commits, never in `.swift` comments, and write our own implementation. The public credit lives in `ATTRIBUTION.md` (linked from the README). (PixelKit is AsyncGraphics's older node-graph predecessor; cite AsyncGraphics instead.)

A third tier names influences for *capabilities still ahead* — shader-function collections, shader-composition / livecoding APIs, and AR. **These are inspirations, not dependencies:** *study how they work and reimplement our own*, never vendor or depend on them. It's especially clean for the shader-function collections — mostly implementations of *known, published techniques* (SDFs, noise, blends, color-space math, domain repetition): peek at the approach, then write Ollin's own, preferring the canonical source of a technique over any one collection's expression. Licenses still drive the no-line-by-line-copy rule:

- **LYGIA** (github.com/patriciogonzalezvivo/lygia, Patricio Gonzalez Vivo, who also created The Book of Shaders) — a large, multi-language catalog of shader functions (GLSL/HLSL/WGSL/CUDA plus an *experimental, partial* MSL/Metal port: `sdf`, `sampler`, `blend`, parts of `distort`/`generative`/`math` done; `lighting`/`geometry`/`palette` not yet). The best *map* of which techniques exist and how they're commonly approached. Licensed **Prosperity Public License 3.0.0** (noncommercial) — since we reimplement rather than ship its code, that's not a bundling problem; it's the reason to never translate a LYGIA file line-by-line and to implement from the underlying technique instead.

The thing to mine is *how it makes combining and mixing visuals so fluid* — borrow that ergonomic direction. Licensed **AGPL-3.0** (strong network copyleft) → **inspiration only**, never ported or vendored, exactly like p5.js's LGPL.
- **ShaderPark** (github.com/shader-park — `shader-park-core`, `shader-park-examples`, `shader-park-live-coding`, all **MIT**) — a JS→shader SDF "sculpting" library with composable combine/blend functions and its own livecoding environment; another reference for *how to compose and mix* shader-driven shapes. MIT, so it can be studied freely — still: write our own, credit it.
- **ofxFX** (github.com/patriciogonzalezvivo/ofxFX, Patricio Gonzalez Vivo again, **MIT**) — the openFrameworks effects addon behind his *Efecto Mariposa*: each effect is a ping-pong-FBO object chained/mixed with a `<<` operator, organized as composers (blend/mask/multi-texture), filters (blur, gaussian, bloom, glow, bokeh, **LUT color grading**, chroma aberration, old-TV), generative (noise, FBM, fire, Gray-Scott), and operations (ripples, flow, edge detect, normals). The reference for the [layered-effects](DESIGN-NOTES.md#layered-effects-and-compositing-partly-shipped) *effect-object architecture and catalog* — blending fx shaders and LUTs — from the GL/oF generation, beside AsyncGraphics' Metal-native take. MIT, study freely — still: write our own, credit it.
- **Paper Shaders** (github.com/paper-design/shaders, paper.design, **Apache-2.0**, shaders by Ksenia Kondrashova) — production design-shader effects for the web: mesh gradients, liquid metal, fluted glass, god rays, water, heatmap, paper texture, dithering/halftone. The map of which *designer-facing* effects exist and their parameter feel — the design-pattern `Generator` set was cross-read against it (written from the canonical techniques, credited per-technique in `ATTRIBUTION.md`), and the design-filter set (fluted glass, water, paper texture, liquid metal, heatmap, gem smoke) was cross-read the same way. Permissive, so study freely — still: write our own, credit it.

Conceptual/product influence only; there's nothing to port. (Used in Zach Lieberman's AR class — keep that personal detail out of public files, see the AR follow-up.)

Same rules as every tier: credit in `ATTRIBUTION.md` and in commits, never in `.swift` comments, own implementation.

## Shaders & the Metal back end

The shader set is split across several `.metal` segments (`Renderer/Shader*.metal`), concatenated and compiled as one library at runtime (see *The shader set is multiple segments* below). Decisions that are cheap now and expensive to retrofit:

- **One source of truth for CPU↔GPU structs — defined once in a shared C header.** The three structs shared between Swift and MSL (`OllinVertex`, `Uniforms`, and `SDFInstance` — the last a stride-144 *tagged union* that keeps growing) live in `Sources/Ollin/Renderer/OllinShaderTypes.h`, so a field can't drift between the two sides and silently corrupt memory. Swift imports them through the thin `COllinShaders` C target (whose umbrella header re-includes the canonical file by relative path, since SwiftPM won't let a resource escape its target or two targets' dirs overlap); `ShaderCore.metal` (the first segment) `#include`s the same header. The one wrinkle the header note predicted: runtime `makeLibrary(source:)` has no include path, so `MetalRenderer.composeShaderSource` splices the header's text in for the `#include` directive before compiling — which is why the header ships *beside* the segments as a `.copy` resource. The fields are spelled in the `simd_*` names the Swift importer maps to `SIMD2<Float>`/etc.; a `__METAL_VERSION__` guard aliases those onto Metal's `float2`/`float3x3`. **A new shared struct (or a wider `SDFInstance`) goes in that header — never re-declared in two places.**
- **Runtime source compilation is a feature, keep it.** `loadLibrary` concatenates the `.metal` segments and compiles them from source at runtime (`makeLibrary(source:)`). For a creative-coding framework that's the seam for shader hot-reload and user-supplied shaders later — don't rip it out. Its costs are startup time and *no build-time error checking*.
- **Add a precompiled `default.metallib` when those costs bite, don't replace.** Build-time validation and zero startup cost need the built-in shaders compiled ahead of time. `loadLibrary` prefers a precompiled `Bundle.module` metallib *before* the source path **on a non-ray-tracing device** (an RT device source-compiles, to splice in the device-conditional `OLLIN_RT_SHADOWS` define), so a precompiled lib slots in with no API change; runtime compilation stays for dynamic shaders. Two facts settle *how* to produce it (both verified on this toolchain — Swift 6.3, macOS):
    - **Ship `.metal` as `.copy` (raw source) — `.process` now precompiles a metallib.** Ollin compiles its shaders from source at runtime, the seam the shader hot-reload, user shaders, *and the device-conditional `OLLIN_RT_SHADOWS` ray-traced-shadow path* all rely on — so the raw `.metal` must reach `Bundle.module`. **On current SwiftPM toolchains, `.process` on a `.metal` precompiles a single `default.metallib`** (and stops copying the raw source), so `makeDefaultLibrary(bundle: .module)` then succeeds — convenient for a fixed shader set, but a metallib holds only one compile, so it *can't* carry a device-conditional variant. That's why the `Shader*.metal` segments are **`.copy`** resources and `loadLibrary` source-compiles on a ray-tracing device (preferring the metallib only on non-RT GPUs). (Historically `swift run` did *not* auto-compile loose `.metal` — that was Xcode-build-system-only — but the toolchain caught up; don't assume `.process` leaves the source uncompiled.)
    - **A precompiled `default.metallib` shipped as a `.copy` resource loads fine.** `xcrun metal` + `xcrun metallib` produce a `default.metallib`; `.copy`-listed in the target, it's found by `makeDefaultLibrary(bundle: .module)`. So under `swift run` the path is a SwiftPM build-tool plugin that runs that compile and emits the metallib as a resource. (Playgrounds plugin support is unreliable — see the iOS follow-up — so keep runtime source compilation too; never go plugin-*only*.)
- **A user-supplied shader-library seam is cheap.** Resolve the active library as `customMetalLibrary ?? defaultMetalLibrary` so a user can drop in their own compiled library without touching the built-ins; pairs with the runtime-source loader for hot-reload. (Both peer Swift+Metal frameworks expose exactly this.)
- **Built-in shader functions are our own, written from the technique — not a vendored library.** As the shader set grows past drawing (noise, SDF primitives, blends, color-space conversions, domain repetition), implement each from the *published technique*, then credit that source in the `ATTRIBUTION.md` Techniques list (as the cosine `CosinePalette` and `curlNoise` already do). The canonical sources to reach for, baked in here so we go straight to them: **Inigo Quilez** for signed-distance functions (2D `iquilezles.org/articles/distfunctions2d`, 3D `/distfunctions`) and smooth-minimum, and the cosine palette (already used); **hg_sdf** (`mercury.sexy/hg_sdf`) for domain operators — axis rotation, mirror, and linear/polar repetition; **The Book of Shaders** for hashing and value noise. LYGIA is a broad *catalog/map* of which techniques exist and how they're approached — read it to discover, implement from the underlying technique, never translate its files (Prosperity; see [Sourcing & attribution](#sourcing--attribution-load-bearing--its-the-public-face)). (Distinct from the user-supplied seam above, which is for a *user's* own shaders, not for vendoring someone else's library into Ollin.)
- **Cache pipelines; don't grow `init`.** `MetalRenderer.init` builds one `MTLRenderPipelineState` inline. A new pipeline (textured quads, a new blend mode, compute) should be a cache lookup, not more code in the constructor. Key the cache on a `Hashable` descriptor struct (shader, blend mode, MSAA sample count, pixel format), not a flat enum: pipeline variants are *combinations* of those axes, and a struct key captures the product without an enum case per combination. Folding blend mode into that descriptor also keeps it a pipeline *parameter* — one pipeline factory — rather than a whole renderer subclass per blend mode (the trap a peer framework fell into).
- **The shader set is multiple `.metal` segments, concatenated at load.** It outgrew a single file at ~2,000 lines and split into `Renderer/Shader*.metal`: `OllinShaderLib` (the shared helper library — see *User-supplied shaders*), `ShaderCore` (preamble + shared color/dither/hash helpers), `ShaderShapes` (SDF primitives + the shared `ollin_sdf_distance`), `ShaderCombinator` (the SDF-combinator node VM — must follow `ShaderShapes`, it reuses `ollin_sdf_distance` + the coverage tail), `Shader3D` (particles/cloud/mesh/matcap/wireframe), `ShaderRaymarch` (the 3D SDF sphere-marcher — must follow `Shader3D`), `ShaderEffects` (present + the single-input filters + basic generators; `PresentOut` lives here for every later segment), `ShaderCombine` (two-input combines + the screen-space depth ops + the deferred RT-reflection passes), `ShaderSim` (the stateful ping-pong sims + fluid), `ShaderPatterns` (the design-pattern generators + design filters), `ShaderIBL` (the environment bake). `loadLibrary` reads them from `Bundle.module` in the fixed order `MetalRenderer.shaderSourceNames` and concatenates into one compile unit, because runtime `makeLibrary(source:)` has no include path (so an `#include` umbrella can't work). **Order is load-bearing:** `ShaderCore` is first because Metal needs a declaration before use and the later segments rely on its helpers; no segment is compilable alone, and the header `#include` lives once in `ShaderCore` for `composeShaderSource` to splice. Live shader reload (`SketchRunner.reloadShaderLibrary(fromDirectory:)`, used by OllinLive) concatenates the same segments from the repo filesystem via `MetalRenderer.concatenatedShaderSource(fromDirectory:)`. Adding a segment: create the file, add it to `shaderSourceNames` (in dependency order) and to the `Package.swift` `.copy` resources.

## Rendering performance (roadmap)

The drawing model is *immediate-mode GPU*: every frame `Drawer` tessellates each primitive into one flat triangle array on the CPU, the renderer uploads it to a **triple-buffered, semaphore-gated vertex-buffer ring**, and issues a single `drawPrimitives`. (That ring is load-bearing — never collapse it back to one shared buffer: writing a buffer the GPU is still reading for an in-flight frame tears the geometry on screen, e.g. gaps in a stroked ring. That was a real bug, fixed by the `maxFramesInFlight` ring + `frameBoundary` semaphore in `MetalRenderer`.) This is the right shape — it's what NanoVG, Dear ImGui, and Processing's GL renderer do — so the "low-level" look is the cost of a Metal core, not accidental complexity. Don't trade it for Core Graphics / SwiftUI `Canvas` / SpriteKit: those are CPU rasterizers or retained-mode scene graphs, and adopting one as the substrate throws away the GPU + shader ceiling the whole vision rests on.

Where it caps out, and the levers — in priority order, all *iterations on this pipeline, not rewrites*:

- **CPU tessellation is the first bottleneck, not the GPU.** Re-tessellating thousands of primitives every frame on the draw thread stalls long before the GPU breaks a sweat. Everything below attacks that cost.
- **Instancing is the biggest lever.** Upload one unit-circle mesh once and draw it N times with a per-instance buffer (center, radius, color) via `drawPrimitives(instanceCount:)`. CPU work per circle drops to a struct write; this is the "10,000 circles at 60fps" path. It's a new `Pipeline` case (`.instancedCircle`) plus a per-instance buffer — the cache seam already exists for exactly this.
- **SDF analytic primitives (point, circle, ellipse, rect, oriented box, line, circular arc, triangle, general 3-point triangle, quadratic Bézier, regular polygon, star, rhombus, vesica, oriented vesica, moon, cross, ring, trapezoid, parallelogram, egg, heart, cut disk, uneven capsule, horseshoe, parabola, rounded X, blobby cross, tunnel, stairs, cool S) — *shipped*.** `drawPoint`/`drawCircle`/`drawEllipse`/`drawRect`, circular `drawArc`, `drawTriangle` (equilateral + isosceles), and `drawNgon`/`drawStar` are no longer tessellated: each is one instanced quad (`SDFInstance`, the `.sdf` `Pipeline` case). (`drawLine`/`drawBezier` were SDF too, but moved to the **fringe stroke path** — see the *Strokes render through the fringe expander* paragraph below; their `.capsule`/`.bezier` shader cases are retained-but-unemitted.) `SDFInstance` is a *tagged union* — a `shape` tag plus generic `size`/`param0`/`param1`/`param2`/`extra` slots — and `ollin_sdf_fragment` switches on it to evaluate the matching SDF, then runs a shared fill + stroke + anti-aliasing tail (iq's 2D distance functions, written from the technique). Per-shape CPU cost is one struct write — `Myriad` draws 8,100 circles at ~1,100 fps CPU ceiling. Each instance carries its own CTM (`float3x3`), so the fragment evaluates the SDF in local space and AA stays ~1px under any transform (`fwidth`); the quad covers `size` + ½ stroke + a small margin. (Circle approach studied from AsyncGraphics's circle shader, MIT — written independently.) The per-shape encodings — which param slot carries what and the `sd*` each calls (`drawPoint`'s round/square/diamond/cross/x markers, `drawNgon`/`drawStar` sharing one `sdStar`, the egg/heart/tunnel/stairs Y-flips, the three-point `drawTriangle` and `drawBezier` reading their free points from `param0`/`param1`/`param2`, and the rest) — live in `SDFShape` + `ShaderShapes.metal`; all evaluate iq's distance functions and all region shapes use `regionCoverage`. One rule there is *not* safely discoverable from the code, so it stays: the four roundable shapes (rhombus/vesica/moon/cross) take a footprint-preserving `cornerRadius`, and vesica/moon must `opRound` off a *full-footprint* SDF — insetting the vesica's waist toward zero sends its derived circle radius/offset to ~1e7 and the shader's `sqrt(r²−d²)` loses all precision (a real glitch, fixed by the full-footprint form). **Coverage is split by whether a shape tiles, and it's load-bearing.** `box`, `pie`, `chord`, `triangle`, `star`/n-gon, and the non-round point `marker`s use an **inside-biased** ramp (`regionCoverage`: full to the geometric edge, AA halo only outside) so abutting fills — tiled grids, gradient bands, the rotated wedges that tile a cell in `LifeQuilt` — leave no seam; never move them onto the centered ramp or the seams return. The **disk (ellipse/circle/round point)** and **capsule/line** instead use **area-conserving** coverage (`diskCoverage` and the capsule case): a centered AA ramp, but any mark smaller than ~½px on screen keeps a ~1px footprint while its alpha scales by the true/clamped **area** (disk) or **width** (line). That makes sizes run from 0…n — tiny dots, small circles, and thin lines fade by area instead of popping in, snapping to a 1px floor, or flickering as they move — and it's safe because disks and lines never tile edge-to-edge, so they don't need the inside bias. **Stroke *bands* conserve ink the same way:** a shared `strokeBandCoverage` (used by both `regionCoverage` for region-shape outlines and `diskCoverage` for disk outlines) holds a band thinner than ~1px at a ~1px footprint and scales its alpha by the width ratio — the capsule's trick — so an outline thinner than a pixel fades by ink to nothing instead of plateauing at a fixed hairline (the old smoothstep band floored at ~half coverage as `hw→0`, so a 0.4px and a 0.05px outline read alike); a band ≥~1px reduces to the plain smoothstep edge it always was (byte-identical, snapshot-safe), so only sub-pixel outlines change. (These area-conserving paths and every stroke band then run their coverage through `perceptualCoverage`, and the capsule/bézier footprint is the L2 gradient length rather than `fwidth` — both detailed in the linear-light bullet below.) **The other load-bearing piece is draw-order preservation:** `Drawer` records geometry into call-ordered `GeometryBatch`es (a run is `.triangles` or `.sdf`), so SDF shapes and tessellated triangles composite front-to-back as the sketch drew them — never collapse that into two unordered passes (it breaks occlusion, e.g. EllipseField's black-fill ropes). Still on the triangle path by nature: arbitrary `drawPolygon`/`drawPolyline`, and *elliptical* + full-turn arcs (`drawArc` runtime-branches `rx == ry` and sweep `< τ` to SDF, else tessellates). **Hollow/band mode** generalizes the ring's `opOnion` to every region shape: `hollow(_:)` / `solid()` set a per-instance `bandWidth`, and `regionFill` onions the shape's SDF (`abs(d) − bandWidth/2`) before `regionCoverage`, so the `fill` paints a constant-width band hugging the outline and an active `stroke` borders *both* edges (the framed-ring look stroke alone can't make). The band straddles the edge, so the covering quad grows by `bandWidth/2`; the `bandWidth` field fit the `SDFInstance` *tail padding*, so it forced no widening (the struct only grew later, to 144, for the three-point shapes' `param2`). Region shapes opt in via `SDFShape.honorsHollow`; points, lines, and the ring (already a band) opt out, and the round-dot point opts out by hand since it shares the `.ellipse` tag (a solid disk's area-conserving `diskCoverage` is bypassed for `regionFill` only when banding). **Stroke alignment** (`strokeAlign(_:)` → `.center`/`.inside`/`.outside`) rides the same coverage tail: `regionCoverage`/`diskCoverage` take a `strokeBias` (`0` / `−hw` / `+hw`) that shifts the stroke band off the edge (`abs(d − strokeBias) < hw`) while the fill still stops at `d = 0`, so the inset/outset is an exact SDF offset; `.center` (bias 0) is byte-identical to before. The 3-state align rides in **bits 8-9 of the `shape` tag** (the tag is < 256), so the vertex shader masks (`shape & 0xFF`) before the switch and align costs the instance no room; `.outside` grows the covering quad by another ½ stroke. Hollow forces the bias to 0 (a band already has two edges); lines/points/open-arc never compute a stroke band, so they stay centered.
- **More SDF primitives — the cheap catalog expansion (roadmap).** The tagged union has a *scalar budget* — `size`(2) + `param0`(2) + `param1`(2) + `param2`(2) + `extra`(1) on top of the per-instance CTM/center/colors/stroke — so any shape that's a *canonical form parameterized by a size + a ratio or two* drops in as the same four touch-points (an `SDFShape` case, a `Drawer.draw*` builder, an `sd*` function, a fragment `case`) with **no renderer/pipeline change**; position/rotation/scale come free from the CTM. One constraint: `size` is *not* a free slot — the vertex shader uses it as the covering quad's AABB half-extent, so it carries the bounding extent and can't double as a geometry point. All from iq's 2D distance functions, implemented from the technique and credited in the `ATTRIBUTION.md` Techniques list (canonical-source and no-copy rules under *Built-in shader functions* above; **hg_sdf** is the source for the *operator* track below). More canonical iq forms drop in the same four touch-points whenever one's wanted. The two shapes that need **three free points** beside `size`-as-AABB — the **general 3-point triangle** and the **quadratic Bézier** stroke (`sdBezier`, the *fast* path for curved contours, exact AA, no tessellation) — forced the one widening so far: a `param2` (2) slot added to `SDFInstance` in the shared C header (one definition for both sides — see *One source of truth for CPU↔GPU structs* below), taking the stride 128 → 144; the 8 bytes of tail padding that left have since been claimed by the gradient-paint row fields, so the struct is *full* at 144 — the next field is a real widening. Two things stay *off* this list by nature: arbitrary polygon/polyline (variable vertex count — they stay on the triangle path / libtess2), and SDF *operators* (smooth-min, union/subtract, hg_sdf domain repetition) which *combine* fields and so live on the **SDF-combinator path** (the `SDF` value type + `ShaderCombinator.metal`'s node VM — see *SDF combinators* under *Current state*), not the one-shape-per-instance primitive path.
- **MSAA is 8× where the device supports it** (else 4×), and only for the *triangle* path. The SDF primitives already bypass it (analytic coverage); the remaining triangle-path shapes (polygon/polyline, elliptical/full arcs) are where thin strokes or large zoom can still reveal that limit. The sample count is chosen once via `ollinPreferredSampleCount(_:)` (`SketchView.swift`) and shared by the live view and the export paths.
- **Rendering is gamma-correct (linear-light).** Geometry composites into a **linear `rgba16Float` intermediate** (`linearFormat`; the sRGB `.bgra8Unorm_srgb` `ollinColorPixelFormat` is now the *drawable*/present-target format, not the geometry target — see *HDR / float pipeline* under *Current state*), so the hardware blends and resolves MSAA in linear space — anti-aliased edges and translucent stacks composite physically, not with the too-dark fringes of a gamma-space blend, and the float precision means many overlapping translucent layers don't band as an 8-bit intermediate would. Three load-bearing pieces keep tones from shifting: (1) the shaders **linearize** their sRGB `Color` inputs before compositing and output linear into the float target (the *present pass* re-encodes to sRGB, not the geometry store); (2) the **background/clear color** is *also* linearized (`Color.srgbToLinear` in `mtlClearColor`) so the clear value lands in the float target as linear, matching the shaded geometry — miss this and the background washes out lighter (the clear bypasses the shader); (3) image textures load `.SRGB: true` so each sample decodes to linear, matching the linearized solid colors beside them. A triangular-PDF **dither** (a pure function of pixel position, so renders stay reproducible) is applied in `finalizeColor` — which now runs **in the present pass** (the single 8-bit quantization point, after tone-mapping the resolved float frame) — just before the 8-bit quantization to break the banding smooth gradients otherwise show. The image fragment still skips the dither (its source pixels are premultiplied; it outputs premultiplied linear straight into the float target). **One deliberate carve-out from pure linear light: stroke and disk/dot AA *coverage* is remapped to perceptual alpha** (`perceptualCoverage`, `1 − srgbToLinear(1 − c)`) before compositing. Linear blending makes a partially-covered dark mark read lighter than its coverage (a 50%-covered black pixel → sRGB ~0.74), so a thin diagonal line's correctly-conserved ink splits across the pixel staircase and reads faint/"beaded" — the bug that made the Molnár *Interruptions* field look chopped after the linear-light switch. The remap lands each covered pixel at the gamma-space darkness its coverage implies, so a 1px stroke is evenly dark at *any* angle and a sub-pixel mark still fades 0…n. It touches **only partial coverage** (`perceptualCoverage(1)=1`, `(0)=0`) and never a shape's own fill/stroke *alpha*, so solid interiors and translucent/overlap blending stay linear-light (solids still merge correctly). It's applied to the capsule/`drawBezier` strokes, `diskCoverage` (fill + outline), and `regionCoverage`'s **stroke** band — but **not** the region *fill* ramp, which stays plain linear so abutting fills tile seamlessly. Paired with this, the capsule/bézier footprint uses the **L2 gradient length**, not `fwidth`: a unit-gradient distance field's L1 norm overshoots √2× at 45°, which had been fading diagonal 1px lines as if sub-pixel. (Verified near-optimal for the raster path: 4× SSAA barely beats it — a 1px diagonal's residual softness is fundamental to native-resolution rasterization, see [`DESIGN-NOTES.md`](DESIGN-NOTES.md).)

Seam in place and now exercised: `MetalRenderer` builds pipelines through an enum-keyed cache (`Pipeline` + `makePipeline(_:)`) — `.solid` and `.sdf` today — so further pipelines slot in as new cases instead of more `init` code. Once variants multiply across blend mode × MSAA × pixel format, migrate that enum key to a `Hashable` descriptor struct (see *Cache pipelines* above) rather than enumerating the product by hand. (The CPU↔GPU structs feeding these pipelines live in the shared C header — see *One source of truth for CPU↔GPU structs* under *Shaders & the Metal back end*.)

Triangulator — *shipped, not hand-rolled.* The vector `Shape`/`Contour` type (concave polygons, holes) fills via **vendored libtess2** (the GLU tessellator lineage Processing/p5 descend from), wrapped in `Shape.triangulatedFill()` (`ShapeTriangulator.swift`, `import CLibtess2`) and drawn by `drawShape` on the triangle path. The fill rule is a per-`Shape` `winding: FillWinding` (`.evenOdd` default — nested contours become holes, a contour's direction doesn't matter — or `.nonZero`); `triangulatedFill()` maps it to `TESS_WINDING_ODD`/`TESS_WINDING_NONZERO`. **Font glyphs must be `.nonZero`** (the rule outlines are authored for): even-odd drops the region where a glyph's outline self-overlaps — e.g. the terminal of an `e`/`a`/`g`/`s` rendered as a flat *cut* (a real bug, fixed by giving glyph `Shape`s `.nonZero`), while simple glyphs (`o`, `l`) look the same either way. So `OutlineFont` builds glyph shapes `.nonZero`, and `Shape.mapPoints(_:)` (the point-transform helper used to place/warp glyphs — in `drawText(along:)`, `shifted`, the `OutlineText` warp) *preserves* `winding`; rebuilding a glyph via `Shape(contours:)` would silently reset it to even-odd and re-break the `e`. **A second glyph gotcha, distinct from winding: some system faces (San Francisco) build a glyph from *overlapping* sub-contours.** Even with `.nonZero`, the overlaps leave a faint hairline seam in the triangulated *fill* (visible inside the counters of `a`/`e`/`g`) and doubled edges in the *outline* (so a stroke, or dots sampled along the outline, double up where sub-contours cross). `OutlineFont.geometry(for:)` cleans each glyph with a Clipper2 union (`Shape.union` with an empty shape, normalizing it under nonzero) before triangulating, and feeds the **cleaned contours to both the fill and the returned outline** (so stroke/`textToShapes`/dots are clean too). Two load-bearing details: the union only merges cleanly when the curves are finely flattened, and **flatten density tracks the render size** (`CurveSampling`), so at small sizes the overlap stays coarse and the seam survives — so clean at a large **reference scale (1024)**, then scale the result to the render size; and that reference-scale flatten leaves the contours ~40× denser than the render size needs, which the per-frame stroke tessellation + fill bake then pay for *every frame* (a real 12→ fps regression), so **simplify** the cleaned contours back to a sub-pixel tolerance (Ramer–Douglas–Peucker, `OutlineFont.simplifyClosed`) before returning. All cached per `(glyph, size)`. (The niche `glyphRun` text-on-path/per-glyph path still flattens raw — a known follow-up.) libtess2 is bundled, not reimplemented — see the bundled-third-party-source tier in [Sourcing & attribution](#sourcing--attribution-load-bearing--its-the-public-face) (`External/CLibtess2`, SGI-B). Convex shapes (circle, rect, ellipse) and convex `drawPolygon` stay on the current fan/strip math; don't route them through the triangulator. **Strokes render through the AGG/NanoVG-style fringe expander** (`appendFringeStroke`, written from the technique — no SDF, no MSAA/SSAA). Every stroked path — `drawLine`, `drawBezier`, `drawPolyline`, the `drawPolygon` outline, and `drawShape` contours — is edge-expanded CPU-side into per-segment butt quads plus a **~1px screen-space anti-aliasing fringe** (`fw = 1/ctmScale`; coverage ramps 1→0 across it, GPU-interpolated so the edge stays smooth at *any* angle at native resolution — the staircase the SDF capsule's single-sample `fwidth` left on shallow diagonals). It rides its own `.fringe` `GeometryKind`/pipeline (`ollin_fringe_vertex`/`ollin_fringe_fragment`) but **reuses the triangle vertex buffer**: the coverage rides in an `aa` field tucked into `OllinVertex`'s existing float2→float4 alignment padding (stride stays 32, the triangle path byte-identical), with the stroke's rgb + paint alpha in `color`. The fragment remaps **only the coverage** through `perceptualCoverage` (thin lines stay dark in linear light) and keeps the **paint alpha linear** (translucent strokes composite at their true opacity — the two channels kept separate is *why* the `aa` field was needed). Solid, translucent, and gradient paint all take this path — gradient samples per path vertex like the tessellated path (`vertexPaint`: along-path reads arc length; long segments split first so the baked LUT tracks). The fringe **straddles** the true edge so perceived width = `strokeWidth` — geometry stays within snapshot tolerance of the old SDF/tessellated output, so **no snapshot re-record was needed**. **Joins/caps are honored** via per-join outer-gap fillers (`strokeJoin` `.miter` — beveling past the limit — / `.bevel` / `.round`; `strokeCap` `.butt`/`.round`/`.square` on open ends), so `drawLine` (single segment, cap-only — now default **butt**, not the old always-round capsule) and `drawBezier` (flattened → cap + joins) honor them too. `appendStrokedPath` (the old tessellated `appendSegment`/`appendArcFan` join-filler path) is **retained for text glyph stroking only**. **Fills stay on libtess2 + 8× MSAA, byte-identical** — the empirical call (native-res A/B): MSAA fill edges are already smooth, and a fill fringe would reintroduce abutting-fill seams (Voronoi/LifeQuilt) or fatten, so the fringe is **strokes-only**. Curved outlines (quadratic/cubic Bézier + Catmull-Rom `curve`) **sample to points** via the public `Path` builder (`Path.swift` — `move`/`line`/`curve`/`quadCurve`/`cubicCurve`/`close`, plus `Contour`/`Shape(curveThrough:)`), surfaced as the closure sugar `drawShape { p in … }` and the top-level `drawCurve(_:closed:)`. They feed the same triangulated fill + stroked path, so a curve never touches the SDF/renderer side — the `Contour`/`Shape` data stays polygonal, the `Path` just flattens curves into it.

## Build, run, verify

```sh
swift run Example-Basic-HelloCircle   # opens a window running an example
```

The canvas is `1080×1080` by default (`canvasSize`, the typed `CanvasSize` enum — `.square(n)` / `.size(w, h)` + named presets, integer pixels); the preview window is sized from the sketch's `windowMode` (`.auto` fits the screen, `.fixed`, or `.resizable`) — the window is a scaled view of the canvas, not the canvas itself.

- **Requires macOS 26+ and a Metal-capable GPU.**
- **`swift build --target Example-X` does not relink the executable.** It compiles the module and reports success, but `.build/debug/Example-X` stays the *old* binary — a tuning loop against it silently re-runs stale code (a real hour lost: three "tuning" rounds of VideoTrace all ran the first build). Rebuild runnable examples with `swift build --product Example-X` or just `swift run Example-X`; reserve `--target` for compile-checking libraries.
- **Check the environment before claiming you can't build.** Ollin needs the Swift toolchain and Metal, which exist on a Mac but *not* in the Linux web/iPhone container. These two run on different machines, so don't assume: if `swift --version` and `xcrun --find metal` succeed, you're on a Mac with the toolchain — **build, run, and verify directly** (`swift build`, `swift run <Example>`), and don't add caveats about being unable to compile. Only when that toolchain is genuinely absent (the Linux container) are changes unverifiable on this machine — say so then, and not before. Either way, the things that truly need a simulator or device (iOS/visionOS/AR) stay unverifiable here regardless.

Per-feature *user-facing* depth lives in the `Docs/` page named in each bullet; deeper *engineering internals* (the mechanism, the why, the measurements behind a shipped system) live in [`ARCHITECTURE.md`](ARCHITECTURE.md), so this section can keep a terse invariant + a pointer instead of swelling. A few load-bearing rules recur across the satellites, so they're stated once here instead of per-bullet:

- **Render-thread closures must be built non-isolated.** Any closure an audio / MIDI / Vision / capture render thread calls, if formed in a `@MainActor` context, inherits main-actor isolation and Swift injects an executor assertion that *SIGILLs* the instant that thread runs it — build it in a free function or a non-`@MainActor` type.
- **`resource:in:` can't default `in:` to `.module`** — a default arg resolves to *Ollin's* bundle, not the caller's; every font / image / mesh / model loader makes `in:` explicit.
- **Never replace a GPU texture in place** — an in-flight frame may still be reading the old one; allocate a fresh texture when the bytes change.
- **Satellites can't depend on each other** — a shared seam (`RGBDFrame`, `SegmentationImages`, `FrameSource`, `AudioTapSource`, the `OllinUSBMux` tunnel) lives in the `Ollin` core, often `package`-access.
- **Background-producer → main-reader handoff** is uniformly an `@unchecked Sendable` producer with an `OSAllocatedUnfairLock` handoff (audio analyzer, OSC/MIDI receivers, Vision analyzer, phone readers all share this shape).

- **SDF combinators** (`Sources/Ollin/Drawing/SDF.swift` + `Renderer/ShaderCombinator.metal`; 3D in `Sources/Ollin/Drawing/SDF3D.swift` + `Renderer/ShaderRaymarch.metal`). Compose signed-distance *fields* so shapes **merge** instead of stack — the field-combining axis the per-instance SDF primitive path can't express. The typed **`SDF`** value type (leaf circle/ellipse/rect/square/ngon/star/rhombus/ring/triangle + `.union`/`.smoothUnion(_:k:)`/`.subtract`/`.smoothSubtract`/`.intersect`/`.smoothIntersect`/`.morph`/the joint + detailing ops (the chamfer/stairs/columns trios (sels 7-15) + `engrave`/`groove`/`tongue`/`pipe` (16-19), hg_sdf, crisp nearer-side/body color, the second scalar (steps/count/width) riding the OP node's `extra`; columns keeps the reference's own band guard; detailing ops are value-type-only (morph precedent), columns gets block forms; they assume frankly-crossing surfaces — near-parallel faces within the radius echo the pattern, the documented envelope)/`.rounded`/`.onion`/`.at`/`.rotated`/`.scaled`/`.stretched`/`.colored`/`.mirrored`/`.repeated`/`.repeatedRadially`) draws via `drawSDF(_:)` honoring the current fill/stroke/CTM, the stroke tracing the *merged* outline; a scoped **block form** (`smoothUnion(k:){ drawCircle…; drawRect… }`, + the hard/mirror/repeat variants, and the stateful **`sculpt { }`** block whose `add()`/`carve()`/`blend(_:)` verbs mutate per-child mode/melt mid-block — the CombineFrame snapshots the state per captured child, a nested block lands under the state at its close, the verbs address the innermost *sculpt* frame through nested blocks, and each sculpt frame keeps its own state; built for the live-coding loop) is sugar — bare region draws are captured at `Drawer.appendSDF` as leaves, reaching **every** fillable region shape. **Rendering is an "SDF VM":** the value tree flattens (CPU) to a flat `SDFNode` program (own `SDFGroupInstance` + node buffer + `GeometryKind.sdfGroup` + `.sdfGroup` pipeline, *beside* the per-instance `SDFInstance` path — it can't ride it, that struct is full at 144) that `ollin_sdfgroup_fragment` walks per pixel with two fixed-depth stacks (cap 16: value (distance,color) + point/transform). Smooth ops use iq's polynomial smin whose blend factor **also lerps the operands' colors** (the melt look); hard ops min/max. **Load-bearing invariants:** **leaves carry no transform** (all positioning is XFORM nodes → method-chain order exact: `a.at(p).repeated()` tiles the moved shape, `a.repeated().at(p)` shifts the tiling); the leaf distance **`ollin_sdf_distance`** is **kept in sync by hand** with `ollin_sdf_fragment`'s switch (a new region shape goes in both; the per-shape fragment switch stays untouched so single-shape snapshots are byte-identical); **polar/radial repeat is the shared sel-5 XFORM** (2D fold around origin, 3D around an `axis`), the **single-evaluation** kind (wedge-symmetric content exact, else a seam); **region shapes only** (lines/open-arcs/Béziers skipped with a one-time log); a field past the caps (depth 16, ~256 nodes) is logged + skipped, never mis-drawn; the buffers thread all 9 `encode` sites. **2D gradient paint** (fill/stroke solid or linear/radial, sampled in **field space** at `in.field`; along-path falls back to solid; a solid-leaf field is byte-identical). **Per-axis sizing:** `stretched(x:y:[z:])` (iq `opElongate`, an **exact** SDF, the preferred tool) vs `scaled(x:y:[z:])` (true non-uniform, only a **conservative bound** — rescales by the **min** scale component for a safe Lipschitz march, so blends distort under strong anisotropy). The **raymarched 3D sibling** — **`SDF3D`** + **`drawSDF3D(_:)`** composes 3D fields (sphere/box/roundBox/torus/capsule/cylinder/cone/octahedron/ellipsoid/plane + the sculpting leaves line-between-points/hexPrism/pyramid/cappedTorus/link (tags 10-14; `line` is the one non-origin-centered leaf, its AABB from both endpoints) + the same ops, plus the sculpting distortions `.twisted`/`.bent` (XFORM sel 8/9) and `.displaced`/`.roughened` surface displacement (MOD sel 2/3) — every distortion/displacement is a distance *bound*, so flatten computes a conservative Lipschitz rescale from the child bounds (twist/bend on RESTORE_P) or amp·freq (displacement, in the MOD's geo0.x) that keeps the march hole-free) that **merge**, **sphere-traced** through the active camera and **depth-composited with the rasterized meshes** (a parallel path: own `SDFNode3D` + `SDF3DGroupInstance` + `GeometryKind.sdfGroup3D` + `.raymarch` pipeline). **Load-bearing:** the march runs in **world space** (each step maps the world point into the field's local frame via `inverseModel`) so the 4-tap gradient normal + written `[[depth(any)]]` come out world-space with no normal matrix; one **fullscreen triangle per field** bounded by its world AABB (a miss bails O(1)); shading **reuses `meshLitColor` unchanged**, **honors `material(_:)` per batch** (`ensureSDF3DBatch` records the finish + breaks the batch when it changes, like solid meshes — the generic `ensureBatch` records none, the bug that left field materials silently ignored), and **adds the same IBL ambient the mesh fragments add** (split-sum for a PBR finish — including the traced-reflection swap under `rtReflections`, bound the same accel/flat-mesh/offsets way — flat irradiance for standard/toon, Gooch none; gated on `iblEnabled` → byte-identical with no environment; `resolveFieldLighting` carries the same IBL setup + `rtReflections` flag, so the half-res tiers light identically). The **infinite plane** (`SDF3D.plane(normal:offset:)`) is the one *unbounded* leaf (flattener marks the field `unbounded`, propagated through combine; marches the near..far span; value-type-only). All byte-identical when off. **Perf (load-bearing):** the point-light cast is per-receiver-pixel (a screen-filling floor is GPU-heavy), trimmed by a conservative AABB early-out + a **half-res field-shadow pass** on the `resolveRaymarchScale` dial; export skips the pre-pass (full-res, byte-identical snapshots). **Quality dial — `raymarchQuality`/`raymarchResolution`:** a field's cost is **bound to pixel count, not step count**, so the dial scales internal **resolution** (`.detail` full / `.default` half / `.performance` quarter) via a reduced-res pre-pass (point-sampled depth keeps the silhouette crisp); the fraction is a **coverage-adaptive budget, not a fixed downscale** (`min(1, fraction/√coverage)` over the fields' projected-AABB screen coverage — a dollied-out field traces at full res and the pre-pass skips itself, the zoom-out-blur fix; grow-only targets + a viewport subrect so a dolly never reallocates; the pre-pass AA cone sizes by the *internal* pixel via `Uniforms3D.raymarchScale`, scale 1 bit-identical); the automatic tier is **live-preview only** (export resolves `.detail`, marches full-res → default-tier snapshots byte-identical; an *explicit* fraction/tier is honored on export, adaptively). - **User-supplied shaders** (`Sources/Ollin/Effects/Shader.swift` + the wrapper/compile/error path in `MetalRenderer`). A sketch writes its own fragment shader and runs it through the effect graph. The contract is **Ollin-native, not raw Metal**: the user defines `float4 shade(float2 uv, ShaderInfo info)` (uv 0…1 top-left, return straight sRGB) and Ollin generates the surrounding fragment + a fullscreen `ollin_user_vertex`. The **`Shader`** value type (Sendable; inline `String` *or* `resource:in:` read eagerly at construction to dodge the bundle + render-thread gotchas) carries the source, `params` ([Float], up to 32, read via the `param(info, i)` macro, packed into a `float4` buffer at index 0), and a **`Modules`** opt-in set. Routing **reuses the effect-graph enums** — a `.shader(Shader)` case on `Generator`/`Filter`/`Combine.Kind` — so input count *is* the variant: `generate(.shader(s))` (0 inputs, generator), `layer.filtered(.shader(s))` (1, `sample(info, uv)`), `a.combined(with: b, .shader(s))` (2, + `sampleAux(info, uv)`); all three resolve through the existing `encodeGenerator`/`applyFilter`/`applyCombine` with no new render-graph plumbing. **Compile model mirrors the compute path:** each shader is its **own** `device.makeLibrary(source:)` (the `OllinShaderLib` segment + the variant wrapper + the user source), cached by `fnv1a(composed)` → `MTLLibrary` → `MTLRenderPipelineState` (`userShader*` caches), so it compiles **once**, not per frame; a *failed* compile is cached too (`userShaderErrors`) so a broken shader doesn't retry every frame, and all three caches clear on a framework-shader reload. `ShaderInfo` is built per frame from `frameComputeUniforms` (snapshotted from `drawer.computeUniforms` at the top of `encodeEffectTargets`, so the filter/combine call sites need no `drawer`). The bound uniform struct is **`OllinShaderUniforms`** (scalars only — no array — so Swift fills it with the plain memberwise init; user params ride the separate `float4` buffer). The **input layer(s) ride inside the wrapper's `ShaderInfo`** as `texture2d<float>` + `sampler` members (valid MSL: passed by value to `shade`; verified on Metal), read back as **straight sRGB** (`ollin_layer_sample` un-premultiplies + `linearToSrgb`) so the shader works in one color space. **Friendly errors are the headline:** `Shader.init` captures its call site (`#filePath`/`#line` default args) and the wrapper emits `#line <startLine> "<file>"` before the user source, so Metal reports diagnostics at the **real, IDE-clickable** location — the sketch's own `.swift` for an inline string (a multiline literal's content starts at `line + 1`; a no-newline string sits on the call line, so a one-content-line literal reads one off — accepted, `ShaderErrorTests` pins the semantics), the `.metal` file itself for a resource (line 1); `cleanShaderDiagnostics` strips the `Compilation failed:` header + `program_source:`-rebases to the same `file:line` as a fallback + drops compiler-internal `note:` lines that point at `/System/` framework headers (a line naming the user's file is always kept). The location rides the composed-source hash, so identical shaders at two call sites cache separately (fine — same-site rebuilds like `Visual` still hit). The error surfaces two ways: **stderr** (once per source hash, for a plain `swift run`) and a **pull-model channel** to the host — the renderer holds `currentUserShaderError` (reset each frame, set on failure), `SketchRunner` reads it after `render()` on the main thread and forwards via `onUserShaderError` (deduped), and `LiveSession` maps it to its `shaderError` → the existing `CompileErrorState` overlay (so a shader error and a Swift compile error don't clear each other; `reloadShaders`'s framework-shader gap is closed the same way). The **`OllinShaderLib`** helper segment (color/hash/noise/sdf/domain + `palette`/OKLab, plus the once-compute-only `curlNoise`/`discSample`/3D `valueNoise`/1-out hashes folded into its hash/noise sections) is **one source of truth, used three ways**: the framework's own segments build on it, it splices into every user shader, *and* `composeComputeSource` splices the whole of it into every compute kernel (the separate compute prelude is gone — one helper set, `hashNM` names, everywhere); `using: [.noise, .sdf]` keeps only marked sections (`// OLLIN_LIB_BEGIN/END <module>`, `noise→hash` dependency resolved) — GPU-free (DCE), a *compile-time* lever, default `.all`. **Hot-reload** covers both forms in OllinLive: an inline-string shader reloads with the sketch (a `.swift` edit), and a `.metal` *resource* shader reloads on its own — the `Shader(resource:in:)` reads **lazily** (it stores the bundle-resolved path, not the content; `Bundle.module` resolves to the sketch dir under OllinLive too), the renderer reads + caches the file, and a watched-`.metal` change routes through `LiveSession.handle` to `SketchRunner.invalidateUserShaders()` (clears the source/library/pipeline caches; forces one frame if `noLoop`), so the next frame re-reads and recompiles with **no swiftc pass** (verified end-to-end: edit → reload, break → line-accurate overlay error, fix → recover). A framework-segment `.metal` (under the repo's `Renderer` dir) still routes to the full library reload; the dispatch tells them apart by path. The **2D `sd*` distance functions** (the iq catalog: `sdEllipse`/`sdRoundBox`/`sdSegment`/`sdStar`/`sdHeart`/`sdBezier`/… + the `dot2`/`ndot` helpers they share) live in `OllinShaderLib`'s `sdf` section too, **moved verbatim out of `ShaderShapes`** (the block was self-contained — its `dot2`/`ndot` defined and used only within it — so the framework lib still resolves them, all 65 snapshots byte-identical) so the framework's own shapes and user shaders share one copy; `ollin_sdf_distance` + the fragment switch in `ShaderShapes` still *call* them. Examples `Shaders/HelloShader` (a Toby-Howard-homage plasma generator), `Shaders/ShaderFilter` (wave + posterize filter), `Shaders/ShaderBlend` (two-layer combine), `Shaders/ShaderFile` (a `.metal`-resource shader, the hot-reload demo); snapshot `user-shader`. `Docs/Shaders/Shaders.md` + the per-function `Docs/Shaders/ShaderLibrary.md` reference.

- **Visual chains** (`Sources/Ollin/Effects/Visual.swift` + the `visual` section of `OllinShaderLib.metal`). The fluent composition tier over the effect substrate: **`Visual`** is a value type (struct over an `indirect enum Node`, the `SDF` shape) recording a chain of per-pixel ops in five families — sources (`.oscillator`/`.noise`/`.voronoi`/`.shape`/`.gradient`/`.solid`/`.layer`), coordinate warps (`.rotated`/`.scaled`/`.pixelated`/`.repeated`/`.kaleidoscope`/`.scrolled`), color adjustments (`.brightness`/`.contrast`/`.saturation`/`.inverted`/`.posterized`/`.thresholded`/`.luma`/`.hueShifted`/`.tinted`/`.colorCycled`/`.channel`), combines (`.blended(with:_:amount:)` over the typed `BlendMode`, `.mixed`/`.differenced`/`.masked`), and modulations (driver overloads of the warps: `.displaced(by:)`, `.rotated(by:)`, `.scaled(by:)`, `.pixelated(by:)`, `.kaleidoscope(by:)` — one chain's color perturbs another's sampling coordinate). `compile()` walks the tree once and emits a `shade(uv, info)` body over `ollin_vis_*` library functions; the whole chain (drivers included) is **one fragment shader, one pass**, run through the user-shader path (`Shader` + the compile-once source-hash cache). **Load-bearing:** the generated source depends on the chain's *structure only* — every numeric argument becomes a params-buffer slot in traversal order (`VisualTests` pins this), so a chain rebuilt each `draw()` hits the cached pipeline and animated values/`@Param` knobs never recompile (structural selectors — blend mode, channel — are spelled as literals *by design*); the params buffer is **16 rows / 64 floats** (`OLLIN_SHADER_PARAM_ROWS`, raised from 8 — `paddedParams` and the wrapper both read the macro), overflow bakes literals with a one-time note; the codegen's fresh-variable counter **starts at 1** (`st0` is the root the body declares — 0 collides); `.layer` leaves dedupe by target identity and cap at the wrapper's **2 textures** (routing by count: 0 → `generate`, 1 → `.filtered`, 2 → `.combined`; extras sample black + one-time note); `.layer(_ feedback:)` reads the previous frame (video feedback); `BlendMode.visualIndex` is kept in step with `ollin_vis_blend`'s switch; ops aspect-correct *inside* the function (coordinates stay 0…1 so `fract` wraps compose), colors are straight sRGB per the user-shader contract, and `.noise` is signed so displacement wobbles about zero; `Modules.visual` splices the ops into every user shader (dependency `visual → hash+noise` in `filterLibModules`). Example `Shaders/VisualSynth`; snapshot `visual-chain` (all five families + a layer read); `Docs/Shaders/Visuals.md` + the module's function table in `Docs/Shaders/ShaderLibrary.md`.

- **Layered effects** (the substrate; `Sources/Ollin/Effects/`). Draw into off-screen layers, filter them on the GPU, composite back with blend modes (the OPENRNDR `RenderTarget`/`Filter`/`compose` model): `renderTarget(scale:)` → an off-screen `rgba16Float` `RenderTarget`; `withTarget(_:) {}` redirects drawing into it (scoped like `withState`; `background(_:)` inside clears *that* layer); `target.image` composites it back; `target.filtered(_:)` → a new layer; `postProcess(_:)` filters the whole frame. **`Filter`** is a ~55-entry catalog in six families — blur/glow, color/tone, stylize/optical (incl. the thin-film `.iridescence` sheen, hash-cell `.glitter` sparkle, per-shape via `compose`/`layer{}.post`, the `.relight` height-map material pass (matte/metal/glass/sand/liquid finishes over a uv-normalized Sobel normal — the gradient must be uv-scaled or high-res relief flattens), and the two-tone `.dither(dark:light:)`), retro, uv-warp distortion (the radial warps take a `center:` in layer fractions, byte-identical at the 0.5 default), and the **design filters** (`.flutedGlass`/`.water`/`.paperTexture` transform the layer; `.liquidMetal`/`.heatmap`/`.gemSmoke` read its **alpha shape** — draw a shape, filter it: liquid metal + gem smoke consume a true interior-inflation field solved per frame as coarse-to-fine Jacobi fragment passes (`poissonInteriorField` — smooth AND boundary-exact; a blur leaks across concavities, an EDT creases at the medial axis), heatmap a Gaussian halo prep, `blurredAlphaFields`, matching its blur-based reference) (full per-filter list in `Docs/Drawing/Effects.md`); new built-ins are written from the published technique, credited in `ATTRIBUTION.md`, never in `.swift`. **`Generator`** + `generate(_:)` fills a procedural pattern into a target: the four basics (`.checkers`/`.gridLines`/`.bars`/`.noise`) plus the **design-pattern set** (`.meshGradient`/`.filaments`/`.smokeRing`/`.colorPanels`/`.spiral`/`.waves`/`.dotOrbit`/`.grainGradient`/`.pulsingBorder`/`.godRays`, in `ShaderPatterns.metal` — cross-read against Paper Shaders (Apache-2.0), written from the canonical techniques, per-technique credits in `ATTRIBUTION.md`) and the **pattern fields** (`.quasicrystal`/`.moire`/`.gyroid`/`.phyllotaxis`/`.hexPulse` — closed-form animated fields, same conventions, sharing `ollin_pat_ramp`) and **escape-time fractals** (`.mandelbrot`/`.julia`, smooth iteration count through a cosine palette fold); `generate(_:width:height:)` fills an explicit-size layer (patterns compose per-layer, so tiles aren't squashed full-canvas fills; the Shader and Visual `generate` forms have the same explicit-size overloads). Design-pattern invariants: animation is an explicit `phase` param (feed `time` — deterministic export/snapshots, no hidden clock); palettes ride as trailing float4 rows after the scalar rows; and the fragments blend palettes + composite **internally in sRGB** (`ollin_pat_stop`/`ollin_pat_out`), converting to premultiplied linear only on output — designer palettes mixed in linear read washed-out pastel (a real bug), and the mesh-gradient IDW especially depends on this. **Feedback** — `feedback(scale:)` → a *persistent* `Feedback` layer (made once in `setup()` and held — its identity carries the ping-pong state across frames) + `withFeedback(_:) { prev in … }`. **Simulation fields** — `simField(_:scale:)` → a persistent `SimField` running a `Sim` (`.reactionDiffusion(feed:kill:)` Gray-Scott / `.gameOfLife` Conway / `.fluid(...)` real-time fluid) that you seed/force by drawing into it (`withField(_:_:)`, `force:`); `SimField.image` is the raw state, `.filtered(_:)` recolors it through the `Filter` catalog. **Depth-capturing targets** — a target a 3D scene is drawn into resolves a sampleable depth buffer; `target.depth` exposes it as a gray layer (0 near … 1 far) that feeds `.defocus` for 3D depth-of-field (set the camera `near`/`far` to bracket the scene); two-tier opt-in so *2D never pays* (`needsDepth` only when 3D is recorded; the resolve+normalize only when `.depth` is read; particles in a target still skip). **Compose DSL** (`Effects/Compose.swift`) — `compose { layer { … }.post(_:).blend(_:).scale(_:) … }`, composited bottom-to-top in declared order; pure sugar over the substrate. **Multi-input combine** (`Effects/Combine.swift`) — `base.combined(with: aux, op)` with six ops: `.mask` / `.displace` / `.mix` / `.defocus` (near/far-separated bokeh-gather depth of field; artifact history in [[ollin-depth-of-field-gather-artifacts]]) / `.ambientOcclusion` (SSAO over depth + the mesh-normal G-buffer) / `.screenSpaceReflections` (SSR: trace → resolve → temporal → composite); `aside { }` + `.masked(by:)` / `.displaced(by:amount:)` / `.mixed(with:amount:)` / `.defocused(by:)` is the combine's `compose` sugar. **Load-bearing invariants (terse — mechanism and why in [`ARCHITECTURE.md`](ARCHITECTURE.md) § *Layered-effects substrate* + § *Screen-space combine effects*):** the `Drawer` stays a pure recorder and the renderer resolves the deferred graph at `render()`/`image(of:)` time, entirely GPU-resident (layers are attachments, filter inputs sampler binds, never a CPU round-trip), premultiplied linear, the no-targets path byte-identical; every `GeometryBatch` begin snapshots **all** the `*Start` offsets (omitting one zeroes a *preceding* batch's count — the `SceneDefocus` bug); `withTarget`/`withFeedback`/`withField` push/pop the drawing state around the block (the documented `withState`-like scoping — a `blendMode` set inside a layer block must never leak to the canvas; fluid keeps its own `fluidSlots` (velocity + dye pairs) beside `FeedbackSlot` so the single-field sims stay byte-identical; `layer(_:)`'s draw closure is `@escaping @_implicitSelfCapture` (without it, bare draw calls inside `layer { }` need `self.` and the p5 feel breaks); SSAO's stabilizers (dense Fibonacci hemisphere kernel with no per-pixel rotation, continuous Duff basis, depth-aware MSAA normal resolve, 7×7 depth-aware blur, **no** G-buffer Y-flip) and SSR's (McGuire-Mara adaptive stride, depth-interval crossing + back-face rejection, the half-stride march start + 4-step floor — never anchor the first interval on the receiver's own depth, and never leave a sub-2px-span ray a single coarse interval — dense never-strided resolve kernel, `SSRHistorySlot` keyed by the op's call site, not a frame-wide ordinal) each fixed a worse artifact — don't undo ([[ollin-ssao-normal-gbuffer-followup]], [[research-before-implementing]], [[verify-perceptual-temporal-fixes]]); The ~42 auto-orbit `3D/*` examples call it; `3D/CameraControl` (pure manual) + `3D/CameraMoves` (the move catalog) stay as the lower-level demos; snapshot `camera-move` (a deterministic `.turntable` at a fixed frame — the input-driven paths are covered by the `CameraRigTests` / `TimelineTests` CPU units instead, since a snapshot can't drive synthetic events). **Scene inspection views** snap the rig to canonical angles — `cameraView(_:)` / `resetCamera()` (`CameraView`: `.reset` restores the opening framing — target + radius + angle; the six axis views swing only the orbit angle keeping the current target + radius; `.isometric` (`.corner` is the deprecated alias) is true isometric, `asin(1/√3)` up at 45° around), gliding by default (`animated: false` cuts) and on completion handing the pose back to the active driver via `CameraRig.driver` (control resyncs its goal, move re-bases, showcase holds then idle-returns), so motion resumes from the snapped pose with no jump. **Byte-identical when no snap is active** (`applyViewSnap` early-returns; the `.driver` set is inert), so `camera-move` wasn't re-recorded. Both are host chrome like the FPS overlay — **never exported, 2D no-op**, read live each frame or toggled from the **Camera menu** (Show Axis / Show Ground Grid). **Load-bearing grid invariant:** the infinite-grid LOD (Golus technique, reimplemented) divides the **once-computed base world-uv derivative** by each decade-spaced scale — **never `dfdx()` of a pre-scaled uv** (`cellA` jumps a decade across adjacent pixels at a LOD boundary → derivative spike → the lines shatter into a crawling dotted band, a real fixed bug); "major" (every-10th) lines are distinguished **by width in the one line color** — not a brighter color and not a separate per-class fade — so every scale fades by the same rule (its line thinning below a pixel, `covA + max(covB, covC)`) and the levels converge and fall off together toward the horizon under a single uniform radial fade. A brighter, separately-faded major (the old form) made the levels vanish at staggered depths and read as stacked planes at different heights — don't reintroduce it. Example `3D/SceneViews`; snap math + hand-back in `CameraRigTests`. Full mechanism in [`ARCHITECTURE.md`](ARCHITECTURE.md). `Docs/3D/Camera.md`, `Docs/Helpers/Animation.md` (the `Timeline` section).

- **RGBD recordings + live USB (Record3D)** (`OllinRecord3D` satellite). `Record3DRecording` opens a Record3D `.r3d` clip and `Record3DDevice` reads a tethered phone's live USB RGBD stream — both unproject color + depth with true intrinsics into a `PointCloud` (over the core `RGBDFrame` / `CameraIntrinsics`). ## Live reload — edit code, see it render (shipped via `OllinLive`)

The headline creative-coding feature, and it's built. `swift run OllinLive <path/to/Sketch.swift>` opens a window, watches the file, and on save recompiles *just that sketch* into a `.dylib` and hot-swaps it into the running loop — the window never closes. This is the Olive / canvas-sketch model (a persistent host owns the window; the sketch is the swappable unit), chosen over InjectionIII because that needs an external app and is finicky on the terminal `swift run` workflow Ollin lives in. Code is in `Sources/OllinLive/` (`main`, `FileWatcher`, `LiveSession`, plus `--selftest`/`--watchtest` headless smoke tests); the reusable loader `SketchLoader` lives in the **`OllinRuntime`** library (a small target shared with the examples gallery, kept *out* of the shipping `Ollin` framework so it stays free of dev-only tooling); the runner-side swap is `SketchRunner.reload(to:)` in `SketchView.swift`.

How it works, and the load-bearing decisions (most are cheap-to-forget, expensive-to-rediscover):

- **Host + swappable sketch dylib.** OllinLive is a SwiftUI `App`: its `WindowGroup` hosts a `SketchView`, which hands back the `SketchRunner` through its `onRunner` callback; the file watcher then drives `SketchRunner.reload(to:)`. `SketchRunner.sketch` is a `var`; the loop already calls `sketch.performDraw()` through the instance, so swapping the var means the next frame runs new code.
- **`-undefined dynamic_lookup`, not a dynamic Ollin product.** The sketch dylib compiles with `-I` pointing at the dirs that hold `Ollin.swiftmodule` and the C targets' module maps (to type-check `import Ollin`) and `-undefined dynamic_lookup` with *no* `-lOllin`; the host links `-Xlinker -export_dynamic` so the dylib's Ollin symbols resolve against the host at `dlopen`. Those `-I` dirs are **discovered, not assumed** (`SketchLoader.moduleSearchPaths`): the classic SwiftPM build puts them next to the executable (`<bin>/Modules`, `<bin>/<C>.build`), but the Xcode/Swift build system puts `Ollin.swiftmodule` directly in `<bin>` and the C maps under `.build/index-build/<triple>/debug`, so a `<bin>/Modules`-only assumption fails with "no such module 'Ollin'" (it did; the `--selftest` harness exercises exactly this). A third source sits outside the build tree: a vendored C target with a *checked-in* module map (`External/<T>/include/module.modulemap` — CBox2D, CSyphon) never lands under a `*.build` dir, so the loader also collects those `include/` dirs from the package root — without them a loose sketch can't `import OllinPhysics` (its swiftmodule needs the clang module even though the import is `internal import`). One copy of `Sketch`, so the loaded object casts as `Ollin.Sketch`. **A `.dynamic` Ollin product does not fix this** — SwiftPM still links the target statically into the executable, giving two copies and a failed cast (verified the hard way). Each load uses a unique `-module-name` so repeated reloads of the same class don't collide in the objc runtime.
- **A generated factory shim.** The loader regexes the `class …: Sketch` name and compiles a sibling `@_cdecl("ollin_make_sketch")` file alongside the user's source, so the user file is untouched and its `@main` is harmless (it compiles fine under `-emit-library`).
- **FSEvents on the *directory*.** Editors save atomically (temp file + rename), which breaks fd-based watches; `FileWatcher` watches directories with `kFSEventStreamCreateFlagUseCFTypes | …FileEvents` (the UseCFTypes flag is required or the path-array cast crashes), debounced ~150ms. It dispatches by extension: `.swift` → recompile + swap; `.metal` → `MetalRenderer.reloadLibrary(source:)` (live shader reload, active only when run from the repo); image assets → re-run `setup()` (a forward hook; image *loading* isn't a feature yet).
- **Resilience + threading.** Recompile runs off the main thread (the window keeps drawing the old sketch); the swap is marshaled to the main queue. A compile error is printed and the running sketch is left alone — a typo never closes the window. `MetalRenderer.reloadLibrary` builds the new pipelines before committing, so a bad shader edit can't blank the renderer.
- **State on reload: fresh restart by default; `--keep-clock` to continue.** `reload(to:keepClock:)` re-instantiates and re-runs `setup()`; by default it resets `time`/`frameCount`, and `--keep-clock` carries them forward (offsets `startTime` so `time` continues, copies `frameCount`) so an animation's phase doesn't jump. Either way instance state resets (fresh instance). `Sketch.onReload()` (lifecycle hook) fires once after the post-reload setup (never on first launch). Matches Olive/canvas-sketch.
- **Keep `Sketch`/`draw()` `open`** (already true) — the dylib subclass must override them; never `final`.

Window title: `"Ollin - <SketchName>"` (plain hyphen, not a middot). @eaviles ruled out FPS-in-the-title (the oF idiom); live FPS lives in the hosts' inspector surfaces (the OllinLive and gallery sidebars; standalone, the detached ⌘/ panel), not the title bar.

**GUI / parameter knobs — shipped, typed.** The generic `@Param` wrapper/registry in the `Ollin` core (`Param.swift`) drives the shared inspector (`Inspector.swift`) in all three hosts; **the control follows the property's type** — `Double` → slider (optional `step:` snaps every write; `style: .field` drops the track for a scrub/type-only field), `Int` → stepper, `Bool` → toggle, a `ParamOption` enum → menu (keyed on case *names* for persistence; Ollin's own CaseIterable mode enums — `BlendMode` / `StrokeCap` / `StrokeJoin` / `Colormap` — conform out of the box), `Color` → color well, `Vector2` → paired x/y fields (`style: .pad` adds a drag pad mapped top-left = both lower bounds, the canvas origin), `Vector3` → an x/y/z field line, `Rectangle` → x/y + w/h field lines, `Insets` → t/r + b/l field lines, `ClosedRange<Double>` → a **two-thumb slider** + ordered min/max pair by default (`style: .field` drops the track; a min dragged past the max pushes it along; the grabbed thumb is held for the whole gesture), `String` → a text field, plus `style: .segmented` on the option kinds (ViewThatFits: inline beside a `.fixedSize()`-pinned label, else wrapped full-width — an un-pinned truncatable label makes ViewThatFits never wrap, and ViewThatFits *centers* a narrower child, so the wrapped block needs `maxWidth alignment: .leading`), and a **`ParamChoices`** named-catalog type → menu (needs `Equatable` to find the current selection — why `Easing`, a closure wrapper, and the parameterized `Material` finishes stay out; `LightingPreset` conforms) — through the type-erased `AnyParam` / `ParamControl` surface (typed get/set closures per control kind), so hosts never touch `Param<Value>` directly; `ParamValue` is public, so a user type can conform by mapping onto an existing control kind (no custom rows). `icon:` / `group:` on every init put an SF Symbol on the row and split the list into titled group cards (declaration order; ungrouped first). **Numeric value boxes scrub**: drag to change (Option fine, Shift coarse), click to type — gotcha: any Text sharing the pill's HStack must be `.fixedSize()`, or the paired-pill (Vector2) row compresses it to zero width and it silently vanishes (a real bug; the ∅-sentinel probe found it). Knob values persist across reloads as `ParamStored` payloads (`SketchSession.recordParam` / `syncParams`; a property that changed *type* in the edit drops its stale value so the new default wins). OSC/MIDI bind to `Param<Double>`; smoothing stays Double-only. Headless gates: `OllinLive --paramtest` (the typed family end-to-end) + `ParamTests`. Ties to the extension/lifecycle seam.

**Performance stats — a shared `FrameStats` feeding every host surface.** The runner (`SketchRunner`) fills one `FrameStats` (`@Observable`: fps, CPU frame time, vertex/SDF draw counts, clock, canvas size) a few times a second via the built-in `StatsExtension` on the extend seam. Three surfaces read it: the OllinLive sidebar inspector, the gallery's right-sidebar inspector, and — standalone `swift run` — a detached frosted `NSPanel` (`StatsPanel.swift`; `View ▸ Show Inspector`, ⌘/ via `OllinHUDCommands`, bound to `@AppStorage(OllinHUD.showStatsKey)`). A host with its own inspector sidebar opts the panel off (`SketchView(showsInspectorPanel: false)`) and omits `OllinHUDCommands` — its ⌘/ toggles the sidebar instead. Stats are *debug chrome, not in-canvas drawing*: SwiftUI siblings of the Metal view, so they never land in exports. Two gotchas the build proved: the CPU-ms must time `performDraw()` *alone* — timing across `renderer.render()` includes the triple-buffer semaphore (vsync) wait and pins it to ~1/fps, telling you nothing; and an on-canvas element's corner inset must be `.padding` *before* the canvas-filling `.frame`, or the padded box overflows and clips. `SketchView` is a SwiftUI `View` that `ZStack`s host chrome (the axis widget, the keyboard-focus hint) over a private `MetalCanvas` — the `NSViewRepresentable` MTKView, still the AppKit/UIKit-portability seam.

**Live coding — the performance host (shipped via `OllinLiveCoding`).** `swift run OllinLiveCoding [Sketch.swift]` (release wrapper `Scripts/OllinLiveCoding`) is the on-stage instrument: one window, the sketch letterboxed on a black stage, the code over it as translucent text (per-glyph backdrop strips, not a panel), ⌘↩ compiles the editor buffer and hot-swaps mid-motion (`keepClock` **on by default**; ⌘⇧↩ evaluates fresh), ⌘S is the only thing that writes the `.swift` (evaluate never saves; a crash-recovery autosave rides every evaluation). Load-bearing invariants, cheap to forget:

- **The shared engine lives in `OllinRuntime.SketchSession`** (supersede-cancel compile scheduling, `syncParams` re-applied *before* the swap so knobs never snap, the two-channel Swift-vs-shader error model where neither clears the other); `LiveSession` and `PerformanceSession` are thin wrappers over it — orchestration changes go in `SketchSession`, never re-forked per host.
- **Buffer compiles** (`SketchLoader.Input.source`) write the text into the per-compile work dir *under the sketch's own file name*: diagnostics carry exact buffer lines and the same file name (`CompileDiagnostic.parse` + match by `fileName` — never by path, it's the temp copy), while the factory shim's `Bundle.module` keeps pointing at the sketch's *real* folder so co-located assets resolve. An untitled buffer compiles as a stand-in path under Application Support; save first if the sketch needs assets.
- **`SketchRunner.reload(to:)` honors the *new* sketch's declared `canvasSize`** for non-`.resizable` modes (so an edited resolution takes effect on the swap; a fixed window never delivers the drawable resize that used to be the only trigger); `.resizable` still carries the live view size.
- **Letterbox at the SwiftUI layer only** (`.aspectRatio(_, contentMode: .fit)` around `SketchView`): the canvas view stretches to its frame and maps the mouse by bounds, so the aspect-fit frame is what keeps rendering *and* mouse coordinates exact.
- **No `.windowResizability(.contentSize)` here** (unlike the sibling hosts): fullscreen is the projection mode (`.fullScreenPrimary` via `WindowCustomizer`), the stage flexes, and status/error UI are *stage overlays* (chip, evaluated toast, diagnostics strip) because fullscreen hides the title bar. The error strip never dims the stage — the last good sketch keeps playing through a typo.
- **Editor rules:** the `NSTextView` owns the buffer (never mirror it into SwiftUI state); hide-code (⌃⇧H) is `.opacity` + hit-testing, never a structural `if` (that destroys the buffer and undo stack); every automatic substitution is off (a smart quote is a silent compile break); `keyboardFocus: .onClick` so the editor keeps the keys, and a canvas click intentionally hands them to the sketch.
- **Recovery is scoped to its document** (`recovery-origin` beside `recovery.swift`): an untitled buffer's net must never offer itself over an opened file (a real early miss — restoring replaced an opened sketch with old untitled work).
- Headless gates: `--selftest` (buffer compile → render → edit → differ, plus line-accurate diagnostic parsing; asserts the buffer path never writes the file) and `--sessiontest` (param carry, edited defaults, supersede semantics — the extraction's regression net for both hosts).

## Roadmap & design notes

Planned, in-progress, and eventual work is documented outside this file so the always-loaded guidance stays small:

Remove it from `DESIGN-NOTES.md` too, unless its design rationale still guides future maintenance or evolution (e.g. the conventions for extending the examples set), in which case keep only that part, not the status narration. (The `drawTriangle` commit got this wrong: it rewrote the catalog bullet to announce the triangle "has landed" instead of silently dropping it — the exact narration this rule forbids.) The ship checklist, every time something lands: **(1)** add it to *Current state* in this file; **(2)** remove it from `ROADMAP.md` (drop the entry; for an umbrella, the sub-entry only) with no "landed" note — and the README's Roadmap section is a short pointer with a one-line "what's ahead" list, so drop the item there too if it's named; **(3)** strip it from `DESIGN-NOTES.md`, keeping only rationale that still guides future work; **(4)** if it adds user-facing API, give it a `Docs/` page *and* wire it into both indexes (`Docs/README.md` and the README docs list) in the *same* commit — a commit that introduces a public concept but leaves `Docs/` untouched is missing its page; purely internal changes (a refactor, a renderer tweak) skip this and live only in *Current state*; **(5)** if it adds a user-facing capability, give it a row in the Guide's feature-coverage matrix (`Guide/PLAN.md`), naming its chapter home — and clear its parking-lot entry there if it had one. Do all of this only once the work is actually verified (built and run) — don't pre-narrate unbuilt work as shipped.

The convention: the root holds project meta and contributor docs (`README.md`, `ROADMAP.md`, `DESIGN-NOTES.md`, [`ARCHITECTURE.md`](ARCHITECTURE.md), `AGENTS.md`, this file, `LICENSE`, `ATTRIBUTION.md`, `THIRD-PARTY-NOTICES.md`), while [`Docs/`](Docs/) is the user-facing API reference (`Sketch`, `Drawing`, `Color`, …) plus `Docs/Tools/` for the user-facing host-app guides (live coding) — and nothing else. The third doc tree is [`Guide/`](Guide/), the narrative book: a practical creative-coding guide taught through Ollin, written chapter-by-chapter across sessions. Its authoring charter is `Guide/AUTHORING.md`, its chapter queue + briefs + feature-coverage matrix `Guide/PLAN.md`, its figures rendered/verified by `Scripts/guide-figures.sh` — guide facts route there, not here. `ARCHITECTURE.md` is the contributor-facing engineering-internals doc (the *how* and *why* of shipped systems, the home for depth that would otherwise bloat this file); `DESIGN-NOTES.md`/`ROADMAP.md` stay forward-looking, `Docs/` stays user-facing, so `ARCHITECTURE.md` is the one place shipped internals belong. Keep these at the root (don't fold them into a `Notes/`-style folder): several are auto-discovered or front-page (`README`/`LICENSE`/`CLAUDE.md`/`AGENTS.md`), and `ARCHITECTURE.md` wants root-level discoverability by convention.
