# Ollin — guidance for development

Ollin is a creative-coding framework for Swift + Metal (macOS). This file captures the design intent so work here stays coherent across sessions.

## Vision

**p5.js ergonomics on an OPENRNDR-grade core, with motion as the default.**

- The API people *type* should feel like p5: `setup()`/`draw()`, bare calls like `background(.white)`, `stroke(.black)`, `drawCircle(x, y, radius)`. That familiarity is the point — don't sacrifice it.
- The architecture they *grow into* should feel like OPENRNDR: typed value objects, an explicit `Drawer`, and composable geometry.
- `draw()` runs continuously at the display refresh rate. Animation is not opt-in — `radius: 120 + sin(time) * 40` just moves. `noLoop()` is the rare still-image escape hatch.

## Scope — a framework, not an editor (load-bearing)

Ollin is a *framework* — a library of creative-coding techniques you call from `draw()` — not an *application* you open instead of writing a sketch. The framing that keeps this honest: Ollin is a curated **collection of creative-coding recipes/techniques exposed as a coherent Swift API**, so depth is always welcome *as more recipes a sketch can call*, never as application surfaces that replace writing the sketch. The test for a feature: is it a *capability a sketch calls*, or an *application surface that owns the workflow*? The first grows without bound and Ollin stays a framework; the second is the drift to resist — a full 3D editor, a DAW, a video NLE, a node-graph studio.

**Richer experiences live in host apps built *on top of* the framework, not in the core.** `OllinLive` (dev hot-reload), `OllinExamples` (the gallery), and `OllinLiveCoding` (the live-coding / live-performance instrument) are apps that *consume* Ollin — the same tier, and the right home for performance- or editor-*shaped* features. **Live coding and live performance are first-class use cases** Ollin aims to serve, through that app layer. Three rules keep the apps from dragging the core out of lane: the framework stays fully usable on its own; the `.swift` **sketch is always the artifact and the source of truth**; and any tool is a *lens on that source* (round-trips to `.swift`), never a proprietary document only the GUI can open. A **code editor is the in-lane kind of editor** — `OllinLiveCoding` live-codes the Ollin **Swift sketch itself** (not just the shader part) and *shows* that code to the audience (the Hydra model, where the code is the performance), which keeps code canonical; a GUI document editor that makes the sketch incidental is the out-of-lane kind. (The live-coding loop builds on the shipped dylib hot-reload engine — `SketchLoader` / `SketchRunner.reload`, the `--keep-clock` phase-carry — driven from an in-app editor with evaluate-on-command, since Swift compiles rather than `eval`s.)

**Where Ollin meets the pro tools, it interoperates rather than replaces.** The integration tier — Syphon, OSC, MIDI, virtual camera, tempo sync (sync *to* Ableton, never *be* Ableton), USDZ export — is "play in someone's existing rig," not "be the rig." That interop posture is the framework lane expressed in code.

## Platform scope

Apple platforms only, by design. macOS is the focus today; iOS, tvOS, and visionOS are in scope as *future* targets (see the Swift Playgrounds / iOS follow-up and the 3D & visionOS follow-up). Linux and Windows are explicitly out of scope — not now, not later — so don't add cross-platform abstractions for them: lean on Metal, AppKit/UIKit, and SwiftUI freely. "No Linux/Windows" is not "macOS-only"; keep Apple-platform portability in mind (the `#if canImport(AppKit)`/`#if canImport(UIKit)` seams) so the iOS/visionOS work later isn't a retrofit.

**Web / WebAssembly was considered and declined, on purpose.** WASM (via SwiftWasm) is the one path to p5's "share a sketch by URL" web reach — the incumbents' biggest on-ramp advantage Ollin structurally lacks — so it's worth recording *why* it stays out rather than re-litigating it. The browser has no Metal: a web build needs a *second renderer* on WebGPU, exactly the cross-platform renderer abstraction this stance refuses, and the web version would be a reduced subset anyway (WebGPU has no hardware ray tracing or MetalFX, so the photorealism/RT tier wouldn't port, and the Apple-framework satellites — Vision, audio, MIDI, video, ARKit, the iPhone sensor link — have no browser equivalent). The Metal-native bet and a browser runtime are mutually exclusive, and the bet wins. Web *reach*, when wanted, is served by *exporting the artifact* (video / GIF / USDZ / SVG) and the OS-surface outputs, not a live web runtime; the only WASM use that wouldn't betray the bet is compiling the non-rendering geometry/SVG core for a web *tool* that emits vectors. The bar that would reopen it: WebGPU reaching feature parity (ray tracing included) *and* strong, specific demand for in-browser sketches — until both, it stays out.

## The architecture rule (load-bearing)

**The bare p5-style API is sugar over a public, typed core. Never make the facade the only path to a feature.**

- `Sketch`'s bare methods forward to an internal `Drawer` (see `Sources/Ollin/Core/Sketch.swift`). Keep that split. Anything `drawCircle(...)` can do, the `Drawer` should also do — with more control.
- The day a capability is reachable *only* through the bare API, the ceiling is capped. Build the feature on the core first, then add the sugar.

## Conventions

- **Typed value objects early.** Geometry and color are data you pass around, transform, and compose — not just immediate draw calls. Prefer adding `Vector2`, `Rectangle`, and a vector `Shape`/`Contour` type *before* the call sites multiply; retrofitting `x:y:` doubles into `Vector2` later is expensive.
- **Swift-idiomatic, not a literal p5 port.** Enums for modes (not `"CENTER"` strings), trailing-closure scoping (`withState { }`) over leaky global state, value types, overloads. Borrow p5's feel, not its warts.
- **Build on the extension seam.** OPENRNDR's `extend(...)` is shipped: register a `SketchExtension` (`Sketch.extend`) for `setup`/`beforeDraw`/`afterDraw` (in-frame, before the render — can draw into the canvas), `afterFrame` (post-render, with `FrameInfo` timing), and `frameRendered` (post-render, with the rendered `CGImage`) hooks. New cross-cutting features — overlays, guides, recorders, the FPS stats (already the seam's first customer) — bolt on as extensions instead of bloating the core. Extensions are per-instance, so the runner re-attaches built-ins like the stats observer across live-reload swaps. The **frame-grab** hook is the seam's latest customer: `frameRendered(_:_:)` hands an extension the rendered frame, *opt-in* via `wantsRenderedFrame` (read live each frame, so a recorder can arm/disarm) so only something recording pays the GPU→CPU readback; on the live path it's served by an off-screen re-render (pixel-identical to export, keeps it off the present path — an async drawable readback is a later optimization). The same capture without a window is the public headless `OllinApp.image(of:frame:)` (returns a `CGImage`; `OllinApp.export` is the PNG wrapper over it), which is what the render-correctness snapshot tests diff against committed references.
- Drawing methods live on `Sketch` (scoped to the instance), not true globals — keep it that way.
- **Draw verbs, not nouns.** Geometry-emitting calls are imperative verb phrases with a `draw` prefix — `drawCircle`, `drawRect`, `drawLine`, `drawPolygon`, `drawPolyline`, never bare nouns (`circle`). They read as the side-effecting immediate-mode commands they are (what the Swift API Design Guidelines want), and the prefix gives a clean rule: `draw*` emits geometry; state (`fill`/`stroke`/`background`) and transforms (`translate`/`rotate`/`scale`) keep their own names. "Feels like p5" is the *shape* of the API — bare top-level calls, terse positional args, motion by default — not p5's literal spelling, so the prefix keeps the feel and stays a good Swift citizen. New primitives take it too (`drawEllipse`, `drawTriangle`, …). (oF landed here too: `ofCircle` → `ofDrawCircle`.)
- **Consistent point arguments.** A primitive that takes a point offers a *positional* scalar form and a *role-labeled* `Vector2` form: `drawCircle(x, y, radius)` beside `drawCircle(center:radius:)`, `drawRect(x, y, width, height)` beside `drawRect(corner:…)`/`drawRect(center:…)`, `drawLine(x1, y1, x2, y2)` beside `drawLine(_:_:)`, `translate(x, y)` beside `translate(_ offset: Vector2)`. The rule: bare scalars go positional — everyone knows the `x, y, radius` order, and labels on them are pure stutter once call sites pass `x`/`y` variables (`drawCircle(x: x, y: y, …)`). The label is reserved for the value-object overload, where it names the *anchor* (`center:` vs `corner:`) and carries real information. New point-taking primitives (`drawEllipse`, `drawPoint`, `drawTriangle`, …) follow the same split. (Unlike Kotlin/OPENRNDR, Swift can't make one declaration callable both ways, so don't double the overloads to fake "both" — pick positional for the scalar form.)
- **State stack reads as Swift.** The drawing-state stack is `pushState()` / `popState()` — the combined transform+style snapshot, mirroring Core Graphics' `saveGState`/`restoreGState` — with `withState { }` as the scoped, exception-safe primary form (the `with…{ }` idiom of `withAnimation`/`withTaskGroup`). Reach for `withState { }`; the bare pair is the escape hatch. Combined (not split into transform vs style) by design; a split push/pop can come later as `Drawer`-level methods.
- **Deprecation path is a 1.0 gate.** Pre-1.0 the public API churns freely with no shims (the README disclaims stability) — no external sketches to protect yet, so renames like the noun→verb (`circle`→`drawCircle`) and `push`/`pop`/`isolated`→`pushState`/`popState`/`withState` ship unshimmed. *Before* 1.0, stand up the migration discipline that holds from 1.0 on: every public rename/removal ships an `@available(*, deprecated, renamed: "…")` shim that forwards to the new API, so Xcode offers a one-click fix-it. Gotchas: use the *full selector* in `renamed:` when labels or arity differ (`@available(*, deprecated, renamed: "drawCircle(_:_:_:)")`, not just `"drawCircle"`); keep deprecated members together (a `Deprecations.swift`) so they're easy to audit and drop after a grace cycle; have the shim *forward* to the new API, not duplicate it. A must-do gate, not a nice-to-have — the 1.0 stabilization pass is where the pre-1.0 renames get their shims.

## Sourcing & attribution (load-bearing — it's the public face)

This project is built with AI and says so openly (the README's "Built with AI" and "Influences & attribution" sections; the latter is a summary of the full credit record in the repo-root `ATTRIBUTION.md`). Getting attribution and license-compatibility right earns the creative-coding community's trust — treat it as first priority, not a side chore.

The framework is *inspired by* p5.js (LGPL-2.1), OPENRNDR (BSD-2-Clause), and openFrameworks (MIT): borrow their ideas and API vocabulary, write the implementation independently. **Never translate their source line-by-line** — a port of source is a derivative work that carries the original's license, and p5.js's LGPL is incompatible with Ollin shipping wholesale as MIT. "Inspired by" keeps Ollin MIT-clean; "ported from source" does not.

**One sanctioned exception: bundled third-party source (a distinct tier).** A library may be *vendored* — shipped as actual source — when it's a self-contained, permissively-licensed component wasteful to reimplement, wrapped behind Ollin's own API so it stays swappable and off the public surface. This is the opposite of inspired-by (it *is* their code), so it carries license obligations: keep the upstream LICENSE + per-file headers **intact** in the vendored dir (the one exception to "no framework names in code" — they're the library's own headers, and stripping them breaks the license); record provenance (upstream URL, commit, date); list it in the repo-root `THIRD-PARTY-NOTICES.md`; add a *Bundled third-party code* entry to `ATTRIBUTION.md` (the credits file the README links); keep the root `LICENSE` pure MIT so GitHub's root-only license detection holds the "MIT" badge. Vendor under `External/`, not `Sources/`. The first instance was **libtess2** (`External/CLibtess2`, SGI-B), the triangulator behind `Shape`/`Contour`; the current inventory (Box2D, Jolt, Clipper2, Syphon, Hosek-Wilkie, …) lives in `THIRD-PARTY-NOTICES.md`. A C++ library is reached through a hand-written `extern "C"` shim whose header is the target's `publicHeadersPath` (the CClipper2/CJolt pattern), never Swift C++ interop, so Swift only ever imports a C module. This tier is *not* a license to vendor copyleft (LGPL/AGPL/GPL) code, which stays inspired-by-only.

For ported *example sketches* (the iterate-by-porting workflow), provenance is per-sketch and must be honored:

- **Only port sketches whose license permits redistribution under MIT** — MIT, BSD, Apache-2.0, CC0/public domain, or CC-BY (with credit). For GPL/LGPL, CC-BY-NC, or CC-BY-SA sources, either get permission or rewrite the sketch as original work using the source only as inspiration (credit it as "inspired by").
- **Name the source in the file header** — the specific sketch, its author, a URL, and its license. Template lives in `Examples/README.md`.
- When unsure of a sketch's origin or license, **ask before committing it.** A trivial sketch (a plain dot grid) may fall below the copyright-originality bar, but crediting the inspiration is still the default.
- **Recreations** (`Examples/Recreations/`, organized by artist) credit the artist, framed as a homage *after* them (not a reproduction, not endorsed), plus the SFPC "Recreating the Past" class that inspired the section. Some are *ported* from a source sketch, so they also carry the code-lineage header (e.g. the Molnár ones, via the p5 repo); others are *original* Ollin interpretations built directly from the artwork, with no code lineage (e.g. the Riley one). Either way, name the artist and work and keep the homage framing. See `Examples/Recreations/README.md`.
- **Keep framework names — and product/lineage comparisons — out of code.** The influence story (p5.js / OPENRNDR / openFrameworks) lives in this file, the README, `ATTRIBUTION.md`, and commit messages — *not* in `.swift` comments. This is not limited to those three: it covers any *external product* reference (e.g. **Record3D** the capture app, SinkCam, Hydra) **and** *lineage/marketing comparison framing*. Don't write `// p5 default`, `/// like oF's ofNoise`, `// the own-app successor to borrowing Record3D's feed`, `// Ollin's own-app answer to X`, `// the way X does, but ours` — keep the information, drop the name *and* the comparison. (Ollin's *own* type/example names — `Record3DDevice`, `Camera`, `PhoneBodyPose` — are fine as plain internal cross-references, and Apple-framework API names actually in use — ARKit, Vision, usbmuxd — are fine; the prohibition is *external* product/framework names and *comparison framing*, not internal documentation.) Apply this *at authoring time*, not as a later cleanup, and when sweeping a file check *pre-existing* comments too — these have slipped into committed code before. The one *exception* is the per-example attribution header, which credits the actual source lineage. Source littered with running comparisons reads like a port and undercuts the "independent implementation, inspired-by not copied" stance.

There's a second tier of influence worth distinguishing from the conceptual one. Where p5.js / OPENRNDR / openFrameworks shaped the *API and ideas*, two peer Swift+Metal frameworks were read for *engineering approach* on the same platform: **swifty-creatives** (Apache-2.0, Processing-style immediate-mode) and **AsyncGraphics** (MIT, GPU image/video compositing). They were studied, not ported — specific lessons are noted inline through this file (shader build, pipeline cache, SDF circle, iOS seam, easing, snapshot testing). Same rules apply: credit them in `ATTRIBUTION.md` and commits, never in `.swift` comments, and write our own implementation. The public credit lives in `ATTRIBUTION.md` (linked from the README). (PixelKit is AsyncGraphics's older node-graph predecessor; cite AsyncGraphics instead.)

A third tier names influences for *capabilities still ahead* — shader-function collections, shader-composition / livecoding APIs, and AR. **These are inspirations, not dependencies:** *study how they work and reimplement our own*, never vendor or depend on them. It's especially clean for the shader-function collections — mostly implementations of *known, published techniques* (SDFs, noise, blends, color-space math, domain repetition): peek at the approach, then write Ollin's own, preferring the canonical source of a technique over any one collection's expression. Licenses still drive the no-line-by-line-copy rule:

- **LYGIA** (github.com/patriciogonzalezvivo/lygia, Patricio Gonzalez Vivo, who also created The Book of Shaders) — a large, multi-language catalog of shader functions (GLSL/HLSL/WGSL/CUDA plus an *experimental, partial* MSL/Metal port: `sdf`, `sampler`, `blend`, parts of `distort`/`generative`/`math` done; `lighting`/`geometry`/`palette` not yet). The best *map* of which techniques exist and how they're commonly approached. Licensed **Prosperity Public License 3.0.0** (noncommercial) — since we reimplement rather than ship its code, that's not a bundling problem; it's the reason to never translate a LYGIA file line-by-line and to implement from the underlying technique instead.
- **Hydra** (github.com/ojack/hydra, Olivia Jack) — a web livecoding environment with a chainable, analog-video-synth shader API (`osc().rotate().modulate(noise())…`). The thing to mine is *how it makes combining and mixing visuals so fluid* — borrow that ergonomic direction. Licensed **AGPL-3.0** (strong network copyleft) → **inspiration only**, never ported or vendored, exactly like p5.js's LGPL.
- **ShaderPark** (github.com/shader-park — `shader-park-core`, `shader-park-examples`, `shader-park-live-coding`, all **MIT**) — a JS→shader SDF "sculpting" library with composable combine/blend functions and its own livecoding environment; another reference for *how to compose and mix* shader-driven shapes. MIT, so it can be studied freely — still: write our own, credit it.
- **ofxFX** (github.com/patriciogonzalezvivo/ofxFX, Patricio Gonzalez Vivo again, **MIT**) — the openFrameworks effects addon behind his *Efecto Mariposa*: each effect is a ping-pong-FBO object chained/mixed with a `<<` operator, organized as composers (blend/mask/multi-texture), filters (blur, gaussian, bloom, glow, bokeh, **LUT color grading**, chroma aberration, old-TV), generative (noise, FBM, fire, Gray-Scott), and operations (ripples, flow, edge detect, normals). The reference for the [layered-effects](DESIGN-NOTES.md#layered-effects-and-compositing) *effect-object architecture and catalog* — blending fx shaders and LUTs — from the GL/oF generation, beside AsyncGraphics' Metal-native take. MIT, study freely — still: write our own, credit it.
- **Paper Shaders** (github.com/paper-design/shaders, paper.design, **Apache-2.0**, shaders by Ksenia Kondrashova) — production design-shader effects for the web: mesh gradients, liquid metal, fluted glass, god rays, water, heatmap, paper texture, dithering/halftone. The map of which *designer-facing* effects exist and their parameter feel — the design-pattern `Generator` set was cross-read against it (written from the canonical techniques, credited per-technique in `ATTRIBUTION.md`), and the design-filter set (fluted glass, water, paper texture, liquid metal, heatmap, gem smoke) was cross-read the same way. Permissive, so study freely — still: write our own, credit it.
- **Meta Spark** (Meta's discontinued AR studio, shut down Jan 2025 — no public source) — the *product* reference for an AR direction: its template-driven AR-effect authoring is the void @eaviles wants Ollin to fill on Apple platforms. Conceptual/product influence only; there's nothing to port. (Used in Zach Lieberman's AR class — keep that personal detail out of public files, see the AR follow-up.)

Same rules as every tier: credit in `ATTRIBUTION.md` and in commits, never in `.swift` comments, own implementation.

## Shaders & the Metal back end

The shader set is split across several `.metal` segments (`Renderer/Shader*.metal`), concatenated and compiled as one library at runtime (see *The shader set is multiple segments* below). Decisions that are cheap now and expensive to retrofit:

- **One source of truth for CPU↔GPU structs — defined once in a shared C header.** The three structs shared between Swift and MSL (`OllinVertex`, `Uniforms`, and `SDFInstance` — the last a stride-144 *tagged union* that keeps growing) live in `Sources/Ollin/Renderer/OllinShaderTypes.h`, so a field can't drift between the two sides and silently corrupt memory. Swift imports them through the thin `COllinShaders` C target (whose umbrella header re-includes the canonical file by relative path, since SwiftPM won't let a resource escape its target or two targets' dirs overlap); `ShaderCore.metal` (the first segment) `#include`s the same header. The one wrinkle the header note predicted: runtime `makeLibrary(source:)` has no include path, so `MetalRenderer.composeShaderSource` splices the header's text in for the `#include` directive before compiling — which is why the header ships *beside* the segments as a `.copy` resource. The fields are spelled in the `simd_*` names the Swift importer maps to `SIMD2<Float>`/etc.; a `__METAL_VERSION__` guard aliases those onto Metal's `float2`/`float3x3`. **A new shared struct (or a wider `SDFInstance`) goes in that header — never re-declared in two places.**
- **Runtime source compilation is a feature, keep it.** `loadLibrary` concatenates the `.metal` segments and compiles them from source at runtime (`makeLibrary(source:)`). For a creative-coding framework that's the seam for shader hot-reload and user-supplied shaders later — don't rip it out. Its costs are startup time and *no build-time error checking*.
- **Add a precompiled `default.metallib` when those costs bite, don't replace.** Build-time validation and zero startup cost need the built-in shaders compiled ahead of time. `loadLibrary` prefers a precompiled `Bundle.module` metallib *before* the source path **on a non-ray-tracing device** (an RT device source-compiles, to splice in the device-conditional `OLLIN_RT_SHADOWS` define), so a precompiled lib slots in with no API change; runtime compilation stays for dynamic shaders. Two facts settle *how* to produce it (both verified on this toolchain — Swift 6.3, macOS):
    - **Ship `.metal` as `.copy` (raw source) — `.process` now precompiles a metallib.** Ollin compiles its shaders from source at runtime, the seam the shader hot-reload, user shaders, *and the device-conditional `OLLIN_RT_SHADOWS` ray-traced-shadow path* all rely on — so the raw `.metal` must reach `Bundle.module`. **On current SwiftPM toolchains, `.process` on a `.metal` precompiles a single `default.metallib`** (and stops copying the raw source), so `makeDefaultLibrary(bundle: .module)` then succeeds — convenient for a fixed shader set, but a metallib holds only one compile, so it *can't* carry a device-conditional variant. That's why the `Shader*.metal` segments are **`.copy`** resources and `loadLibrary` source-compiles on a ray-tracing device (preferring the metallib only on non-RT GPUs). (Historically `swift run` did *not* auto-compile loose `.metal` — that was Xcode-build-system-only — but the toolchain caught up; don't assume `.process` leaves the source uncompiled.)
    - **A precompiled `default.metallib` shipped as a `.copy` resource loads fine.** `xcrun metal` + `xcrun metallib` produce a `default.metallib`; `.copy`-listed in the target, it's found by `makeDefaultLibrary(bundle: .module)`. So under `swift run` the path is a SwiftPM build-tool plugin that runs that compile and emits the metallib as a resource. (Playgrounds plugin support is unreliable — see the iOS follow-up — so keep runtime source compilation too; never go plugin-*only*.)
- **A user-supplied shader-library seam is cheap.** Resolve the active library as `customMetalLibrary ?? defaultMetalLibrary` so a user can drop in their own compiled library without touching the built-ins; pairs with the runtime-source loader for hot-reload. (Both peer Swift+Metal frameworks expose exactly this.)
- **Built-in shader functions are our own, written from the technique — not a vendored library.** As the shader set grows past drawing (noise, SDF primitives, blends, color-space conversions, domain repetition), implement each from the *published technique*, then credit that source in the `ATTRIBUTION.md` Techniques list (as the cosine `CosinePalette` and `curlNoise` already do). The canonical sources to reach for, baked in here so we go straight to them: **Inigo Quilez** for signed-distance functions (2D `iquilezles.org/articles/distfunctions2d`, 3D `/distfunctions`) and smooth-minimum, and the cosine palette (already used); **hg_sdf** (`mercury.sexy/hg_sdf`) for domain operators — axis rotation, mirror, and linear/polar repetition; **The Book of Shaders** for hashing and value noise. LYGIA is a broad *catalog/map* of which techniques exist and how they're approached — read it to discover, implement from the underlying technique, never translate its files (Prosperity; see [Sourcing & attribution](#sourcing--attribution-load-bearing--its-the-public-face)). (Distinct from the user-supplied seam above, which is for a *user's* own shaders, not for vendoring someone else's library into Ollin.)
- **Cache pipelines; don't grow `init`.** `MetalRenderer.init` builds one `MTLRenderPipelineState` inline. A new pipeline (textured quads, a new blend mode, compute) should be a cache lookup, not more code in the constructor. Key the cache on a `Hashable` descriptor struct (shader, blend mode, MSAA sample count, pixel format), not a flat enum: pipeline variants are *combinations* of those axes, and a struct key captures the product without an enum case per combination. Folding blend mode into that descriptor also keeps it a pipeline *parameter* — one pipeline factory — rather than a whole renderer subclass per blend mode (the trap a peer framework fell into).
- **The shader set is multiple `.metal` segments, concatenated at load.** It outgrew a single file at ~2,000 lines and split into `Renderer/Shader*.metal`: `OllinShaderLib` (the shared helper library — see *User-supplied shaders*), `ShaderCore` (preamble + shared color/dither/hash helpers), `ShaderShapes` (SDF primitives + the shared `ollin_sdf_distance`), `ShaderCombinator` (the SDF-combinator node VM — must follow `ShaderShapes`, it reuses `ollin_sdf_distance` + the coverage tail), `Shader3D` (particles/cloud/mesh/matcap/wireframe), `ShaderRaymarch` (the 3D SDF sphere-marcher — must follow `Shader3D`), `ShaderEffects` (present + the single-input filters + basic generators; `PresentOut` lives here for every later segment), `ShaderCombine` (two-input combines + the screen-space depth ops + the deferred RT-reflection passes), `ShaderSim` (the stateful ping-pong sims + fluid), `ShaderPatterns` (the design-pattern generators + design filters), `ShaderIBL` (the environment bake). `loadLibrary` reads them from `Bundle.module` in the fixed order `MetalRenderer.shaderSourceNames` and concatenates into one compile unit, because runtime `makeLibrary(source:)` has no include path (so an `#include` umbrella can't work). **Order is load-bearing:** `ShaderCore` is first because Metal needs a declaration before use and the later segments rely on its helpers; no segment is compilable alone, and the header `#include` lives once in `ShaderCore` for `composeShaderSource` to splice. Live shader reload (`SketchRunner.reloadShaderLibrary(fromDirectory:)`, used by OllinLive) concatenates the same segments from the repo filesystem via `MetalRenderer.concatenatedShaderSource(fromDirectory:)`. Adding a segment: create the file, add it to `shaderSourceNames` (in dependency order) and to the `Package.swift` `.copy` resources.

## Rendering performance

The drawing model is *immediate-mode GPU*: every frame `Drawer` records each primitive into call-ordered batches, the renderer uploads them through a **triple-buffered, semaphore-gated vertex-buffer ring**, and encodes one draw per batch run. (The ring is load-bearing — never collapse it back to one shared buffer: writing a buffer the GPU is still reading for an in-flight frame tears the geometry on screen, e.g. gaps in a stroked ring; a real bug, fixed by the `maxFramesInFlight` ring + `frameBoundary` semaphore in `MetalRenderer`.) This is the right shape — it's what NanoVG, Dear ImGui, and Processing's GL renderer do — so the "low-level" look is the cost of a Metal core, not accidental complexity. Don't trade it for Core Graphics / SwiftUI `Canvas` / SpriteKit: those are CPU rasterizers or retained-mode scene graphs, and adopting one as the substrate throws away the GPU + shader ceiling the whole vision rests on. **CPU tessellation is the first bottleneck, not the GPU** — and **instancing is the shipped answer** (the SDF quads, the point-cloud splats), with **retained batches** (`Batch`, the *Current state* bullet) the shipped answer for static heavy content; the tiers above them (indirect command buffers, mesh shaders) are roadmap (`ROADMAP.md` § *Rendering and color frontier*, `DESIGN-NOTES.md`).

Mechanism and history live in [`ARCHITECTURE.md`](ARCHITECTURE.md) § *The 2D drawing paths*; the regression-preventing rules stay here:

- **SDF analytic primitives — shipped.** The closed 2D primitives (~30 shapes: point markers / circle / ellipse / rect / oriented box / circular arc / triangle / ngon / star / ring + the novelty catalog) each render as one instanced quad (`SDFInstance`, the `.sdf` pipeline) — per-shape CPU cost is one struct write, and each instance carries its own CTM so AA stays ~1px under any transform. `drawLine`/`drawBezier` moved to the **fringe stroke path** (their shader cases retained-but-unemitted); arbitrary `drawPolygon`/`drawPolyline` and elliptical/full-turn arcs stay on the triangle path (`drawArc` runtime-branches; its *stroke* goes to the fringe path either way). **Coverage is split by whether a shape tiles, and it's load-bearing:** box/pie/chord/triangle/star/ngon + the non-round markers use the **inside-biased** ramp (`regionCoverage` — full to the geometric edge, AA halo only outside) so abutting fills leave no seam — never move them onto the centered ramp; disks and capsules/lines use **area-conserving** coverage (`diskCoverage` — a sub-pixel mark keeps a ~1px footprint while its alpha scales by true area/width, so sizes run 0…n without popping or flicker); stroke **bands** conserve ink the same way (`strokeBandCoverage`; a band ≥~1px reduces to the plain smoothstep, byte-identical). **Draw order is preserved:** call-ordered `GeometryBatch`es (`.triangles`/`.sdf` runs) composite as drawn — never collapse into unordered passes (breaks occlusion, e.g. EllipseField's black-fill ropes). One non-discoverable rule: vesica/moon `cornerRadius` must `opRound` off a *full-footprint* SDF (the inset form loses all float precision — a real glitch). **Hollow/band mode** (`hollow(_:)` / `solid()`) onions every region shape's SDF (`SDFShape.honorsHollow` opts in); **stroke alignment** (`strokeAlign(_:)`) shifts the stroke band by an exact SDF offset riding bits 8-9 of the `shape` tag; `.center` is byte-identical. New shapes drop in as four touch-points under a fixed scalar budget — **`SDFInstance` is full at 144 bytes** (the next field is a real widening) and `size` doubles as the covering-quad AABB half-extent, never a free geometry slot; the forward shape list lives in `ROADMAP.md`, and SDF *operators* live on the combinator path.
- **MSAA is 8× where the device supports it** (else 4×), and only for the *triangle* path (the SDF and fringe paths carry analytic coverage). The sample count is chosen once via `ollinPreferredSampleCount(_:)` (`SketchView.swift`) and shared by the live view and the export paths.
- **Rendering is gamma-correct (linear-light).** Geometry composites into a **linear `rgba16Float` intermediate**; the present pass tone-maps, dithers (TPDF, a pure function of pixel position — reproducible), and re-encodes to the sRGB drawable — the single 8-bit quantization point. Three rules keep tones from shifting: shaders **linearize** their sRGB `Color` inputs; the **clear color is linearized too** (`Color.srgbToLinear` in `mtlClearColor` — miss it and the background washes out lighter, since the clear bypasses the shader); image textures load `.SRGB: true`. **One deliberate carve-out: stroke and disk/dot AA *coverage* is remapped to perceptual alpha** (`perceptualCoverage`) — pure linear blending reads a thin dark mark faint/"beaded" (the Molnár *Interruptions* bug) — touching **only partial coverage**, never a shape's own fill/stroke alpha, and **not** the region *fill* ramp (abutting fills must keep tiling seamlessly). The capsule/bézier AA footprint is the **L2 gradient length**, not `fwidth` (the L1 norm overshoots √2× at 45°, fading diagonals). Verified near-optimal for the raster path (4× SSAA barely beats it).
- **Fills triangulate, strokes fringe.** Concave/holed fills go through **vendored libtess2** (`Shape.triangulatedFill()`, per-`Shape` `winding` — `.evenOdd` default, font glyphs `.nonZero`; the glyph clean/simplify gotchas live under *Text* in *Current state*) + MSAA; convex shapes keep the direct fan/strip math — don't route them through the triangulator. **Every stroke renders through the AGG/NanoVG-style fringe expander** (`appendFringeStroke`): CPU edge-expansion plus a ~1px screen-space AA fringe, honoring `strokeJoin`/`strokeCap` (`drawLine`'s default cap is now **butt**), the coverage riding an `aa` field in `OllinVertex`'s alignment padding (stride stays 32, the triangle path byte-identical), the fringe straddling the true edge so perceived width = `strokeWidth`. **The fringe is strokes-only — fills stay libtess2 + MSAA, byte-identical** (a fill fringe reintroduces abutting-fill seams or fattens; settled by a native-res A/B). A cross-section is **five points (outer/core/center/core/outer), and the centerline one is load-bearing**: every join fans from the path vertex, so without it that apex T-junctions into the middle of the core band's end edge and the sub-pixel-snapping hairline eats MSAA samples (isolated 6/8-coverage pixels inside solid ink; `FringeStrokeTests` pins it, no snapshot can — a few pixels in a million average away). Coverage is equal across the two core bands, so the split draws nothing new, and building each cross-section as a fixed `Cross` value rather than the old per-call `offsets(_:).map` arrays makes it a net **~10% faster** than before. **Consecutive segments end on their shared inner crossing** (the inner miter point, NanoVG's `chooseBevel` model, `innerMiter[v]` scaled so an offset stays the true distance to *both* centerlines): ending each on its own perpendicular makes both quads cover the wedge between them, and non-opaque ink composites it twice — a hard second-coat diamond at every corner (224 → 197 at alpha 0.25), a graded band down a curve's inner half, dark radial spokes combing a spiral. **Only the inner side moves** (the outer side keeps its perpendicular, so the join filler and the centerline seam are untouched), the covered region is *unchanged* for opaque strokes (the union already ended at that crossing → whole snapshot suite passed unrecorded), collinear vertices are skipped (a straight polyline is byte-identical), and a crossing outside either neighbouring segment falls back to square ends (the inner-bevel case — an overlap beats a crack when the corner folds anyway). Triangle count and speed are unchanged. `FringeStrokeTests` pins it (a snapshot's mean diff averages it away). **Measure coverage in linear light** before reasoning about gap widths (the same pixel reads 46% in sRGB, 75% linear — the sRGB figure made the seam look impossible). `appendStrokedPath` is retained for **outline-glyph stroking only** and shares the rule via `Drawer.innerCrossings`, but its segments are plain quads with no centerline point, so bending the inner end moves the end edge off the path vertex and a filler fanning from there T-junctions (a **pale** comb, the mirror of the dark one): its filler fans from **the crossing itself** instead (free — the gap is bounded by both end edges, which run to that point; pixel-identical to splitting each segment at the centerline, which costs two triangles). `GlyphStrokeTests` pins both symptoms with AA-immune predicates (darker-than-coat / lighter-than-coat-with-ink-all-around, `InkProbe` in the test support; note the present pass **dithers**, so one coat straddles two 8-bit levels). The **elliptical/full-turn `drawArc` stroke** joined the fringe path too (it used to lay bare `appendSegment` quads with no joins or caps at all, so it carried *both* defects: inner overlap **and** outer gaps, together a fine faceting) — it hands the expander the same shapes `svgRecord` writes (`.open` polyline / `.chord` closed / `.pie` closed through the center), so raster and vector trace one outline, and it now honors `strokeCap`/`strokeJoin` (default `.butt` keeps the old ends). Curved outlines flatten through the public `Path` builder (`drawShape { }`, `drawCurve(_:closed:)`) into the same fill + stroke paths — a curve never touches the SDF side.

Pipelines build through the `PipelineKey`-keyed cache (`makePipeline(_:)`; the enum→`Hashable`-struct key migration shipped with the 3D work), so a new pipeline is a new cache key, not more `init` code — blend mode, MSAA count, and pixel format ride the key as parameters (see *Cache pipelines* above).

## Build, run, verify

```sh
swift run Example-Basic-HelloCircle   # opens a window running an example
```

The canvas is `1080×1080` by default (`canvasSize`, the typed `CanvasSize` enum — `.square(n)` / `.size(w, h)` + named presets, integer pixels); the preview window is sized from the sketch's `windowMode` (`.auto` fits the screen, `.fixed`, or `.resizable`) — the window is a scaled view of the canvas, not the canvas itself.

- **Requires macOS 26+ and a Metal-capable GPU.**
- **`swift build --target Example-X` does not relink the executable.** It compiles the module and reports success, but `.build/debug/Example-X` stays the *old* binary — a tuning loop against it silently re-runs stale code (a real hour lost: three "tuning" rounds of VideoTrace all ran the first build). Rebuild runnable examples with `swift build --product Example-X` or just `swift run Example-X`; reserve `--target` for compile-checking libraries.
- **Check the environment before claiming you can't build.** Ollin needs the Swift toolchain and Metal, which exist on a Mac but *not* in the Linux web/iPhone container. These two run on different machines, so don't assume: if `swift --version` and `xcrun --find metal` succeed, you're on a Mac with the toolchain — **build, run, and verify directly** (`swift build`, `swift run <Example>`), and don't add caveats about being unable to compile. Only when that toolchain is genuinely absent (the Linux container) are changes unverifiable on this machine — say so then, and not before. Either way, the things that truly need a simulator or device (iOS/visionOS/AR) stay unverifiable here regardless.

A few load-bearing rules recur across the satellites, so they're stated once here instead of per-bullet:

- **Render-thread closures must be built non-isolated.** Any closure an audio / MIDI / Vision / capture render thread calls, if formed in a `@MainActor` context, inherits main-actor isolation and Swift injects an executor assertion that *SIGILLs* the instant that thread runs it — build it in a free function or a non-`@MainActor` type.
- **`resource:in:` can't default `in:` to `.module`** — a default arg resolves to *Ollin's* bundle, not the caller's; every font / image / mesh / model loader makes `in:` explicit.
- **Never replace a GPU texture in place** — an in-flight frame may still be reading the old one; allocate a fresh texture when the bytes change.
- **Satellites can't depend on each other** — a shared seam (`RGBDFrame`, `SegmentationImages`, `FrameSource`, `AudioTapSource`, the `OllinUSBMux` tunnel) lives in the `Ollin` core, often `package`-access.
- **Background-producer → main-reader handoff** is uniformly an `@unchecked Sendable` producer with an `OSAllocatedUnfairLock` handoff (audio analyzer, OSC/MIDI receivers, Vision analyzer, phone readers all share this shape).

The **SDF path** covers a broad analytic-shape catalog (`drawPoint` / `drawCircle` / `drawEllipse` / `drawRect` / `drawOrientedBox` / circular `drawArc` / `drawTriangle` / `drawNgon` / `drawStar` / `drawRing` / `drawHeart` / `drawMoon` / … + `hollow(_:)` band mode, `strokeAlign(_:)`, area-conserving disk + outline coverage); the **fringe path** covers every stroke (`drawLine` / `drawBezier` / `drawPolyline` + polygon/shape/elliptical-arc outlines, honoring `strokeJoin` / `strokeCap` / `strokeProfile`, translucent + gradient paint); the **triangle path** covers convex/concave/holed fills (`drawPolygon` / `drawShape`, curved via the `Path` builder + `drawCurve`) and elliptical/full-arc fills. Collection sugar: `drawCircles` / `drawPoints` / `drawRects`. **Kaleidoscope symmetry** — `symmetry(_:mirrored:)` / `noSymmetry()`, stack state: every 2D draw call replicates through canvas-space fold matrices (each local rotation/reflection conjugated by the CTM at the `symmetry` call — fold 0 stays the exact identity, so the primary copy is byte-identical). **Load-bearing:** replication is per emission funnel — SDF instances and combinator groups left-multiply their per-instance `transform` (groups share one node program), the triangle/fringe/image/glyph paths range-copy canvas-space vertices via `Drawer.replicated` whose body must stay within **one batch kind** (wrap a fill section and its stroke separately; `isReplicating` passes a nested funnel through, and folds are rigid so screen-space AA/fringe widths stay exact), and `svgRecord` replicates commands so `--export-svg` folds too; 3D geometry, GPU particles, and depth scenes are untouched by design. Example `Patterns/Kaleidoscope` (declares `loopDuration`); snapshot `symmetry`; `SymmetryTests`. **Clipping** — `withClip(shape/rect/circle) { }`, the standard stencil clip (increment/decrement): the region triangulates through the fill path into a stencil-only `.clipPush` batch (CTM baked at the push), content batches carry a `clipLevel` and stencil-test `equal` to it, and the block's end appends a fullscreen-decrement `.clipPop`; nesting intersects. **Load-bearing:** a `stencil8` memoryless MSAA attachment joins a pass **only when that surface clips** (`Drawer.usesClipStencil` / `RenderTarget.needsStencil` — an unclipped frame is byte-identical), and in a stencil-carrying pass **every** pipeline key must declare `stencilFormat` (skybox and raymarch-upsample included) or Metal validation rejects the draw; never pass `setDepthStencilState(nil)` (validation rejects nil — use `noDepthState`); clipping is **per surface** (a layer opened inside a clip block starts unclipped); `background(_:)` inside a clip block re-emits the open pushes after the wipe (`reemitClipPushes`); clip edges AA at MSAA resolution (the clip shape rasterizes binary per sample); `--export-svg` emits native `<clipPath>` defs + nested `<g>` groups. Example `Shapes/Clipping`; snapshot `clip`; `ClipTests`. The load-bearing renderer rules (the vertex-buffer ring, the SDF tagged union, coverage models, the present/float pipeline) live in *Shaders & the Metal back end* + *Rendering performance* above. `Docs/Drawing/Drawing.md`.

- **Variable-width strokes** (`Sources/Ollin/Drawing/StrokeProfile.swift` + the expander in `Core/Drawer+Tessellation.swift`). **`strokeProfile(_:)`** / `noStrokeProfile()` is stack state shaping width along a path: the **`StrokeProfile`** value type (`.uniform` / `.taper(start:end:)` / `.ramp(from:to:)` / `.nib(angle:thinness:)` / `.values(_:)` + the closure forms) returns a **multiplier on `strokeWeight`**, read at path fraction 0…1 plus the local direction (what `.nib` uses). The fringe expander carries a **half-width per path vertex** (`Drawer.strokeHalfWidths`), so a segment quad becomes a trapezoid, exact for a linear ramp along a straight run. **Load-bearing:** width is sampled **per path vertex, not per segment**, which is *why* joins stay simple (both segments at a corner agree on the width there, so a corner is the constant-width corner problem at the local width) and why joins/caps just read their own vertex's width; a non-uniform profile **subdivides like a gradient does** (`maxLength: 12`) since the profile can only follow the points it's given; **`.uniform` is the untouched path** (`isUniform` gates the expander, the outline builder, and the vector recorder) and the coverage ramp is the shipped one either way, so a profiled and an unprofiled stroke of the same width lay down the same ink and every existing snapshot is unchanged; the **analytic SDF shapes carry one width by construction** and ignore a profile with a one-time `noteOnce`. **Vector export stays true:** `svgRecord` routes a profiled stroke to `variableStrokeOutline` (trapezoids + join wedges + caps, each wound the same way into **one nonzero-wound `Shape`**, so the union needs no boolean work), recorded as a filled path rather than a `stroke-width`; PDF replays the same commands. Example `Shapes/StrokeProfiles`; snapshot `stroke-profiles`; `StrokeProfileTests` (the family, arc-length sampling, outline winding + area, rendered taper falloff). `Docs/Drawing/Drawing.md#strokeProfile`.

- **Stroke dynamics** (`Sources/Ollin/Drawing/StrokeDynamics.swift` + `StrokeMark.swift`). The width-profile sibling driven by *how a mark is made* rather than where you are along it: a **`StrokeMark`** records the pointer (`record(_:dt:pressure:)`, sugar `Sketch.record(into:)`) measuring speed and press force, runs both through a **`StrokeDynamics`** (one **`StrokeResponse`** per axis over a **`StrokeInput`** of speed/pressure/direction/distance), and keeps the resulting width + opacity *at* each point; `drawMark(_:)` strokes it. **Load-bearing:** a profile can't express this because a mark in progress has no length to take a fraction of, and a recorded hand's points are **not evenly spaced** (dense where it slowed), so `.values(_:)` genuinely doesn't fit and `StrokeProfile.values(_:at:)` (values at *given* fractions) is the general form `drawMark` builds; speed is measured over **real elapsed time** with skipped sub-`minimumSpacing` frames **banking** their dt (frame-rate independence, pinned by `recordingIsFrameRateIndependent`), smoothed by a `OneEuroFilter` per axis fed a **scaled** signal (a px/s speed runs in the hundreds, and the filter's `beta` is in the signal's units); the **two axes are separate and each defaults to `.unchanged`** (a shared preset with per-axis defaults silently drove both, the bug the first probe caught); the first point is **held until a second gives it a heading**; the ambient `strokeProfile` **multiplies** with the mark's widths; the mark's opacity rides the existing **per-vertex color alpha** via an internal `strokeOpacityShape` (`.uniform` default → every other stroke byte-identical, and a `.uniform` mark is byte-identical to `drawPolyline`). **Pressure is plumbed** through the one platform-neutral input surface (`Sketch.pressure` / `pressureIsAvailable`, capability latching on the first press), so it reaches standalone + gallery + OllinLive — but **not via `pressureChange`**: the SwiftUI hosting layer consumes `.pressure` events before responder dispatch *and* its recognizers override the view's `.primaryGeneric` with deep-click (reads ~0 across the whole normal force range), so `OllinMTKView` feeds a **view-owned local `.pressure` event monitor** and `mouseDown` re-claims the stream with `pressureConfiguration?.set()`; **never read `associatedEventsMask` on a `.pressure` event** (the access raises and AppKit swallows the raise, silently dropping the report — a pressure event is itself the capability proof), and mouse/drag events from a pressure-capable device **seed zero, then go quiet once the stream is live** (their `pressure` field is the legacy constant 1). Mechanism: [`ARCHITECTURE.md`](ARCHITECTURE.md) § *Trackpad pressure delivery*. **Vector export** keeps width exactly (the profiled filled-outline path) and **flattens opacity to its length-weighted average** with a `noteOnce` (one fill, one alpha per path; free for the one-pen plotter case). Example `Shapes/Brushwork` (class renamed off `StrokeDynamics` to dodge the `SlitScan` shadowing trap); `StrokeDynamicsTests` (mapping, measurement, arc-fraction placement, three rendered probes, no pixel snapshot since dynamics is interactive). `Docs/Drawing/Marks.md`.

- **Brushes** (`Sources/Ollin/Drawing/Brush.swift` + `Core/Drawer+Brush.swift`). The third mark axis beside the width profile and the recorded mark: **`strokeBrush(_:)`** / `noStrokeBrush()` is stack state that **replaces the ribbon with a row of stamps**. The **`Brush`** value type carries a `tip` (`.circle` / `.square` / `.shape(Shape)` / `.image(Image)`), `spacing`, `sizeJitter`, `angle` (`.followPath` / `.fixed` / `.random`), `angleJitter`, `scatter`, `count`, `opacityJitter`, `seed`, plus the `.round` / `.chisel()` / `.spray()` / `.scatter()` presets; size comes from **`strokeWeight`** and color from **`stroke`**, so a brush is texture only. **Load-bearing:** every distance is a **fraction of the stamp's own size**, which is what keeps a brush's texture constant across weights (pinned by `spacingScalesWithTheStampNotTheCanvas`); stamps are placed **by arc length, not per vertex** (a recorded mark's points bunch where the hand slowed, and a brush must not bunch with them); randomness is a **pure function of stamp index + `seed`** via a private `SplitMix`, **never the sketch's `rng`** (the halton/sobol rule), so adding a brush cannot shift a sketch's other rolls; the ambient `strokeProfile` / `strokeOpacityShape` are read per stamp and **multiply**, and the step is taken at the *local* size so a tapering mark crowds rather than going gappy; a stamp draws through the **ordinary draw methods** (`drawCircle` / `drawOrientedBox` / `drawShape` / `drawImage`) with fill/stroke/brush swapped and restored, so vector export, symmetry, clipping, and retained batches all work with no knowledge of brushes (and recursion is impossible); **`strokedAsBrush(_:closed:)` is called ahead of every stroke entry point's `svgRecorder` short-circuit** (`drawLine` / `drawBezier` / `drawPolyline` / `drawMark` / `drawArc`, and `drawShape` / `drawPolygon` which re-enter fill-only then stamp) or the vector path would silently export the bare path instead of the stamps — the `appendFringeStroke` hook is the catch-all for internal callers; a brushed `drawMark` **keeps** its varying opacity in vector export (each stamp is its own shape) where the ribbon must flatten it; opacity over a **gradient** stroke is the one thing a brush cannot vary (it would mean rewriting the ramp) and notes once, as do the analytic SDF outlines (the `strokeProfile` precedent). `Brush` is **not `Sendable`/`Equatable`** (an `Image` tip is neither). Example `Shapes/Brushes`; snapshot `brushes`; `BrushTests`. `Docs/Drawing/Marks.md#brushes`.

- **Retained batches** (`Sources/Ollin/Drawing/Batch.swift` + `encodeRetained` in `MetalRenderer+Effects.swift`). **`makeBatch { }`** records a drawing once into a **`Batch`** (persistent, made in `setup()` and held — the `Feedback` shape) and **`drawBatch(_:)`** replays it from the handle's own once-written per-device `MTLBuffer`s — the escape from per-frame re-recording for *static heavy* content (measured M2 1080² release: 150k circles ~13.5 ms/frame per-frame vs ~0.003 ms replayed; example knob flips the two live). **Load-bearing:** recording is an **array swap** on the `Drawer` (per-frame arrays + batch list + gradient-row table), so recorded runs index the handle's arrays and baked gradient rows are **handle-relative** — the replay binds the batch's **own strip texture**, never the frame's; the body runs style-scoped (`pushState`/`popState`) from an **identity CTM** with the target/clip stacks swapped out, and the `.retained` reference batch supplies the draw-time context (CTM + target + clip level + `depth(at:)`); the draw-time CTM rides **flag-gated `Uniforms` fields** every 2D vertex shader applies to its *output position only* (flag 0 outside a replay → ordinary paths byte-identical, snapshot suite unchanged; identity replay byte-identical to the per-frame drawing, pinned by `BatchRenderTests`; SDF analytic AA stays exact under any replay transform because shape-local interpolants never change); **unsupported content is gated at its funnel** with a one-time note (meshes + 3D fields would silently lose shadows/reflections; particles; layer blocks; clipping; `background`; nesting) — never dropped after recording, which would corrupt the next-run count derivation; point clouds record camera-less and replay through the frame's camera (the 2D replay CTM doesn't touch them); **draw-time symmetry does not fold a replay** (record folds inside the block); vector export flips **`OllinApp.isVectorExporting` for the whole `recordVectorFrame` drive** (setup + warmup included) so `makeBatch` captures `SVGCommand`s instead and `drawBatch` splices them under the composed CTM — SVG/PDF see every stamp. Example `Rendering/RetainedBatch`; snapshot `retained-batch`; `BatchTests`/`BatchRenderTests`. Mechanism: [`ARCHITECTURE.md`](ARCHITECTURE.md) § *Retained batches*. `Docs/Drawing/Batches.md`.

- **SDF combinators** (`Sources/Ollin/Drawing/SDF.swift` + `Renderer/ShaderCombinator.metal`; 3D in `Sources/Ollin/Drawing/SDF3D.swift` + `Renderer/ShaderRaymarch.metal`). Compose signed-distance *fields* so shapes **merge** instead of stack — the field-combining axis the per-instance SDF path can't express. The typed **`SDF`** value type (leaf region shapes + `.union`/`.smoothUnion(_:k:)`/`.subtract`/`.smoothSubtract`/`.intersect`/`.smoothIntersect`/`.morph`, the hg_sdf joint + detailing ops (the chamfer/stairs/columns trios + `engrave`/`groove`/`tongue`/`pipe` — crisp nearer-side/body color; the detailing ops are value-type-only (the morph precedent), columns gets block forms; they assume frankly-crossing surfaces — near-parallel faces within the radius echo the pattern, the documented envelope), and `.rounded`/`.onion`/`.at`/`.rotated`/`.scaled`/`.stretched`/`.colored`/`.mirrored`/`.repeated`/`.repeatedRadially`) draws via `drawSDF(_:)` honoring the current fill/stroke/CTM, the stroke tracing the *merged* outline; the scoped **block forms** (`smoothUnion(k:){ … }` + hard/mirror/repeat variants, and the stateful **`sculpt { }`** block whose `add()`/`carve()`/`blend(_:)` verbs mutate per-child mode/melt mid-block — built for the live-coding loop) capture bare region draws at `Drawer.appendSDF` as leaves, reaching **every** fillable region shape. - **User-supplied shaders** (`Sources/Ollin/Effects/Shader.swift` + the wrapper/compile/error path in `MetalRenderer`). A sketch writes its own fragment shader and runs it through the effect graph. The contract is **Ollin-native, not raw Metal**: define `float4 shade(float2 uv, ShaderInfo info)` (uv 0…1 top-left, return straight sRGB — input layers are read back as straight sRGB too) and Ollin generates the surrounding fragment + vertex. the evolved state carries), and **Lenia** is the paper-faithful continuous CA (exponential kernel core in up to 3 β-rings, **normalized in-loop by the summed weight**, gaussian growth, clipped dt integration; Orbium defaults R=13/T=10/μ=0.15/σ=0.015) whose dying / labyrinth / rings / maze looks are all real regimes — **seed it densely** (sparse mass starves, the documented envelope, not a bug); **`.ripples`** is the height/velocity interactive-water kernel (state h in r, v in g, both signed; 6 substeps; clamped taps, soft absorbing border rim) whose **per-sim inject is load-bearing**: `Sim.injectFragment` routes it to `ollin_sim_inject_height`, which *adds* the drawn mark's premultiplied luminance to height only — the generic replace-by-alpha inject pins the surface and writes color into the velocity channel (the exact bug that parked the 2026-07-07 attempt, see [[ollin-ripples-sim-parked]]); the **coupling gain `speed` must stay under 2** (clamped to 1, default 0.5): 2 is the CFL boundary where the Nyquist checkerboard sits on a repeated λ=−1 root and grows linearly, settling ~22× the ring amplitude under any damping and shading into glitter — substeps went 3→6 so the ring pace is unchanged (wave speed ∝ √gain); soft radial-gradient dabs are the drop contract (hard discs legitimately ring at every frequency), and the raw `image` is a debug view (shade with `.relight`); **`.sandpile`** is the Bak-Tang-Wiesenfeld toppling CA on the generic single-texture step path (no dedicated pipeline; Dhar's abelian property licenses any parallel schedule, and `SandpileTests` pins the settled pile **cell-for-cell against a sequential CPU reference**, the edge variant verified red against its counterfactual) with five terse invariants: the step is the **k-fold parallel form** `q' = fract(q) + Σ floor(q_n)/4` — topple as many times as a cell can per pass, identical to single toppling in the critical regime but load-bearing at a hot source, where single toppling pools for thousands of passes (a saturated blob's interior is net zero: lose four, receive four back); grains stored in **quarters** (stable cells read 0/¼/½/¾, gradientMap-ready; exact in half float to 2048 grains), state **read from `.r` only** (a luminance dot is off by an ulp and the toppling floor/fract must be exact), boundary **open — reject the position before sampling, never wrap or clamp** (the clamping sampler reads the edge texel back as its own neighbour, a reflecting wall; on a torus sand accumulates until every cell topples forever), and the inject **adds `rint(luma·pour)` whole grains** (an AA fringe pours whole grains or none; nothing erases); `topplings` is `subSteps`, the pacing dial (an avalanche front moves one texel per pass), the **classic relaxed figure is drop-and-relax** (one heavy mark on one frame, then settle — a steady heavy pour keeps a molten super-critical core by design), and `runSimulation` binds **`sim.params` to the inject pass too** (pre-existing injects read none — byte-identical); **`.relight` measures slope over a span, not a texel** (taps on the half-texel grid for a free 2×2 box, gain divided by the span, span growing with resolution past 1080) — slope weights a wavelength by 1/L, so a per-texel Sobel lights few-texel content as steeply as the real relief; smooth relief is preserved to ~1% (`effects-relight` did **not** need re-recording). **Don't soften a finish's specular exponent to chase speckle** — a broad lobe lifts the highlight on *flat* areas too (a `pow(sh,60)` `.liquid` washed the Guide's Organism background several shades lighter), so fix the normal, not the lobe; headless `image(of:frame:)` renders *every* warmup frame when `drawer.usesFeedback` (feedback / sim fields / SSR — else the ping-pong never evolves); fluid keeps its own `fluidSlots` beside `FeedbackSlot` so the single-field sims stay byte-identical; **`.multiScaleTuring`** is McCabe's rule (activator/inhibitor disc averages at several scales, least-disagreement scale fires, renormalize each step) and runs its **own multi-pass pipeline** (`runMultiScaleTuring`) like the fluid while sharing the one-pair `FeedbackSlot` (so flip/prune/repeat are the shipped ones), with four load-bearing pieces, each of which was a real defect first: the field **starts as seeded noise, not a constant** (a flat field is a fixed point of the rule, so `feedbackSlot` grew a `fill:` override beside `restState`); the blur pyramid is **Gaussian (Burt-Adelson binomial), not a 2x2 box** (a square kernel has square preferred directions, so the labyrinth came out rectilinear); a radius **gathers a 9-tap disc two rungs *finer* than the radius match**, never a single tap at the matching rung (that rung holds one sample per feature, so the pattern locks to the lattice, unfixable by any kernel since the information isn't there); and **variation is averaged over a per-scale `variationRadius`** (read at a point, a fine scale's disagreement crosses zero along every contour of its own structure and, since *least* disagreement wins, it claims a dense web of pixels and buries the coarse scales). Two parameter facts are equally load-bearing because renormalization couples the scales: **equal `amount`s across rungs** (the hardest-pushing rung sets the range and squeezes the rest toward mid gray) and a **ladder starting at radius 2** (radius 1 works on single texels and reads as speckle). `TuringScale.maxScales` (6) must equal `OLLIN_TURING_MAX_SCALES`, and `MetalRenderer.turingPyramidLevels` (12) must equal `OLLIN_TURING_LEVELS` (it sizes the texture-array binding; a shallower pyramid repeats its top rung to fill it). Deliberate v1 cut: the winning-scale index is **not** carried in the state (colour-by-scale would muddy a channel the display and the extent reduce both read as gray); `layer(_:)`'s draw closure is `@escaping @_implicitSelfCapture` (without it, bare draws inside `layer { }` need `self.` and the p5 feel breaks); SSAO's and SSR's stabilizer sets each fixed a worse artifact — don't undo any of them ([[ollin-ssao-normal-gbuffer-followup]], [[research-before-implementing]], [[verify-perceptual-temporal-fixes]]); DoF/SSAO/SSR `quality` is a `RenderQuality` tier resolving to a per-GPU budget (DoF: the bokeh *tap* budget via `resolveDofTaps` — M2 1080²: `.default` 192 ≈ 14 ms; **benchmark back-to-back on a cool machine**, single runs drift 50% under thermal load, enough to invert an A/B). **`.defocus` is two passes:** a **pre-pass** reduces the aux depth to `(scatter, depth, receive)` per pixel and the gather reads *that*, so a tap is one sample and no math (~35% faster than decoding depth per tap). The two sizes answer the depth map's **anti-aliased rim** from both sides and are load-bearing: **receive** = neighbourhood **max** (the seam dilation, kills the dotted in-focus ring), **scatter** = neighbourhood **min at radius 2** (kills the hard-edged `maxBlur`-radius halo a *sharp* object leaked; radius 2 not 1, or the gather's bilinear averages half the rim back in). The gather's own rules: both accumulators seed with the **centre texel** (black-seeded near field composites a dark ring at partial coverage), **alpha rides with the colour** (premultiplied layers), a farther tap is **occlusion-clamped to 2× the centre's blur** (else a heavy backdrop dissolves a barely-defocused midground for the full `maxBlur`, the pop that made a rack unwatchable), compositing is **far first, near over it** (`mix(mix(centre, bg, dof), fg, α)`; one `max(dof, α)` mix double-applies the coverage), a pixel **under a near blur lets the bg field gather from inside that blur** and **fg coverage is an area fraction of the *near* blur, not the disc** (`total·(r/maxBlur)²`) — without both, a foreground blurs outward but keeps a razor *inner* edge (a 40% step in one pixel). The snapshots' mean-diff tolerance averages every one of these away (they all live in a band around a silhouette), so **`DefocusTests` pins them behaviorally** — reach for a probe here, not a whole-frame diff. - **GPU artificial life** (`Sources/Ollin/Compute/SpatialHash.swift` + `ParticleLife.swift` / `PPS.swift` / `Physarum.swift`). The compute path's first *cooperative* primitive + three emergent-behavior sims on it. **`SpatialHash`** (public) is a GPU uniform-grid fixed-radius neighbor search (Hoetzlein **counting sort**: clear → count → serial exclusive-prefix-sum → scatter, the four kernels sharing one source); it's the enabler `ParticleLife`/`PPS` query and a sketch builds its own sim on via the `neighborStep(_:over:reading:writing:)` facade + the `OLLIN_FOR_NEIGHBORS` macro. **Load-bearing:** the shared struct is **`OllinSpatialGrid`** in `OllinShaderTypes.h` (stride 32; **distinct from the pre-existing `OllinGridParams`**, the 3D ground-grid uniform, whose name it must not reuse); the grid/neighbor helpers (`ollin_grid_cell`, `ollin_torus_delta`, the `OLLIN_FOR_NEIGHBORS`/`OLLIN_END_NEIGHBORS` macro pair) live **unmarked** at the tail of `OllinShaderLib.metal` so `filterLibModules` always keeps them (compute-only; never bloats a user fragment shader's `using:` subset); cell edge = query **radius** over a **toroidal** domain so all in-radius neighbors sit in the wrapped **3×3** block, which needs `gridW`/`gridH` **≥ 3** (init clamps, so `worldSize` may round up past `bounds`) or the wrap double-counts a cell; **atomics** power the count/scatter (`atomic_fetch_add`) and never appeared in this codebase before, and the **serial compute encoder** (default `makeComputeCommandEncoder()`) orders the build passes with no explicit barriers (same as `Simulation`'s substeps); buffer-index contract `0/1` particles read/write, `2` sortedIndices, `3` cellStart, `4` cellCount, `5` grid, `6+` sim-specific (`ParticleLife`'s matrix at 6); `nil` gaps in a `RecordedDispatch.buffers` array bind nothing (index = array position). All three sims reuse **`OllinParticle`** (no new struct): type/heading ride the free `seedA` scratch; each is a `@MainActor final class` recording its step by appending `RecordedDispatch`es directly (the `Particles.recordStep` model, **not** the 1-2-buffer `compute()` facade). `Physarum` uses **no hash** (trail path): agent buffer + `r32Float` **`PingPongTexture`** trail + an **atomic `UInt32` deposit grid** (fixed-point, avoids Metal's undefined concurrent-`texture.write` race), stepped clear→agents(sense/steer/move/deposit)→diffuse+decay→colorize; draw via `.image`. **Load-bearing anti-lattice-artifact trio:** **bilinear** trail sensing + a **per-step motor noise** (heading jitter) + a **1-2-1 Gaussian** diffuse (not a box mean); without them the faithful-Jones steering (which keeps heading exactly when all three sensors read equal, i.e. in the empty region an agent forages into) sends escaping agents ballistically straight, and those coherent parallel escapes self-reinforce on the square lattice into **cardinal-axis spurs** (the motor noise is the decisive one, turning the ballistic escape into an even-spreading wander). **Reproducibility caveat (load-bearing):** the counting-sort **scatter order within a cell is GPU-atomic-race-ordered** and the sims are chaotic, so there's **no frame-exact export guarantee and no pixel snapshot** (matching the compute path); correctness is pinned instead by `SpatialHashTests` (`hasMetal`-gated: counts sum, exact prefix sum, `sortedIndices` a permutation, per-cell bucketing, and a neighbor **set** matching brute force — all order-independent). Facade factories `spatialHash(in:radius:count:)` / `particleLife(count:kinds:radius:…)` / `primordialParticles(count:radius:…)` / `physarum(agents:resolution:…)` default `bounds` to the canvas and `seed` to `variation`. `Docs/Simulation/ArtificialLife.md` + `Docs/Shaders/Compute.md#spatialhash`; examples `Simulation/ParticleLife` / `PrimordialParticles` / `Physarum` + `Compute/NeighborSearch` (the raw primitive, the one example that `import COllinShaders` for `OllinParticle`, wired via the extended `example(…, dependencies:)`).

- **GPU fluids & soft bodies** (`Sources/Ollin/Compute/ParticleFluid.swift` + `SoftBodies.swift`). Particle dynamics in a walled box over `SpatialHash`, reusing `OllinParticle`; shared header structs `OllinSPHParams` (stride 112) / `OllinSoftBody` (32) / `OllinSoftBodyParams` (64). **`ParticleFluid`** is 2D SPH (Müller 2003 symmetrized EOS pressure + Clavet 2005 near-density/near-pressure for anti-clumping and emergent surface tension; quadratic/cubic spike kernels normalized for 2D by integration): per substep, predict (gravity + one-frame `pull`/`push`) → rebuild hash over **predicted** positions (fixed 1/120 s look-ahead) → density pass → force/integrate pass, all **pure gathers** off one snapshot so pair forces cancel equal-and-opposite with no atomics. **Load-bearing:** densities are normalized to the *seeded lattice* (`restDensity` 1 = as packed, knobs survive a radius change); the box is **walls, not a torus** — kernels use plain deltas and the `r < h` test rejects the wrapped 3×3's cross-wall candidates (safe because the hash world rounds down by less than one cell); the velocity clamp (0.45·h per substep) makes tunneling impossible, so a hitch can't detonate the sim; wall under-density compression is countered by near-pressure (raising `nearStiffness`, not clamping pressure, is the intended lever). **`SoftBodies`** is meshless shape matching (Müller 2005): a serial one-thread-per-body reduce (the prefix-sum trade) fits centroid + closed-form 2D rotation, then particles steer to rotated rest offsets at `squish` (converted per substep, feel is frame-rate-independent); contacts are **cross-body only** and inelastic (overlap repulsion + each side sheds half the approach speed). **Load-bearing:** rest offsets are taken about the **rest centroid** (the lattice mean, not the disk center) — anything else leaves `Σ(goal − x) ≠ 0` and the body silently self-thrusts (a real bug: blobs hovered and pinned into corners; pinned by `FluidDynamicsTests.isolatedBodyConservesMomentum`); spawns separate via `relaxCircles` before particle fill (an overlapped spawn explodes). Both run fixed substeps against a clamped frame clock (≤ 1/30 s), pack params at buffer 11 per substep, and follow the artificial-life reproducibility rule (**no pixel snapshots**; behavioral `FluidDynamicsTests`). Facades `particleFluid(count:radius:)` / `softBodies(count:radius:)` + `updateParticleFluid` / `updateSoftBodies` / `drawParticles` overloads default `bounds` to the canvas and `seed` to `variation`. Examples `Simulation/ParticleFluid` (dam break, drag to grab) + `Simulation/SoftBodies` (jelly pile, drag to knead). `Docs/Simulation/Fluids.md`.

- **Image as input** (glyph mosaic `Sources/Ollin/Text/GlyphMosaic.swift`, pixel sorting `Image/PixelSort.swift`, single line `Geometry/SingleLine.swift`, slit scan `Image/SlitScan.swift`, halftone `Image/Halftone.swift`). - **Data as input** (`Sources/Ollin/Data/Table.swift` + `JSON.swift`). The load-once material for data-driven drawing: **`loadTable`** reads CSV/TSV into a **`Table`** (a `RandomAccessCollection` of `Row`s; `row["col"]` / `row[2]` plus `number`/`int`/`bool`/`color` and their `at position:` twins, `column(_:)` / `numbers(_:)`) and **`loadJSON`** reads a document into **`JSON`** (a `@dynamicMemberLookup` enum; reach by key/index then ask `.string`/`.number`/`.int`/`.bool`/`.color`/`.array`/`.object`/`.keys`/`.count`/`.isNull`). Both follow the palette-importer posture: **total decode, `nil` rather than a throw or a trap**, and `resource:in:` with **no default bundle** (the framework-wide rule). **Load-bearing:** the CSV parse is the published format as a **byte scanner** (every byte it compares is ASCII and no byte of a multi-byte UTF-8 character can be mistaken for one, so cell text rides through untouched), and its case order is too: **separator and line endings are tested before the after-closing-quote whitespace case**, since a tab is both a separator and whitespace and the separator reading must win (a TSV silently lost a column otherwise); the **BOM is stripped** or it joins the first column's name invisibly and every lookup of that name fails; a **quoted cell is verbatim while an unquoted one is trimmed** (quoting is how a file says it means the spaces, and the whitespace on either side of the quotes is not part of the cell); the blank-line rule **keys on whether the record held quotes**, because a line holding `""` is a row where a truly blank line and the newline closing the last real row are not (dropping it left a 0-row table that crashed the suite's first `table[0]`). Two things are guessed and **an explicit answer overrides each** (the `palettePerLine: Bool?` precedent): the separator (most frequent of comma/tab/semicolon/pipe on the first line, **outside quotes**) and the header (**a first row holding no numbers**). `numbers(_:)` **drops** non-numbers (a series to scale by) while `column(_:)` **pads to the row count** (stays row-aligned) — the one place the two reads deliberately differ. Rows share **one** name-to-position map by class reference rather than each copying a dictionary, and a repeated column name resolves to the first. JSON: a **missing key reads as `.null`** so a path chains without a check at every joint, `.array`/`.object` are **non-optional** so a loop over an absent key runs zero times, and `true` is told from `1` by **`CFBooleanGetTypeID`** (the system reader hands both back as an `NSNumber` holding 1). Deliberately small: a document with a shape worth naming is `Codable`'s job, and the docs say so. Examples `Data/Readings` (a CSV as a range chart, notes holding commas and doubled quotes) + `Data/Places` (a JSON survey, a station with no color landing on the fallback); `TableTests` / `JSONTests` (no pixel snapshot: both are CPU value types). Guide Ch 7 § *Numbers you didn't type* + DataAsMaterial figure. `Docs/Helpers/Data.md`.

- **Physics** (`OllinPhysics` satellite). One `World` stepped each frame, hybrid by design: a **soft Verlet side** (`Particle` — a `final class`, no stored velocity, `previous`-based; `Spring`, a positional distance constraint; `World` with gravity / drag / bounds / bounce / opt-in disk `collisions` broad-phased through a uniform spatial hash) and a **rigid side** backed by **vendored Box2D** (MIT, `External/CBox2D`) — `addBody` / `Body` / `Collider` (`.circle` / `.box` / `.capsule` / `.polygon`) / `connect` / `Joint` (`.revolute` / `.distance` / `.weld` / `.prismatic`) / `grab` (mouse joint), sharing the world's gravity / bounds / bounce / drag, bridged by `pixelsPerMeter`. **Gotchas:** `drag` compounds per step (a weightless drift field needs `drag = 0`); Box2D's world pool is a non-thread-safe global → every Box2D-touching test in one `@Suite(.serialized)`; spawn a `Body` *inside* `bounds`, not above; disk-collision resolution walks particles in **index order with a fixed cell scan** — never iterate the spatial-hash Dictionary directly (per-process hash order reordered the position-mutating pair resolution, so a seeded pile settled differently on every run; a real Guide-figure flake). Examples `Physics/Packing` + `Blobs` (soft), `Stack` / `Tumble` / `Chain` (rigid); `Docs/Simulation/Physics.md`. **The 3D rigid side** (`World3D.swift` / `Body3D.swift` / `Joint3D.swift` / `Sketch+Physics3D.swift`, backed by **vendored Jolt Physics** — MIT, `External/CJolt`, C++ behind Ollin's own `extern "C"` bridge, the *only* code that includes Jolt headers, so the `JPH_*` define-consistency rule holds by construction): `World3D` (eager handle, `gravity` y-up, `ground` slab, `bounce`, `maxTimestep` clamp, `unitsPerMeter` **default 1** — scene units ≈ meters, unlike 2D's 100) / `addBody` with `Collider3D` (`.sphere` / `.box` / `.capsule` / `.cylinder` / `.taperedCapsule` / `.taperedCylinder` / `.cone` / `.hull` / `.mesh` / `.heightfield(Heightfield, width:depth:height:)` / `.compound([Part])` — **mesh and heightfield colliders are static-only**, a dynamic one is pinned with a one-time note) / `connect` with `JointKind3D` (2D's kinds + `.ball`) / `grab`, and the sketch sugar `withBody(_:)` (pose via `withState` + translate + quat→angle/axis `rotate`, so replay/export/materials all apply untouched) + `body(under:in:)` / `grabBody(at:in:)` / `dragGrab(_:to:)` (camera ray-pick; drags in the screen-parallel plane at the picked view depth). **Load-bearing:** never pass `&tuple.0` across the C boundary — the compiler may materialize a temporary for that one element and silently drop every value the C side writes past it (a real bug: positions read back with y/z stuck at 0 while the sim ran perfectly); all marshaling goes through `CJoltInterop.swift`'s `withUnsafe(Mutable)Bytes(of:)` helpers. **The grab is the reference drag model and must stay it**: a *static* anchor body created but never added to the world, *teleported* per move (velocity stays zero), holding the body on a zero-length distance spring (frequency 2, damping 1) — a kinematic anchor driven by `MoveKinematic` feeds its arrival velocity into the constraint and pumps the body into orbit (a real bug). Jolt keeps **no global world pool** (only an init-once type registry behind `call_once`), so the 3D tests run parallel — no `.serialized` needed, unlike Box2D's. **No pixel snapshots for 3D physics** (the artificial-life precedent): determinism is per-binary — the same build replays byte-identically (test-pinned, incl. across thread counts) but a toolchain rebuild may shift ulps and chaotic scenes amplify them; behavioral `RigidBody3DTests` pin the solver instead, and the Guide's CrateFall figure freezes one collapse. **Joint motors, limits & springs** (stage 2): `.revolute`/`.prismatic` take `limits:` (a `ClosedRange` **relative to the connect pose** — that pose is 0, so the range must straddle it; hinge clamped to min ∈ [-π, 0] / max ∈ [0, π], the solver's window) and the returned `Joint3D` carries `drive(at:strength:)` (velocity motor) / `drive(to:frequency:damping:strength:)` (spring-servo position motor, upstream defaults 2 Hz / damping 1) / `stopMotor()` / `friction` / `softenLimits(frequency:damping:)` / the `angle`/`offset` readbacks. **Load-bearing:** `cjolt_constraint_set_motor` **wakes both bodies** (a sleeping pair never feels a motor change — a late-engaging door closer would hang open forever); joint `friction` applies **only while unpowered** (the solver's contract — one knob is both stiff-hinge drag and the post-`stopMotor` coast-down brake); slider targets/offsets convert by `unitsPerMeter` while angles and the N·m / N effort caps pass through; the motor calls no-op with a one-time note on undrivable kinds (bridge switches on `GetSubType`, so no Swift downcast can mis-drive). `JointMotor3DTests` pins every knob against its counterfactual twin. **Compound & world-geometry colliders** (stage 3): `.compound([Part])` fuses shapes into ONE body via `.part(_:at:rotated:axis:density:)` (part `density` **multiplies** the body's; parts nest; the Windmill's blade cross is the proof — five shapes, one body, drawn by a recursive part walk in `withBody`); `.heightfield` takes a `Heightfield` **sized exactly like its `mesh(width:depth:height:)`** so collider and drawn mesh trace one surface (resampled onto the smallest power-of-two grid covering the source cells, 4…1024 per side, 16-bit samples; beyond the edges is void); `addStaticColliders(from: Scene)` walks `Scene.visitWorlds` (now `package`) baking each mesh node's **composed world transform into the triangles** (scale/shear included) as one static mesh body at identity. **Load-bearing:** `mAllowDynamicOrKinematic` must be **false for any `MustBeStatic()` shape** — allowing the switch makes body creation compute mass properties the shape cannot provide and the library *traps* (latent stage-1 bug: nothing had ever created a `.mesh`-collider body until the stage-3 tests); the static pin asks the created shape, never the descriptor type. Shape marshaling goes through `ShapeDescArena` (arena-owned allocations held with `withExtendedLifetime` across the create) because compound children make the pinned-buffer count data-dependent — fixed `withUnsafeBufferPointer` nesting can't express it. `Collider3DTests` pins the tier (compound mass/balance vs counterfactual twins, part poses, cone = ⅓ cylinder mass, heightfield mappings, scene-collider composition, byte-identical replay). **Contact events & sensors** (stage 4): every touch that started or stopped during a `step` lands in **`world.contacts`** (`Contact3D`: `phase` / `a` / `b` / `point` / `normal` / `speed` + `involves`/`other(than:)`), polled in `draw()` like mouse state, with the per-body views `contacts` / `entered` / `exited` / `touching` / `isTouching(_:)`; **`addBody(…, isSensor: true)`** makes a detector region that reports overlaps and pushes nothing. **Load-bearing:** the listener fires on solver worker threads mid-`Update`, so the bridge's mutex-guarded `ContactRecorder` buffers flat-POD events the main thread drains after `cjolt_world_step` returns (never a callback into Swift, the render-thread rule's C cousin); the buffer **collapses sub-shape pairs into body pairs** by reference count (a crate on terrain reports one landing, not one per triangle) and **sorts before draining** (worker-thread record order is nondeterministic; the Swift `touching` lists are sorted arrays, never `Set`s, for the same reason); `speed` is the **pre-solve** closing speed `(v1 − v2)·n` (the manifold normal runs a→b), and an `ended` event carries **only the pair** (`OnContactRemoved` may not touch the bodies at all, one may be destroyed) so its point/normal/speed are zero and an event naming a removed body is dropped *after* its bookkeeping applies; a **sensor is kinematic and never sleeps** whatever `kind` was asked for (a *static* sensor loses the contact the moment a body settles, which would empty a pressure plate) and lives in its own object layer pairing only with moving bodies, so `sensor.touching` answers standing occupancy where **an ordinary settled pile sleeps and stops reporting** (Jolt's model, pinned deliberately against its sensor twin); sensors are invisible to ray picking (`NonSensorBodyFilter`) and `Body3D.kind` refuses to change one (`noteOnce`); the `ground` slab is now a registered-but-unlisted **`world.groundBody`** (in the id map so a landing names a body, out of `bodies` so no drawing loop skips a 1000-unit box). `Contact3DTests` pins it against counterfactual twins (sensor pass-through vs solid deflection, one event per pair vs two loose bodies, √(2gh) impact speed, read-twice-not-drained, no stale touches after a removal, identical replays). **Characters** (stage 5, `Character3D.swift`): **`world.addCharacter(radius:height:at:)`** is a walking figure driven from `draw()` — `move(_:)` sets the horizontal velocity it's *trying* to walk at (held until changed), `jump(_:)` is granted only if it's on the ground at the next step, and `world.step` sweeps every character along with the bodies (no second update call); readbacks are `position` (the **feet**) / `isOnGround` / `groundState` / `groundNormal` / `groundBody` / `groundVelocity`, the knobs `stepHeight` / `maxSlope` / `pushStrength` / `mass` / `facing`, and the sketch sugar **`withCharacter(_:)`** (feet + facing, `withBody`'s twin). **Load-bearing:** a `CharacterVirtual` is a shape swept by hand, **not a body in the world**, so it needs its own bridge object (`CJoltCharacter`) and its own update call — run **before** `cjolt_world_step` (the reference's order) via **`ExtendedUpdate`**, the one that does stair-stepping and stick-to-floor (both distances are its *arguments*, so the wrapper holds them, not the character); the capsule is built **bottom-at-origin** through a `RotatedTranslatedShape` so `position` is the feet, and `mSupportingVolume` is `Plane(up, -radius)` so only the lower cap can hold it up (a hand brushing a wall is not ground); `isOnGround` reads **`GetGroundState`**, never a normal test. The **velocity composition is the library's own recipe** and lives in Swift (`advance`): on the ground it inherits `groundVelocity` (so a moving platform carries it, pinned) and only then may a jump be added, in the air it keeps just its vertical, gravity is added, and the walking velocity is added last and always (air control on, no inertia smoothing — the sketch owns input feel). **`velocity` is intent, not outcome** — the library never writes back the achieved velocity, so a character pinned against a wall still reads a full walking pace; **`actualVelocity`** is derived from the step's position delta (the reference's "effective velocity") and is what a walk cycle must read. **Every character always carries an inner kinematic body** (`character.body`, 0.9× scale, `Layers::MOVING`): it is what gives the character presence among the ordinary bodies, so the stage-4 contact/sensor surface, ray picking, and tunneling protection all work on it — registered in `bodyByID` but kept **out of `world.bodies`** (the `groundBody` precedent, so no drawing loop renders a capsule over the sketch's own figure); characters register in a `CharacterVsCharacterCollisionSimple` so they collide with each other. **`stepHeight` is a probe distance, not a hard ceiling** (the rounded foot rides an edge first, so a ledge ~25% taller may still be climbed — test with a margin, don't fake precision); **`pushStrength` (N) vs ground friction decides a shove** (4 kg crate moves under the default 100 N, 43 kg does not); a slope just past `maxSlope` reads `.onSteepSlope` but a near-vertical face reads `.notSupported`. `Character3DTests` (19) pins each knob against its counterfactual twin (same ramp, one `maxSlope`; same ledge, one `stepHeight`; same crate, one `pushStrength`), plus platform carry, sensor entry, teleport-rereads-ground, and identical replays. (Fixed alongside: `World3D.removeAll()` emptied `bodyByID` while `groundBody` still pointed at the slab, so floor contacts were dropped and a character's `groundBody` read nil after a rebuild.)  **Vehicles** (stage 6, `Vehicle3D.swift`): **`world.addVehicle(_:at:wheels:)`** builds a driveable machine from a chassis collider plus `Wheel3D`s (`position` = the chassis-local mounting point, `radius`/`width`, `steers`/`driven`/`handBrake`, `suspensionLength`/`suspensionTravel`/`suspensionFrequency`/`suspensionDamping`, `brakeTorque`/`handBrakeTorque`, `grip`, `casterAngle`), driven from `draw()` by `throttle` / `steering` / `brake` / `handBrake` (all held until changed, `world.step` hands them over) with the knobs `engineTorque` / `topSpeed` / `wheelContact` / `maxTilt` / `antiRollStiffness` and the readbacks `speed` / `forward` / `up` / `rpm` / `gear` / `isOnGround` plus per-wheel `center` / `spin` / `steerAngle` / `isOnGround` / `groundBody` / `suspensionCompression` / `slip` / `slideAngle`; the sketch sugar **`withWheel(_:)`** poses a +y-aligned cylinder onto a wheel (`withBody`'s twin), and **`balances: true`** makes the leaning two-wheeler. **Load-bearing:** a vehicle is a **constraint on a body, not a body** — the chassis is an ordinary `Body3D` in `world.bodies` (so it collides, reports contacts, and is ray-pickable) and creating one must `AddConstraint` **and `AddStepListener`** (the wheels are collided and driven inside the step listener; without it the vehicle never moves, upstream's own warning), with the constraint destroyed *before* its chassis; the chassis takes an explicit `mass` and a **lowered centre of mass** (defaulting to the mean wheel-mount height) through two new `CJoltBodyDesc` fields, and the `OffsetCenterOfMassShape` wrap leaves `GetPosition` at the shape origin so drawing is untouched; **axles are derived from geometry, not list order** (`Vehicle3D.axles(of:)` sorts by `(z, x, index)` and clusters within a quarter of the wheelbase, so a two-wheeler gets two single-wheel axles where list-order pairing would fuse front and back), an axle with any driven wheel takes a differential and every full pair an anti-roll bar, and **at least one axle must be driven** (zero differentials trips the controller's own torque-split assert, so with nothing marked the rear axle takes it); **gearing is solved from `topSpeed`** in the bridge (top gear at max RPM turns a driven wheel that fast) rather than exposing ratios, and the sample's 10× `SetTireMaxImpulseCallback` hack is deliberately **not** adopted (defaults measured by a torque sweep instead); **every wheel setting except `driven` is live** via `cjolt_vehicle_set_wheel_settings` (one `applyWheelDesc` serves build and retune, `const_cast`ing settings the bridge alone owns and the solver re-reads each step; friction curves rebuild from a default tyre before `grip` scales them) while `driven` is the gearbox and is refused after construction with a note; the wheels' collision tester filters out the chassis **and sensors** (overriding the body filter replaces the default self-filter); and a **two-wheeler needs a real `casterAngle`** (~30°) or the balance controller cannot hold a line — note that running dead straight it stays up even unbalanced, so the counterfactual starts it leaned. `Vehicle3DTests` (19) pins each knob against its twin (the sharpest: two cars with slick fronts differing only in which axle is driven travel 2× apart), plus suspension sag, braking vs coasting, the hand brake locking only its own wheels, reverse braking through a stop, the gearing ceiling, wheels in the air, axle grouping, a leaned two-wheeler righting itself, and identical replays. (Fixed alongside: a `Character3D`/`Vehicle3D` a sketch still holds when its world goes now tears down safely — the world marks them destroyed on its way out.) **Ragdolls** (stage 7, `Ragdoll3D.swift` + `RagdollFit.swift`): **`world.addRagdoll(from: scene, at:joints:swing:twist:mass:friction:)`** turns a skinned `Scene` into a tree of rigid bodies (one per skeleton joint, hung on the new **`.swingTwist(at:axis:swing:twist:)`** joint kind) and **`scene.apply(ragdoll)`** writes the simulated pose back onto the skin, the inverse of `apply(_:at:)`; **`drive(toward: scene, frequency:damping:strength:)`** powers every joint toward the pose a scene is holding (the animation becomes a *request*), `goLimp()` cuts it, `pose(from:)` stands the figure back up, `limit(_:swing:twist:)` retunes one joint live, `applyImpulse(_:)` shoves the whole figure, `kind` switches it dynamic/kinematic/static; readbacks are `limbs` (`name`/`body`/`parent`/`collider`/the shape's pose inside the body) + `bodies` + `position` + `isAwake`, and the sketch sugar **`withLimb(_:)`** poses onto a limb's *fitted shape* (`withBody`'s twin). Built on the library's own `RagdollSettings`/`Ragdoll` for `Stabilize()` + constraint priorities + `DisableParentChildCollisions()`. **Load-bearing:** a limb's body stands **at its joint, not mid-bone** (the shape is pushed out along the bone via `RotatedTranslatedShape`), which is *why* the write-back is exact (body transform ≡ joint transform, pinned to 1e-5) and why a motor target is the skeleton's own local rotation; the **skeleton seam lives in the core** (satellites can't depend on each other) as `package` `Scene.skeleton()` / `skinnedVertices()` / `setJointWorlds(_:)` / `nodeWorldTransforms()` in `3D/SceneSkeleton.swift`, and `setJointWorlds` walks **top-down**, **keeps each node's scale** (a rigid pose has none; dividing it out shrinks the mesh) and **re-syncs a TRS animation base** to the posed transform (else a rotation-only track next frame drags the node back to its authored translation); **shapes are fitted to the mesh, not the bones** (vertices assigned to the limb weighting them most, in the joint's frame; axis = covariance's dominant eigenvector by power iteration seeded from the largest-variance axis, radius = 85th percentile of perpendicular distances, ends = 2nd/98th percentiles, so one stray vertex can't decide an arm's thickness) — the bundled figure fits a 0.157 torso against a 0.051 forearm from similar-length bones; mass splits by fitted volume then rebalances through `Stabilize()` (chain totals preserved); **the root has no constraint**, so a powered figure holds its *shape*, not its place (pin `limbs[0].body.kind = .kinematic` for the puppet-on-a-hook; `ragdoll.kind = .kinematic` routes `drive(toward:)` to `MoveKinematic` so it shoves what it walks through); the **target scene and the drawn scene must be separate copies** (a figure driven toward the scene it was just posed from has nowhere to pull); limbs are ordinary bodies registered in `bodyByID` but **kept out of `world.bodies`** (the `groundBody`/`character.body` precedent — the sketch draws the mesh), which needed `body(under:in:)` to look up `bodyByID` instead of `bodies` (also makes a character's stand-in and the ground slab pickable); each figure gets **its own collision group**, so a limb never fights its parent while two figures collide normally; joints not named in `joints:` **ride the nearest limb above them** with their pose and their share of the flesh. `Ragdoll3DTests` (22) pins it against counterfactual twins — the headline being one drop run twice, shape error 0.48 limp vs 0.034 powered. Asset authored by `Scripts/make-ragdoll-scene.swift` (a 16-joint humanoid + a looping wave animation). **Soft bodies** (stage 8, `SoftBody3D.swift` + the `package` `Mesh.welded()` seam in `Sources/Ollin/3D/MeshWeld.swift`): **`world.addSoftBody(from: mesh, at:rotation:axis:mass:stiffness:bend:pressure:damping:friction:bounce:iterations:vertexRadius:twoSided:pinned:)`** turns any `Mesh` into simulated particles (position-based dynamics; cloth that drapes, closed surfaces that hold air), read back as **`softBody.mesh`** (the source mesh with the simulation's positions + derived normals, cached per step) and drawn by the sketch sugar **`drawSoftBody(_:)`**; per-particle control is `pin` / `unpin` / `isPinned` / `move(_:to:)` / `nearestVertex(to:)`, the live knobs are `pressure` / `iterations` / `vertexRadius`, and the mouse pair is **`grabSoftBody(at:in:)` / `dragSoftGrab(_:to:)` / `releaseSoftGrab(_:)`** over a `Sketch.SoftGrip` (a *pinned particle*, since a constraint can't act on a soft body). Bodies live in `world.softBodies`, **out of `world.bodies`** (whose one-pose surface doesn't describe them; the `groundBody`/`character.body`/limb precedent). **Load-bearing:** **welding is a precondition, not a nicety** — Ollin's generators emit flat-shaded meshes whose triangles share no vertex index, so an unwelded soft body has no connectivity at all and falls apart into loose triangles; `Mesh.welded()` merges by position and the `remap` republishes results in the *source* mesh's order (the `MeshReactionDiffusion` precedent), which is what keeps uvs/colors/material intact. **Read-back normals follow the source mesh's own normals, not the winding** (a one-time area-weighted vote at build time against the rest shape; Ollin's catalog doesn't agree with itself here — `Mesh.plane` came back lit from underneath, the subdivision-surface lesson again). **All three knobs are normalized so one number means the same at any size:** `stiffness` maps onto compliance through `scale = meanEdge · √particleCount / (mass · gravity)` (the compliance at which one loaded edge stretches by its own length; a fixed compliance softens a heavy cloth and does nothing to a light one — pinned by `stiffnessMeansTheSameAtAnyWeight`), `bend` divides that same scale by **meanEdge²** (a fold constraint measures an angle where a stretch constraint measures a length, so it carries two fewer powers of length; without the correction the whole 0.2…1 range was already rigid), and `pressure` is the solver's `n R T` expressed as **outward acceleration in gravities** (`a = P·A/(m·V)` worked back through `ApplyPressure`, so `1` just holds the body's own weight up; refused with a note on an open surface, the closed test being every edge in exactly two faces). **Settling takes ~600 steps** — a 200-step probe read non-monotone and nearly flat, which is a measurement artifact, not the mapping. **The envelope is the library's** (not a shortcut): soft bodies collide with rigid bodies but **not each other or themselves** (a folded sheet passes through its own layers), they are **outside `world.contacts`** and `body(under:in:)`, impulses/joints/grabs don't reach one (hence `applyForce` for wind), and **there is no tearing** (a tear must split a shared vertex and rebuild the constraint set, impossible mid-simulation). `SoftBody3DTests` (19) pins it against counterfactual twins (pinned vs free, stiff vs slack stretch, bend-held vs limp droop, firm vs limp ball height/volume/shove, pressure inert on a sheet, drape over a sphere, wind, identical replays). **Water & buoyancy** (stage 9, `Water.swift`): **`world.water = Water(level:density:linearDrag:angularDrag:flow:waves:)`** floats every dynamic body below the surface with **no per-body opt-in** (the `ground` DX), plus `Body3D.buoyancy` (a multiplier on what density alone would do), `world.waterHeight(at:)` / `waterMesh(extent:resolution:around:)` / `waterPhase`, and `Water.Waves(amplitude:wavelength:speed:heading:)`. **Load-bearing:** buoyancy is an impulse the **caller** applies per body per step, not something the solver works out, so the loop lives in `World3D.step` **before** `cjolt_world_step` (the samples' `PrePhysicsUpdate` slot). The library takes a dimensionless factor (fluid density ÷ body density) rather than a density; the bridge forms it as `scale · density · totalVolume / mass` using **the `totalVolume` `GetSubmergedVolume` just returned**, never the shape's own reported volume, so the waterline lands where the displaced volume says (a body of density *d* settles with fraction *d* under, pinned to 0.08; the margin is what **sleeping** costs, freezing the body wherever its last oscillation reached). Ollin's relative `density: 1` already maps to 1000 kg/m³, so `Water.density` rides the same scale and a cork/stone falls out of the collider `density` a sketch already sets. **Waves are a per-body tangent plane** (the impulse takes a surface point + normal *per call*, the boat sample's own approach), the surface function lives in **Swift** with an **analytic** gradient, so `waterMesh`/`waterHeight` and the ridden surface are one source of truth (test-pinned per vertex); the envelope is that a body much larger than its wavelength is approximated. The query (`cjolt_world_bodies_in_box`, broad-phase `CollideAABox` sorted by handle) filters to **dynamic rigid non-sensor** bodies: a kinematic body (sensor, character stand-in) would be nudged off its driven path and the library's buoyancy **asserts on a soft body** (its documented gap, stated not faked). **Waking has three modes and needs them** (`CJoltBuoyancyWake`): a settled floater sleeps and holds its waterline exactly (correct, and free); a **swell** wakes only what its surface passes through (so a sunk stone sleeps on); a **changed setting** must wake everything afloat **wherever it is**, because the equilibrium moved (the first draft had only the swell rule and a probe caught it: raising the level 0→3 left a sleeping crate frozen at the old waterline, outside its own bounds, so it never woke). Water is an **ocean, not a pool** (everything below `level`, out to the horizon; a harbour is static walls). `Buoyancy3DTests` (20) pins it against counterfactual twins (cork vs stone vs no water, waterline vs density, brine, drag settles vs bobs forever, sleeper holds its level, tide reaches it, swell carries the top and lets the bottom sleep, current drifts, `buoyancy` both ways, sensors/soft bodies untouched, drawn surface == ridden surface, identical replays). **World queries** (stage 10, `Query3D.swift`): `raycast(from:to:)` / `raycastAll` / `sweep(_:from:to:rotated:axis:)` / `sweepAll` / `bodiesOverlapping(_:at:rotated:axis:)` / `bodiesContaining(_:)`, all taking `ignoring:` + `includingSensors:` and all answering the shared **`Hit3D`** (body / point / outward normal / distance along the query) between steps, changing nothing. **Load-bearing:** the C filter is a **struct** (`CJoltQueryFilter`: ignore list + `includeSensors` + `includeSoftBodies`) passed by pointer, so collision filtering lands as a *field* rather than a parameter on every call; **what a query is blind to is a decision, not an inheritance** — a sensor is transparent (a region to be inside, not a surface to hit; the mouse-pick rule) and a soft body is too (no rigid pose to hand back, matching `contacts` / `body(under:in:)`), while the ground slab / character stand-ins / ragdoll limbs **are** visible because hits resolve through `bodyByID`, which is what makes a ground probe and a sight check on a walking figure work; **the mouse pick is the same call** (`World3D.pick(from:to:)`, the internal ray with `includeSoftBodies` on) so there is one ray implementation, not two that can drift; a ray's normal needs a `BodyLockRead` (only the body knows which face the sub-shape id names), a sweep's is the negated penetration axis; the bridge returns how many hits it **found** (not wrote), so Swift sizes a 16-slot buffer and grows exactly once; `mesh`/`heightfield` probes are refused with a one-time note (`MustBeStatic()` asked of the *created* shape, the stage-3 rule). ## Live reload — edit code, see it render (shipped via `OllinLive`)

The headline creative-coding feature, and it's built. `swift run OllinLive <path/to/Sketch.swift>` opens a window, watches the file, and on save recompiles *just that sketch* into a `.dylib` and hot-swaps it into the running loop — the window never closes. This is the Olive / canvas-sketch model (a persistent host owns the window; the sketch is the swappable unit), chosen over InjectionIII (needs an external app, finicky on the terminal `swift run` workflow Ollin lives in). Code in `Sources/OllinLive/` (`main`, `FileWatcher`, `LiveSession`, plus `--selftest`/`--watchtest` headless smoke tests); the reusable loader `SketchLoader` lives in the **`OllinRuntime`** library (shared with the examples gallery, kept *out* of the shipping `Ollin` framework); the runner-side swap is `SketchRunner.reload(to:)` in `SketchView.swift`.

The mechanism (module-path discovery, the factory shim, FSEvents flags, threading, the `@Param` plumbing) is in [`ARCHITECTURE.md`](ARCHITECTURE.md) § *Live reload and the live-coding hosts*; the rules that must survive:

- **`-undefined dynamic_lookup` against the host, not a dynamic Ollin product.** **A `.dynamic` product does not fix the two-copies problem** — SwiftPM still links the target statically into the executable, giving two `Sketch` copies and a failed cast (verified the hard way). The `-I` module dirs are **discovered, not assumed** (the classic and Xcode build layouts differ), vendored C targets' checked-in module maps under `External/` are collected too (else a loose sketch can't `import OllinPhysics`), and each load uses a unique `-module-name` so repeated reloads don't collide in the objc runtime.
- **FSEvents on the *directory*, never an fd watch** (editors save atomically — temp file + rename; the `UseCFTypes` flag is required or the path-array cast crashes), debounced ~150ms, dispatched by extension: `.swift` → recompile + swap; `.metal` → shader reload; image assets → re-run `setup()`.
- **A broken edit never kills the session:** recompiles run off the main thread (the window keeps drawing the old sketch), a compile error leaves the running sketch alone, and shader reloads build the new pipelines before committing.
- **State on reload: fresh restart by default; `--keep-clock` carries `time`/`frameCount` forward** so an animation's phase doesn't jump (instance state resets either way). `Sketch.onReload()` fires once after the post-reload setup, never on first launch. `reload(to:)` honors the *new* sketch's declared `canvasSize` for non-`.resizable` modes.
- **Keep `Sketch`/`draw()` `open`** (already true) — the dylib subclass must override them; never `final`.

Window title: `"Ollin - <SketchName>"` (plain hyphen, not a middot). @eaviles ruled out FPS-in-the-title (the oF idiom); live FPS lives in the hosts' inspector surfaces (the OllinLive and gallery sidebars; standalone, the detached ⌘/ panel), not the title bar.

**Single-file sketches — the `ollin` command (`Scripts/ollin`), shipped.** One loose `.swift` file is a whole sketch, run from any directory: `ollin <file.swift>` opens it in the live host (all flags pass through, so every export flag works on the loose file), `ollin new [name]` writes an executable starter file (class named from the file name), `ollin install [dir]` symlinks the script onto PATH. **Load-bearing:** the script resolves the repo from its own symlink-resolved location and execs `swift run --package-path`, so a PATH symlink is the whole install and `git pull` self-heals on the next run — capture `${0:A}` at **top level** (inside a zsh function `$0` is the *function name*, a real bug) — and sketch paths are absolutized before handoff (the host process runs with the repo as its package, not the caller's cwd). **Hashbang:** `#!/usr/bin/env ollin` + `chmod +x` makes a sketch directly executable; `SketchLoader` neutralizes a leading `#!` to `//` **in place** (same length, so diagnostics keep exact line/column) and compiles from the work-dir copy, since swiftc allows a hashbang only in a main file — applies to `.file` *and* `.source` inputs (the live-coding editor buffer carries the line too). Pinned by two `--selftest` phases (hashbang renders; a broken hashbang sketch reports `Sketch.swift:5:`). `Docs/Tools/SingleFile.md`; the Guide's Ch 1 points at it.

**GUI / parameter knobs — shipped, typed.** The generic `@Param` wrapper/registry in the core (`Param.swift`) drives the shared inspector (`Inspector.swift`) in all three hosts; **the control follows the property's type** — `Double` slider / `Int` stepper / `Bool` toggle / `ParamOption` enum menu / `Color` well / `Vector2` fields (+ `style: .pad`) / `Vector3` / `Rectangle` / `Insets` / `ClosedRange<Double>` two-thumb slider / `String` field / `style: .segmented` / the **`ParamChoices`** named-catalog menu — through the type-erased `AnyParam` / `ParamControl` surface, so hosts never touch `Param<Value>`; `ParamValue` is public, so a user type can conform by mapping onto an existing control kind (no custom rows). `icon:` / `group:` decorate rows into titled group cards; numeric value boxes scrub (Option fine, Shift coarse, click to type). Rules: `ParamChoices` needs `Equatable` to find the current selection (why `Easing`, a closure wrapper, and the parameterized `Material` finishes stay out; `LightingPreset` conforms); knob values persist across reloads as `ParamStored` payloads (`syncParams`; a property that changed *type* drops its stale value so the new default wins); OSC/MIDI bind to `Param<Double>`, and smoothing stays Double-only. The SwiftUI layout gotchas (the scrub-pill `.fixedSize()`, the segmented ViewThatFits wrap) are in ARCHITECTURE.md. Headless gates: `OllinLive --paramtest` + `ParamTests`.

**Performance stats — a shared `FrameStats` feeding every host surface.** The runner fills one `FrameStats` (`@Observable`: fps, CPU frame time, draw counts, clock, canvas size) via the built-in `StatsExtension` on the extend seam; the OllinLive sidebar, the gallery's right sidebar, and — standalone — a detached frosted `NSPanel` (⌘/ via `OllinHUDCommands`) read it. A host with its own inspector sidebar opts the panel off (`SketchView(showsInspectorPanel: false)`) and omits `OllinHUDCommands`. Stats are *debug chrome, not in-canvas drawing* — SwiftUI siblings of the Metal view, so they never land in exports. Gotcha: the CPU-ms must time `performDraw()` *alone* — timing across `renderer.render()` includes the triple-buffer semaphore (vsync) wait and pins to ~1/fps, telling you nothing. `SketchView` `ZStack`s host chrome over a private `MetalCanvas` — the `NSViewRepresentable` MTKView, still the AppKit/UIKit-portability seam.

**Live coding — the performance host (shipped via `OllinLiveCoding`).** `swift run OllinLiveCoding [Sketch.swift]` (release wrapper `Scripts/OllinLiveCoding`) is the on-stage instrument: one window, the sketch letterboxed on a black stage, the code over it as translucent text (per-glyph backdrop strips, not a panel), ⌘↩ compiles the editor buffer and hot-swaps mid-motion (`keepClock` **on by default**; ⌘⇧↩ evaluates fresh), ⌘S is the only thing that writes the `.swift` (evaluate never saves; a crash-recovery autosave rides every evaluation). Load-bearing invariants, cheap to forget:

- **The shared engine lives in `OllinRuntime.SketchSession`** (supersede-cancel compile scheduling, `syncParams` re-applied *before* the swap so knobs never snap, the two-channel Swift-vs-shader error model where neither clears the other); `LiveSession` and `PerformanceSession` are thin wrappers over it — orchestration changes go in `SketchSession`, never re-forked per host.
- **Buffer compiles** write the editor text into the per-compile work dir *under the sketch's own file name* (diagnostics carry exact buffer lines and match by `fileName` — never by path, it's the temp copy), while the factory shim's `Bundle.module` keeps pointing at the sketch's *real* folder so co-located assets resolve. An untitled buffer compiles as a stand-in path under Application Support; save first if the sketch needs assets.
- **Letterbox at the SwiftUI layer only** (`.aspectRatio(_, contentMode: .fit)` around `SketchView`): the canvas view stretches to its frame and maps the mouse by bounds, so the aspect-fit frame is what keeps rendering *and* mouse coordinates exact.
- **No `.windowResizability(.contentSize)` here** (unlike the sibling hosts): fullscreen is the projection mode (`.fullScreenPrimary` via `WindowCustomizer`), the stage flexes, and status/error UI are *stage overlays* (chip, evaluated toast, diagnostics strip) because fullscreen hides the title bar. The error strip never dims the stage — the last good sketch keeps playing through a typo.
- **Editor rules:** the `NSTextView` owns the buffer (never mirror it into SwiftUI state); hide-code (⌃⇧H) is `.opacity` + hit-testing, never a structural `if` (that destroys the buffer and undo stack); every automatic substitution is off (a smart quote is a silent compile break); `keyboardFocus: .onClick` so the editor keeps the keys, and a canvas click intentionally hands them to the sketch.
- **Recovery is scoped to its document** (`recovery-origin` beside `recovery.swift`): an untitled buffer's net must never offer itself over an opened file (a real early miss — restoring replaced an opened sketch with old untitled work).
- Headless gates: `--selftest` (buffer compile → render → edit → differ, plus line-accurate diagnostic parsing; asserts the buffer path never writes the file) and `--sessiontest` (param carry, edited defaults, supersede semantics — the extraction's regression net for both hosts).

## Roadmap & design notes

Planned, in-progress, and eventual work is documented outside this file so the always-loaded guidance stays small:

- [`ROADMAP.md`](ROADMAP.md) — the public, contributor-facing roadmap: what's planned and how to help.
- [`DESIGN-NOTES.md`](DESIGN-NOTES.md) — the engineering design intent behind each planned item (the approach, the APIs involved, the reasoning).

**When work ships, it leaves these two files.** Drop it from `ROADMAP.md` (the roadmap stays forward-looking — what's *planned*, not a changelog) and record it instead under *Current state* above. Remove it from `DESIGN-NOTES.md` too, unless its design rationale still guides future maintenance or evolution (e.g. the conventions for extending the examples set), in which case keep only that part, not the status narration. Anything fully done and self-contained belongs in its own `Docs/` page or this file — not the roadmap, not the design notes.

**No status words in `ROADMAP.md` / `DESIGN-NOTES.md`.** They describe only what's *ahead*: never write "X landed / shipped / done" or a changelog aside into either file — a reader shouldn't be able to tell from them what shipped yesterday versus a year ago. When the shipped thing is one entry in a still-open *umbrella* item (the SDF shape catalog, a family of helpers), **drop just that entry and keep the umbrella** — don't annotate it as landed. (The `drawTriangle` commit got this wrong: it rewrote the catalog bullet to announce the triangle "has landed" instead of silently dropping it — the exact narration this rule forbids.) The ship checklist, every time something lands: **(1)** add it to *Current state* in this file; **(2)** remove it from `ROADMAP.md` (drop the entry; for an umbrella, the sub-entry only) with no "landed" note — and the README's Roadmap section is a short pointer with a one-line "what's ahead" list, so drop the item there too if it's named; **(3)** strip it from `DESIGN-NOTES.md`, keeping only rationale that still guides future work; **(4)** if it adds user-facing API, give it a `Docs/` page *and* wire it into both indexes in the *same* commit — `Docs/README.md` (the flat annotated index, one grouped entry per page) and the README, which links **by capability** through its *What's in it* catalog table, so a new page joins the table row it belongs to (or the short "good places to start" list) rather than a flat enumeration. **The invariant is that every `Docs/` page stays reachable from the README** — it broke once when that flat list was slimmed and orphaned 21 pages, so check it (`comm` the README's `Docs/…md` links against `find Docs -name '*.md'`) rather than eyeballing. A commit that introduces a public concept but leaves `Docs/` untouched is missing its page; purely internal changes (a refactor, a renderer tweak) skip this and live only in *Current state*; **(5)** if it adds a user-facing capability, **teach it in the Guide, don't just list it** — give it a row in the feature-coverage matrix (`Guide/PLAN.md`) naming its chapter home, clear its parking-lot entry, and get the row to at least **`shown`** (a chapter mention plus a worked example) *in this commit*, with `taught` (a section plus a figure) the goal. A row left at `pointed` is Guide debt and needs an entry in the ledger in `Guide/PLAN.md` naming the chapter that owes it, called out in the commit message. **`Scripts/guide-coverage.sh` is the gate** (it fails on a `pointed` row with no debt entry, a Docs page with no row, and a page unreachable from a numbered chapter); the rationale and the authoring workflow live in `Guide/AUTHORING.md` § *Coverage*. A row marked `pointed` used to satisfy this step outright, which is how seven slices shipped un-taught while audits stayed green. **A renderer change moves Guide figures even when the diff never touches `Guide/`** — run `Scripts/guide-figures.sh` after any change to the drawing paths and commit the re-renders with it, or the next Guide-touching commit inherits unexplained churn (the stroke-join work moved 79 figures by a sub-perceptual ~2/255 at their joins, invisible to the snapshot suite's mean-diff tolerance but not to a byte comparison). Do all of this only once the work is actually verified (built and run) — don't pre-narrate unbuilt work as shipped.

Both live at the repo root, alongside `README.md`. The convention: the root holds project meta and contributor docs (`README.md`, `ROADMAP.md`, `DESIGN-NOTES.md`, [`ARCHITECTURE.md`](ARCHITECTURE.md), `AGENTS.md`, this file, `LICENSE`, `ATTRIBUTION.md`, `THIRD-PARTY-NOTICES.md`), while [`Docs/`](Docs/) is the user-facing API reference (`Sketch`, `Drawing`, `Color`, …) plus `Docs/Tools/` for the user-facing host-app guides (live coding) — and nothing else. The third doc tree is [`Guide/`](Guide/), the narrative book: a practical creative-coding guide taught through Ollin, written chapter-by-chapter across sessions. Its authoring charter is `Guide/AUTHORING.md`, its chapter queue + briefs + feature-coverage matrix `Guide/PLAN.md`, its figures rendered/verified by `Scripts/guide-figures.sh` — guide facts route there, not here. `ARCHITECTURE.md` is the contributor-facing engineering-internals doc (the *how* and *why* of shipped systems, the home for depth that would otherwise bloat this file); `DESIGN-NOTES.md`/`ROADMAP.md` stay forward-looking, `Docs/` stays user-facing, so `ARCHITECTURE.md` is the one place shipped internals belong. Keep these at the root (don't fold them into a `Notes/`-style folder): several are auto-discovered or front-page (`README`/`LICENSE`/`CLAUDE.md`/`AGENTS.md`), and `ARCHITECTURE.md` wants root-level discoverability by convention.
